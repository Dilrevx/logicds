### Understanding the Vulnerability

The "CCS Injection" vulnerability arises from the way OpenSSL processes CCS messages during the TLS handshake. In a typical TLS handshake, the CCS message is used to signal the transition from plaintext communication to encrypted communication using the negotiated keys. However, if this message is improperly handled, an attacker can inject a CCS message at an inappropriate time, leading to the use of a zero-length master key. This can compromise the security of the session, allowing the attacker to hijack the session or obtain sensitive information.

### The Role of the CCS Message

During the TLS handshake, the CCS message plays a pivotal role in signaling the transition from plaintext to encrypted communication. Normally, this message should only be accepted at specific points in the handshake process to prevent attacks where an attacker might inject a CCS message prematurely. In the context of the provided code snippet, the system transitions directly to the `SSL_ST_OK` state after receiving the Finished message from the client. This transition does not explicitly check or set a flag indicating that the CCS message has been received and processed correctly.

By setting this flag, the system ensures that any subsequent CCS message is processed according to the correct protocol rules, thereby preventing unauthorized or premature processing of CCS messages.
