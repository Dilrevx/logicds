### Understanding the Vulnerability

In a typical TLS handshake, the ChangeCipherSpec message signals the transition from the handshake phase to the encrypted phase. It indicates that subsequent messages will be encrypted using the negotiated algorithms and keys. The Finished message, on the other hand, is used to verify that both parties have the same security parameters and that the handshake has been completed successfully. The sequence of these messages is critical for maintaining the integrity and security of the TLS connection.

The CCS Injection vulnerability occurs when an attacker can manipulate the handshake sequence by injecting a CCS message before it should be received. This can cause the server to switch to the encrypted state prematurely, potentially using a zero-length master key if the handshake is not properly validated. This situation can be exploited to intercept or tamper with the communication.
