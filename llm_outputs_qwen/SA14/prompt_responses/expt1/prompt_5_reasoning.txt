### Understanding the Vulnerability

In a typical SSL/TLS handshake, the ChangeCipherSpec (CCS) message is sent by one party (client or server) to signal that it has received the peer's Finished message and is ready to start encrypting its traffic with the agreed-upon encryption parameters. The CCS message is distinct from other handshake messages and is not part of the handshake hash. This distinction is crucial because the integrity of the handshake process depends on the correct sequence and verification of these messages.

The CCS Injection vulnerability occurs when an attacker can inject an additional CCS message into the handshake process. By doing so, the attacker can force the victim to prematurely switch to using an uninitialized or zero-length master key, which effectively breaks the security of the session. This allows the attacker to intercept and decrypt the communication, potentially leading to the hijacking of the session or the theft of sensitive information.
