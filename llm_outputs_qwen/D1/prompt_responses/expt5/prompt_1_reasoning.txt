### Original Issue

In the original code, after attempting to restart SRTP, the following line logs an error message:

```c
PJ_LOG(5,(srtp->pool->obj_name, "Failed to restart SRTP, err=%s",
          get_libsrtp_errstr(err)));
```

Instead, it retains the value from the previous error check (`err == srtp_err_status_replay_old || err == srtp_err_status_replay_fail`). This discrepancy means that the log message might incorrectly attribute the failure to the initial replay detection error rather than the actual error encountered during the SRTP restart process.

### Repair Explanation

The repair involves changing the logged variable from `err` to `status`, which correctly captures the return value of `pjmedia_transport_srtp_start()`:

```c

          get_libsrtp_errstr(status)));
```

3. **Maintainability**: Clear and correct logging practices improve the maintainability of the codebase. When other developers (or the original developer at a later time) need to understand or modify the code, accurate logs serve as a reliable reference.

4. **Enhanced System Reliability**: Ensuring that error reporting is accurate helps in maintaining system reliability. Misleading logs can lead to incorrect assumptions and ineffective troubleshooting, potentially resulting in prolonged downtime or unresolved issues.

5. **Consistency with Coding Practices**: Logging the correct variable aligns with common coding practices and conventions. It ensures that all error messages are consistent in their representation, making the code easier to read and understand.
