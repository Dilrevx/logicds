The vulnerability in the PJSIP library occurs when processing certain packets, causing it to incorrectly switch from using Secure Real-time Transport Protocol (SRTP) media transport to basic Real-time Transport Protocol (RTP) upon SRTP restart. This results in the media being sent insecurely, impacting all PJSIP users who utilize SRTP.

The root cause of this issue lies in the order of operations performed when an SRTP error occurs. In the buggy code, the SRTP transport is stopped immediately when an error is encountered, and then an attempt is made to restart it. However, this approach can lead to a situation where the SRTP transport is not properly re-established, causing the media to be sent insecurely using basic RTP.

The repair addresses this issue by changing the order of operations. Instead of stopping the SRTP transport immediately, the repair first retrieves the current SRTP policies (tx and rx) and then stops the SRTP transport. This ensures that the SRTP policies are preserved and can be used to restart the SRTP transport correctly.

By stopping the SRTP transport after retrieving the policies, the repair ensures that the transport is properly reset and re-established with the correct policies. This prevents the media from being sent insecurely using basic RTP and maintains the security of the SRTP transport.

In essence, the repair corrects the order of operations to ensure that the SRTP transport is properly restarted with the correct policies, thereby preventing the vulnerability and maintaining the security of the media transport. This change ensures that PJSIP users who utilize SRTP are no longer impacted by this vulnerability, and their media is sent securely.
