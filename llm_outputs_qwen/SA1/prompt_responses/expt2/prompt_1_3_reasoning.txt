### Vulnerability Context

In the context of the PEAP protocol, there are two phases of authentication:

1. **Phase 1**: Establishes a secure tunnel using TLS (Transport Layer Security). During this phase, the client verifies the server's identity through its TLS certificate. If the client is configured to skip this verification, it exposes itself to man-in-the-middle attacks where an attacker can impersonate the legitimate access point.

2. **Phase 2**: Within the established secure tunnel, the client performs an inner authentication method (such as MS-CHAPv2) to prove its identity to the server.

The vulnerability described occurs when `wpa_supplicant` is configured to not verify the network's TLS certificate during Phase 1. An attacker can exploit this by sending an EAP-TLV (Extensible Authentication Protocol - Type-Length-Value) Success packet instead of initiating Phase 2 authentication. This bypasses the need for inner authentication, allowing the attacker to gain unauthorized access to the network.
