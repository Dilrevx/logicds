### Vulnerability Overview

TLS 1.3, the latest version of the Transport Layer Security protocol, emphasizes security and efficiency. It introduces several new features, including the use of pre-shared keys and ephemeral key exchanges via key shares. During the TLS 1.3 handshake, the client and server negotiate parameters that determine the security of the session, including the method for key derivation. One critical parameter is the IKM, which is used to derive the session master secret.

In the original code snippet, there is no explicit check to ensure that at least one of the required extensions (PSK or KSE) is present before proceeding with the encryption setup. If neither extension is provided, the code uses a default buffer for the IKM. This default buffer is predictable and can be exploited by an attacker to deduce the session master secret, compromising the confidentiality and integrity of the communication.

The repair introduces a critical validation step to address this vulnerability. Here's a detailed explanation of the changes:

#### Step-by-Step Breakdown

1. **Initial PSK Handling**:

   - If no suitable PSK is found, the code resets PSK-related options and clears the PSK key array to ensure no residual data is used.

2. **Validation for Missing Extensions**:

     if (!ssl.options.pskNegotiated && ssl.session.namedGroup == 0) {

3. **Continuation of Handshake**:
