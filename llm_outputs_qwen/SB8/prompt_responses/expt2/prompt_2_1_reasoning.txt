This vulnerability arises when a TLS 1.3 client connects to a server and receives neither a Pre-Shared Key (PSK) extension nor a Key Share Extension (KSE). In such cases, the client may use a default, predictable buffer as the Input Keying Material (IKM) for generating the session master secret. An attacker can exploit this predictable IKM to compromise the session keys, leading to potential eavesdropping or tampering with the session's contents.

### Understanding the Vulnerability

In TLS 1.3, two primary mechanisms are used for key exchange: Pre-Shared Keys (PSKs) and ephemeral key exchanges like ECDHE (Elliptic Curve Diffie-Hellman Ephemeral). PSKs allow clients and servers to reuse previously established keys, while ephemeral key exchanges provide forward secrecy by generating new keys for each session. Both mechanisms are crucial for ensuring the security of the TLS session.

The vulnerability stems from the client's behavior when neither of these mechanisms is properly negotiated. Specifically, if the server does not include a PSK extension or a KSE in its ServerHello message, the client should not proceed with the handshake using a default, predictable IKM. Instead, it should terminate the handshake process to prevent the establishment of an insecure session.

As a result, if neither a PSK nor a KSE is available, the client might use a default IKM, which compromises the session's security.
