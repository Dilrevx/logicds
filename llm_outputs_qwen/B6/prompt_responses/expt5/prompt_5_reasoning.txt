### Introduction to the Problem

In the context of SSL/TLS, certificates are used to verify the identity of servers and clients. A crucial part of this verification process is matching the hostname (or IP address) that a client is trying to connect to with the names listed in the server's certificate. Traditionally, this was done by checking the Common Name (CN) field in the Subject of the certificate. However, modern certificates often include a Subject Alternative Name (SAN) extension, which can list multiple hostnames and IP addresses that the certificate is valid for.

The original code snippet attempts to verify the hostname against the SANs if they are present. However, it does not filter the SAN entries based on their type, leading to a potential security flaw. For instance, if a certificate includes both a DNS name and an IP address in its SANs, the original code would incorrectly treat the IP address as a potential match for a hostname, which could lead to man-in-the-middle attacks.

### Proposed Solution
