The repair addresses an issue where two certificate checks could interfere with each other when the X509_V_FLAG_X509_STRICT flag is enabled. In the original implementation, even if the first check (which tests for explicit elliptic curve parameters) detected a problem, its error information could be inadvertently overwritten by a subsequent check that verifies the certificate’s authority status. Essentially, the code would run both checks without ensuring that any previous error condition was respected, leading to a scenario where an invalid certificate might slip through if the later check was more lenient or simply reset the error state.

The fix focuses on maintaining the integrity of any error that is raised by the initial check. It does this by adding an extra condition that examines the current state of the return value (here referred to as “ret”) before executing subsequent checks. This means that each subsequent verification stage only runs if the previous check passed successfully. If an earlier check, such as the one checking for explicit elliptic curve parameters, fails (as indicated by a non-positive return value), then the later condition that verifies if the certificate is a valid CA won’t execute. This prevents the later code from overwriting the error code set by the earlier failure.

In summary, the reasoning behind the repair is to ensure that once an error is recorded during one stage of the verification process, no further checks are performed that could negate or replace that error. This preserves the strict verification logic intended by the X509_V_FLAG_X509_STRICT flag. By explicitly verifying that the previous conditions have passed (indicated by the return value being positive) before proceeding to additional checks, the fix ensures that each security constraint is enforced without interference from a subsequent validation step. Consequently, the certificate chain is more reliably rejected when a certificate fails any strict-flag-related check, avoiding the potentially dangerous scenario where a non-CA certificate might incorrectly be allowed to issue new certificates.
