```c
int verify_certificate(X509_STORE_CTX *ctx) {
    int ret = 1; // Assume ret starts as true/valid

    // Check if the certificate is a valid CA
    ret = check_ca(ctx);
    if (ret <= 0) {
        ctx->error = X509_V_ERR_INVALID_CA;
        return ret;
    }

    // Check for explicitly encoded elliptic curve parameters
    // Only proceed if the certificate is a valid CA
    if (ret > 0) {
        int curve_check_result = check_curve(ctx->cert);
        if (curve_check_result < 0) {
            // Unspecified error in curve check
            ctx->error = X509_V_ERR_UNSPECIFIED;
            ret = 0;
        } else if (curve_check_result == 0) {
            // Explicit curve parameters found
            ctx->error = X509_V_ERR_EC_KEY_EXPLICIT_PARAMS;
            ret = 0;
        }
    }

    // Check if a non-CA certificate has a path length constraint
    // Only proceed if all previous checks have succeeded
    if (ret > 0 && !X509_check_purpose(ctx->cert, ctx->purpose, 0)) {
        ctx->error = X509_V_ERR_INVALID_PURPOSE;
        ret = 0;
    }

    return ret;
}
```

### Explanation of Changes

1. **Preserve Initial Validation Result**: The result of the `check_ca` function is stored in `ret`. This value is not overwritten by the result of `check_curve` unless `ret` is already positive.

2. **Conditional Curve Parameter Check**: The `check_curve` function is called only if `ret > 0`, meaning the certificate has passed the CA check.

3. **Error Handling for Curve Parameter Check**: The result of `check_curve` is evaluated:
   - If it returns a negative value, an unspecified error is flagged.
   - If it returns 0, the presence of explicit elliptic curve parameters is noted as an error.

4. **Maintain Subsequent Checks**: The `X509_check_purpose` check is also made conditional on `ret > 0`.

5. **Ensure Consistent Return Value**: The function consistently returns `ret`, which will be 0 if any check fails, ensuring no false positives.
