### Original Issue

In the original implementation of the `ssl_verify_cert_chain` function, the library performs several steps to verify the certificate chain presented by a peer during an SSL/TLS handshake. The function initializes a `X509_STORE_CTX` structure, configures it with appropriate parameters, and then either calls an application-specific verification callback or directly invokes `X509_verify_cert()` if no such callback is provided. The return value from these operations is stored in the variable `i`.

The return value `i` serves multiple purposes:
- A positive value indicates that the certificate chain was successfully verified.
- A value of zero signifies that the verification failed.
- A negative value indicates an internal error, such as running out of memory.

The critical vulnerability arises when `X509_verify_cert()` returns a negative value. In the original code, this negative return value is not explicitly handled. Instead, it is propagated through the function, potentially causing confusion in higher-level functions like `SSL_connect()` or `SSL_do_handshake()`. These functions expect certain error codes and behaviors, but a negative return value from `X509_verify_cert()` can lead to unexpected behavior, particularly the return of `SSL_ERROR_WANT_RETRY_VERIFY`. This error code is intended to signal that the application should retry the verification process, which is only applicable when using an application-specific verification callback. Most applications do not use such callbacks, making the `SSL_ERROR_WANT_RETRY_VERIFY` error code unexpected and potentially leading to incorrect application behavior.
