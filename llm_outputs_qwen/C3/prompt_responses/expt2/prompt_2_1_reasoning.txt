### Context: Access Control Lists in Mosquitto

Eclipse Mosquitto is a popular open-source MQTT broker used for IoT applications. One of its key features is the ability to enforce access control through ACL files. These files specify which clients are allowed to publish to or subscribe to certain topics. Properly configured ACLs are essential for maintaining security in environments where multiple devices and services communicate over MQTT.

### The Vulnerability

The vulnerability arises from how Mosquitto interprets an ACL file that is either empty or contains only comments and blank lines. In the original implementation, if the ACL file did not contain any active rules (i.e., it was empty or contained only comments), Mosquitto would treat this as if no ACL file had been defined at all. As a result, it would revert to a default policy that allows all actions, which can be highly insecure.

This behavior is problematic because it can lead to unintended access to sensitive topics, especially in environments where strict access control is necessary. For example, if an ACL file is accidentally deleted or becomes corrupted, Mosquitto might inadvertently allow all clients to perform any action, potentially exposing sensitive data or enabling unauthorized control over devices.

In such cases, the absence of `acl_list` and `acl_patterns` does not necessarily indicate the absence of an ACL file itself.
