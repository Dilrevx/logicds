### Understanding the Vulnerability

A key requirement for its secure operation is the uniqueness of the nonce for each encryption operation. According to RFC 7539, the nonce must be exactly 96 bits (12 bytes) long. This fixed length is crucial because the algorithm's security relies on the assumption that no two messages are ever encrypted with the same key-nonce pair.

However, OpenSSL introduces flexibility in the nonce length, allowing values ranging from 1 to 16 bytes. This behavior can lead to unintended nonce reuse if developers mistakenly assume that altering the leading bytes of a 16-byte nonce will result in a unique nonce. Since only the last 12 bytes are significant, such changes may not actually produce a new, unique nonce, thus violating the requirement for uniqueness and potentially compromising the security of the encrypted data.
