The repair addresses a critical ordering issue in the process of verifying a certificate chain that can lead to the wrong error code being reported. In the original implementation, the code duplicated the chain and then performed checks on the leaf certificate’s validity and hostname. This ordering meant that if there was an error during the verification of the leaf certificate, especially when a callback instructs the verifier to continue despite an invalid certificate, that error might not be properly captured and stored. As a result, the wrong error code could be returned later in the process.

The patch reorders these operations to ensure proper error propagation. First, it performs the legacy chain validation. Then, crucially, it immediately verifies the leaf certificate’s validity and hostname before duplicating the certificate chain. This early evaluation step allows the context structure to potentially capture any errors arising from the leaf certificate checks. By doing so, the repair guarantees that if an error is detected, particularly on the leaf level, that error is stored in a designated error field associated with the certificate chain.

Additionally, the fix includes logic to record the error in the certificate chain’s error array when certain conditions are met. Specifically, if the error depth is zero, which indicates that the error originates from the leaf certificate, and if the error is not the benign error that signifies the inability to retrieve the issuer certificate locally, then that error is recorded. This step is vital because the benign error might be acceptable in some scenarios, but in other contexts, it is important to record and report the exact nature of the failure.

After these verifications and potential error recordings, the chain is then duplicated for storage within the context’s chain list. Only after the chain duplication—the point at which the chain is safely stored and can be referenced by the rest of the system—is the chain count incremented. Finally, the global error state and error depth in the context are reset to reflect a successful final step of the process.

Overall, the repair fixes the vulnerability by ensuring that any error detected during the verification of the leaf certificate is properly captured and stored before further processing occurs. This prevents scenarios where a verification callback that advises to continue in the face of an invalid certificate would inadvertently cause the final reported error to be inaccurate. By reordering the operations, the code now reliably retains the correct error information, allowing for accurate error reporting and handling downstream in the certificate verification logic.
