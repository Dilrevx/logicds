The repair provided addresses a critical security vulnerability in a TLS v1.3 implementation, specifically related to mutual authentication in server-client handshakes. In the context of secure communications, mutual authentication ensures that both the server and the client verify each other's identities before establishing a secure connection. This is particularly important in environments where client identity verification is necessary to prevent unauthorized access.

### Vulnerability Context

The original code snippet lacks checks to ensure that a TLS v1.3 server requiring mutual authentication properly validates that the client has sent a `CertificateVerify` message, which is essential for confirming that the client possesses a valid certificate. Without this validation, a malicious client could potentially bypass the need to present a certificate, leading to unauthorized access.

### Repair Explanation

The repair introduces several key modifications wrapped in preprocessor directives to ensure that the additional checks are only included when certificates are enabled and client authentication is not disabled. This targeted approach maintains the integrity of the code while addressing the specific vulnerability.

1. **Preprocessing Directives**:
   ```c
   #if !defined(NO_CERTS) && !defined(WOLFSSL_NO_CLIENT_AUTH)
   ```
   These directives ensure that the additional security checks are only compiled and executed when the system is configured to support certificates and client authentication. This prevents unnecessary overhead in configurations where these features are not needed.

2. **Server-Side Check**:
   ```c
   if (ssl->options.side == WOLFSSL_SERVER_END) {
   ```
   This condition ensures that the following checks are only performed on the server side. Mutual authentication is a server-side requirement, and the checks are irrelevant on the client side.

3. **Mutual Authentication Requirement Check**:
   ```c
   if ((ssl->options.mutualAuth || ssl->options.failNoCert) &&
       !ssl->options.havePeerVerify && !ssl->options.resuming) {
   ```
   This nested condition checks two main aspects:
   - **Mutual Authentication Requirement**: It verifies whether mutual authentication is explicitly required (`ssl->options.mutualAuth`) or if the server is configured to fail the handshake if no certificate is provided by the client (`ssl->options.failNoCert`).
   - **Peer Verification Status**: It ensures that the server has not already verified the client's certificate (`!ssl->options.havePeerVerify`) and that the session is not being resumed (`!ssl->options.resuming`). Resumed sessions might have already established trust, so this check prevents unnecessary verification in such cases.

4. **Error Handling**:
   ```c
   int ret = NO_PEER_CERT;
   DoCertFatalAlert(ssl, ret);
   return ret;
   ```
   If the server determines that mutual authentication is required but the client has not provided a certificate (`NO_PEER_CERT`), it triggers a fatal alert to the client using `DoCertFatalAlert(ssl, ret)`. This function call informs the client that the handshake must terminate due to a missing or invalid certificate. The server then returns an error code (`ret`), indicating the failure of the handshake process. This action ensures that the connection cannot proceed without proper client authentication, thus preventing unauthorized access.

5. **Continuation of Existing Logic**:
   After the added security checks, the existing logic for processing the `Finished` message continues as before. This includes checking the buffer size and deriving the finished secret if the handshake is not yet complete. Ensuring that the existing functionality remains intact is crucial to maintain the overall stability and performance of the TLS implementation.

### Conclusion

By incorporating these steps, the repair ensures that a TLS v1.3 server correctly enforces mutual authentication requirements, preventing malicious clients from bypassing the need to present a valid certificate during the handshake process. This modification strengthens the security posture of the server by adhering strictly to the TLS protocol specifications for mutual authentication, thereby safeguarding sensitive data and maintaining trust in the communication channel.
