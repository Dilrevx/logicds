### Vulnerability Context

In TLS v1.3, mutual authentication is achieved through the exchange of certificates and the subsequent verification of these certificates. When mutual authentication is required, the server must validate that the client has sent a `CertificateVerify` message, which cryptographically signs a hash of the handshake messages up to that point using the client's private key. This ensures that the client possesses the private key corresponding to the public key presented in its certificate, thereby verifying the client's identity.

The vulnerability exists because the server's code does not include a check to confirm that the client has sent the `CertificateVerify` message. As a result, a malicious client can skip this step, potentially leading to unauthorized access to services that require mutual authentication.
