The vulnerability in the wolfSSL library allows a malicious server to compromise the security of a TLS 1.3 session by not providing a Pre-Shared Key (PSK) extension or a Key Share Extension (KSE) during the handshake. This causes the client to use a default, predictable buffer for the Input Keying Material (IKM) value when generating the session master secret. An attacker who knows the IKM value can reconstruct the session master secret key, potentially allowing them to access or tamper with the encrypted data.

The repair addresses this vulnerability by adding a sanity check to ensure that either a PSK or a KSE is present before proceeding with the handshake. If neither is present, the function returns an error (EXT_MISSING). This prevents the client from using a predictable IKM value and reduces the risk of the session master secret key being compromised.

The added check verifies that either the PSK has been negotiated (ssl->options.pskNegotiated == 1) or a named group (ssl->session->namedGroup) is set, which indicates the presence of a KSE. If neither condition is met, the function returns an error. This ensures that the client only proceeds with the handshake if a secure IKM value can be used to generate the session master secret key.

By adding this check, the repair prevents the use of a predictable IKM value and reduces the risk of the session master secret key being compromised, thereby addressing the vulnerability in the wolfSSL library.
