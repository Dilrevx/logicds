### Understanding the Vulnerability

The original code snippet checks the Common Name (CN) field of an X.509 certificate against an expected value (`cn`). However, this approach is insufficient because modern certificates often use the SAN extension to specify alternative names that the certificate is valid for. The SAN extension can include various types of names, such as DNS names, email addresses, and IP addresses. The vulnerability arises when the verification process does not properly filter these names based on their type, leading to potential mismatches where an IP address could be incorrectly interpreted as a DNS name.

### Why the Original Code Was Flawed

The original line of code:
```c
if (CommonUtils.x509_crt_check_cn(cur.buf, cn, cn_len) == 0)
```

only checks the CN field for a match with the expected name. This method is inadequate because:
- **Lack of SAN Handling**: It ignores the SAN extension, which can contain multiple names of different types.
- **Potential for Misinterpretation**: If the SAN contains an IP address, it could be mistakenly treated as a DNS name, allowing an attacker to impersonate a domain by obtaining a certificate for an IP address they control.
