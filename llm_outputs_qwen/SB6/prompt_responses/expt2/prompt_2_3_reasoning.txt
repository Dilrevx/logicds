### Understanding the Vulnerability

In the original code snippet, the verification process only checks the Common Name field of the certificate for a match with the expected common name (`cn`). However, modern SSL/TLS certificates often include a SAN extension that lists additional domain names or IP addresses that the certificate is valid for. The flaw lies in the fact that the original code does not discriminate between the types of names listed in the SAN extension. As a result, IP addresses could be mistakenly matched against domain names, allowing attackers to impersonate domains by controlling the corresponding IP addresses.

### The Need for Change

To address this vulnerability, the code needs to be modified to ensure that only DNS names (domain names) in the SAN extension are considered during the verification process. This selective approach prevents IP addresses from being incorrectly matched against the expected domain name, thereby enhancing the security of the verification process.

### Implementation of the Repair

The repair introduces a new function, `x509_crt_check_san`, which is responsible for parsing and verifying the SAN extension. This function is designed to iterate through each entry in the SAN extension, check its type, and perform the comparison only if the entry is a DNS name. Here’s how the function operates:

1. **Parsing the SAN Extension**: The function first locates and parses the SAN extension within the certificate. This involves extracting the list of names and their types.

2. **Type-Specific Checks**: As the function iterates through the list of names, it checks the type of each name. Only DNS names (type 2) are considered for matching. This selective approach ensures that IP addresses (types 7 for IPv4 and 28 for IPv6) are ignored during the comparison.

3. **Comparison Logic**: If a DNS name is found in the SAN extension, the function compares it with the expected common name (`cn`). If a match is found, the verification process proceeds successfully. If no DNS names match the expected common name, the function continues to check other parts of the certificate, such as the Common Name field, if necessary.

4. **Handling Edge Cases**: The function is designed to handle various edge cases, such as certificates without a SAN extension or certificates with malformed SAN entries. In such cases, the function may fall back to checking the Common Name field or return an appropriate error code.
