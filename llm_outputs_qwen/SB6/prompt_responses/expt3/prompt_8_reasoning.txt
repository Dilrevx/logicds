### Understanding the Vulnerability

only checks the Common Name (CN) field of the certificate for a match with the expected CN. The vulnerability arises because the original code does not properly differentiate between these types of names. As a result, an attacker could potentially impersonate a domain by obtaining a certificate for an IP address that they control, as long as the IP address is listed in the SAN extension.

To address this vulnerability, a new function, `x509_crt_check_san`, is introduced. This function is designed to correctly parse and compare the SAN extension against the expected CN. The primary goal is to ensure that only DNS names in the SAN are considered for matching, thereby preventing IP addresses or other types of names from being mistakenly accepted as valid domain names.

### Implementation Details

#### Parsing the SAN Extension

The `x509_crt_check_san` function begins by parsing the SAN extension from the certificate. This involves iterating through each entry in the SAN extension and identifying its type. The ASN.1 structure of the SAN extension is well-defined, and each entry is tagged with a specific type, such as:

- **DNS Name (Type 2)**: Represents a domain name.
- **IP Address (Type 7)**: Represents an IP address (either IPv4 or IPv6).

#### Filtering DNS Names

Once the SAN extension is parsed, the function filters out all entries that are not DNS names. This is crucial because only DNS names should be considered when verifying the expected CN. By ignoring other types of entries, such as IP addresses, the function ensures that the certificate is only considered valid if it contains a matching DNS name.
