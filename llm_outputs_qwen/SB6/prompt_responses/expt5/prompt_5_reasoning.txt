### Understanding the Vulnerability

In the context of X.509 certificates, the Common Name (CN) field in the Subject field traditionally identifies the entity the certificate belongs to. However, modern certificates often use the Subject Alternative Name (SAN) extension to specify additional identities, such as domain names, email addresses, and IP addresses. The vulnerability arises when the certificate verification process incorrectly treats IP addresses in the SAN extension as potential matches for a domain name specified in the CN field. This can lead to man-in-the-middle (MITM) attacks, where an attacker could present a certificate with an IP address in the SAN that matches the target domain's IP, tricking the client into believing the certificate is valid for the intended domain.

This approach is insufficient because it does not account for the presence of the SAN extension, which can contain multiple names of different types. If the SAN includes IP addresses, they are incorrectly treated as potential matches for domain names, allowing potential impersonation attacks.

### The Repair: Introducing `x509_crt_check_san`

To mitigate this vulnerability, the repair introduces a new function, `x509_crt_check_san`, which is designed to correctly parse and compare the SAN extension against the expected domain name.
