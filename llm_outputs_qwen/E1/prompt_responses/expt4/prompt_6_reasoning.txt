The repair implemented addresses a significant security vulnerability in the handling of NAS (Non-Access Stratum) messages within the `write_pdu` function of the `nas_5g` class. This vulnerability arises from the acceptance of plain NAS messages (`plain_5gs_nas_message`) after the NAS security context has been established. Such acceptance can lead to unauthorized access or manipulation of NAS messages, thereby compromising the security of the communication between the User Equipment (UE) and the Network.

### Step-by-Step Explanation of the Repair

#### Step 1: Introduction of Security Context Check
The primary issue in the original code is the lack of a check to determine whether a security context has already been established before accepting plain NAS messages. To address this, a boolean variable `has_sec_ctxt` is introduced. This variable is assumed to hold a value indicating whether the security context is active. By checking this variable when a plain NAS message is received, the system can prevent the processing of such messages after the security context has been activated.

```cpp
if (nas_msg.hdr.security_header_type == nas_5gs_hdr::security_header_type_opts::plain_5gs_nas_message) {
  if (has_sec_ctxt) { // Check if security context is already established
    logger.error("Received plain NAS message after security context activation");
    return SRSRAN_ERROR;
  }
}
```

This modification ensures that plain NAS messages are only accepted when the security context has not yet been established, thus mitigating the risk of unauthorized access.

#### Step 2: Tracking Message Header Types
To enhance traceability and debugging, a new integer variable `current_message_header` is introduced. This variable is used to track the type of security header received. Different values are assigned to `current_message_header` based on the type of security header:

- `0` for `plain_5gs_nas_message`
- `1` for `integrity_protected`
- `2` for `integrity_protected_and_ciphered`
- `3` for `integrity_protected_with_new_5G_nas_context`
- `4` for `integrity_protected_and_ciphered_with_new_5G_nas_context`

This tracking mechanism can be useful for logging and auditing purposes, providing insights into the types of messages being processed.

```cpp
int current_message_header = -1; // Variable to track the type of message header

switch (nas_msg.hdr.security_header_type) {

    current_message_header = 0;

    break;
```

### Additional Considerations

Although the repair does not implement these checks directly, it underscores their importance for enhancing the security of the system.
