The identified vulnerability in the processing of key and initialization vector (IV) lengths can lead to potential truncation or overruns during the initialization of some symmetric ciphers. This can result in non-uniqueness, which could compromise the confidentiality of some cipher modes.

The root cause of this vulnerability lies in the order of operations when calling EVP_EncryptInit_ex2(), EVP_DecryptInit_ex2(), or EVP_CipherInit_ex2(). The provided OSSL_PARAM array is processed after the key and IV have been established. This means that any key or IV length parameters specified in the OSSL_PARAM array are not taken into account during the initial setup of the cipher context.

To fix this vulnerability, the repair code introduces a new section that checks for key and IV length parameters in the OSSL_PARAM array before initializing the cipher. If such parameters are found, they are applied to the cipher context using EVP_CIPHER_CTX_set_params(). This ensures that the key and IV lengths are set correctly before the cipher is initialized.

The repair code specifically checks for two parameters: OSSL_CIPHER_PARAM_KEYLEN and OSSL_CIPHER_PARAM_IVLEN (which is also synonymous with OSSL_CIPHER_PARAM_AEAD_IVLEN). If either of these parameters is present in the OSSL_PARAM array, it is copied to a new array and passed to EVP_CIPHER_CTX_set_params(). This guarantees that the key and IV lengths are set correctly before the cipher is initialized.

By applying the key and IV length parameters before initializing the cipher, the repair code prevents potential truncation or overruns during the initialization of symmetric ciphers. This fix ensures that the cipher modes are properly set up, maintaining the confidentiality of the encrypted data.

It's worth noting that the FIPS provider's internal library context is not affected by this issue, as it uses a different approach to handle key and IV lengths. Therefore, the repair code includes a conditional compilation directive (#ifndef FIPS_MODULE) to exclude the fix when building the FIPS provider.
