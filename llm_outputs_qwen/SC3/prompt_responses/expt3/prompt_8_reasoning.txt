The vulnerability arises because the original code does not differentiate between the absence of an ACL file and an ACL file that is present but empty or filled only with comments. In the latter case, the system defaults to an allow-all policy, which is a significant security risk. An attacker could exploit this by creating an empty or comment-only ACL file, effectively bypassing intended access controls.
