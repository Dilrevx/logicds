### Understanding the Vulnerability

In TLS, client authentication is a process where the client proves its identity to the server, typically using a digital certificate. When the client uses a DH certificate for authentication, it is expected to send a `CertificateVerify` message, which cryptographically signs a hash of the handshake messages exchanged so far. This signature serves as proof of possession of the private key corresponding to the public key in the certificate, ensuring that the client is who it claims to be.

The vulnerability in question arises because the `ssl3_get_cert_verify` function did not enforce the requirement for a `CertificateVerify` message when the client's certificate is of type DH. This oversight allowed attackers to craft TLS Handshake Protocol traffic that did not include the `CertificateVerify` message, effectively bypassing the authentication mechanism. Without proper verification, the server would accept the client as authenticated, leading to unauthorized access.
