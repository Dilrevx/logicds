### Understanding the Vulnerability

ChaCha20-Poly1305 is a widely used AEAD cipher that combines the ChaCha20 stream cipher with the Poly1305 message authentication code. One of the fundamental requirements for secure use of this cipher is the uniqueness of the nonce for each encryption operation. The nonce, or initialization vector (IV), must be exactly 96 bits (12 bytes) long, as specified in RFC 7539. This strict requirement ensures that each encryption operation is unique, thereby maintaining the confidentiality and integrity of the encrypted data.

However, OpenSSL's implementation allows a variable nonce length, padding shorter nonces with zeros and considering only the last 12 bytes of longer nonces. This flexibility can lead to security issues if developers mistakenly assume that longer nonces or non-standard lengths result in unique encryption contexts. Specifically, if two different nonces have the same last 12 bytes, they are treated as identical by OpenSSL, leading to nonce reuse and potential attacks.

The condition `if (arg <= 0 || arg > CHACHA_CTR_SIZE)` checks whether the proposed nonce length is within the allowed range. If the length is valid, it is assigned to `actx->nonce_len`.

To mitigate this risk, the code needs to enforce a strict nonce length of exactly 12 bytes, as mandated by RFC 7539.
