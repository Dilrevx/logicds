In the revised implementation, only a stricter list of NAS message types is allowed in plaintext form. By excluding Detach Request, EMM Information, and EMM Status, the patch forces these types to be handled only when carried with proper security features (like an attached integrity protection). For instance, a Detach Request without integrity protection might allow an attacker to force a user’s device to disconnect, while EMM Information and EMM Status messages might expose sensitive operational details or be manipulated for further attacks.

The repair’s reasoning relies on the general principle that any message that can affect the state or behavior of a system should not be trusted if it is not secured with integrity protection. Thus, by tightening the switch statement to only accept the safer, less impactful messages in plaintext, the vulnerability is mitigated. The system now logs and returns an error when it encounters any NAS message that is not explicitly allowed when no integrity protection is present, thereby preventing the unauthorized use of critical messages without proper verification.

In essence, the patch reflects a conservative approach to message handling: instead of trying to apply special-case logic to manage specific insecure messages, it restricts plaintext processing to the smallest set of message types that are deemed safe. This not only reduces the attack surface but also enforces a higher standard of security for messages that have significant implications on session management and user state.
