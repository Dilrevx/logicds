The repair implemented addresses the CCS Injection vulnerability, a critical security flaw in the TLS/SSL protocol that can allow attackers to hijack secure connections or obtain sensitive information. This vulnerability arises due to improper handling of the ChangeCipherSpec (CCS) message, which is used to signal the transition from one cryptographic state to another during the TLS handshake. An attacker can exploit this vulnerability by injecting a CCS message out of sequence, potentially causing the server to use a zero-length master key, which severely compromises the security of the connection.

### Understanding the Vulnerability

In a typical TLS handshake, messages are sent and received in a specific order, and each message serves a distinct purpose. For instance, after the CertificateVerify message from the client, the server expects a Finished message, and after the Finished message, the server sends its own Finished message, followed by a ChangeCipherSpec message to indicate that the new encryption parameters are in effect. The CCS Injection vulnerability occurs when an attacker can inject a CCS message at an inappropriate time, causing the server to prematurely switch to the new encryption state without completing the necessary handshake steps.
