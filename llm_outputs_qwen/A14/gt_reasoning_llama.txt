The repair introduces a new flag, `SSL3_FLAGS_CCS_OK`, to track whether a ChangeCipherSpec message has been received and processed. This flag is set in specific states of the SSL/TLS handshake, ensuring that the ChangeCipherSpec message is only processed once.

In the repaired code, the `SSL3_FLAGS_CCS_OK` flag is set in the `SSL3_ST_SR_CERT_VRFY_B` and `SSL3_ST_SR_FINISHED_A` states. This ensures that the ChangeCipherSpec message is only processed after the certificate verification and finished messages have been received.

Additionally, the `SSL3_FLAGS_CCS_OK` flag is also set in the `SSL3_ST_SW_FINISHED_A` state, but only if the `next_proto_neg_seen` flag is set. This ensures that the ChangeCipherSpec message is only processed after the next protocol negotiation has been completed.

By introducing this flag and setting it in specific states, the repair prevents the improper processing of ChangeCipherSpec messages, thereby addressing the "CCS Injection" vulnerability.
