The vulnerability in question allows a malicious client to bypass mutual authentication on a TLS v1.3 server by not sending the certificate_verify message. This is a significant security risk, as it enables unauthorized access to the server.

The repair addresses this vulnerability by adding a crucial check on the server-side. Specifically, it verifies whether the server requires mutual authentication or has the failNoCert option enabled. If either condition is true, it then checks if the peer verification has been completed and if the connection is not being resumed.

If the peer verification is incomplete and the connection is not being resumed, the server returns an error (NO_PEER_CERT) and sends a fatal alert to the client. This effectively prevents the client from establishing a connection without presenting a valid certificate.

The reasoning behind this repair is straightforward. By explicitly checking for the completion of peer verification, the server ensures that the client has provided a valid certificate, thereby enforcing mutual authentication. This check is only performed when the server requires mutual authentication or has the failNoCert option enabled, which means that the server is configured to demand a client certificate.

The addition of this check does not interfere with the normal functioning of the TLS handshake. If the client has already provided a valid certificate, the server will proceed with the handshake as usual. However, if the client attempts to bypass mutual authentication by not sending the certificate_verify message, the server will detect this and terminate the connection.

In summary, the repair introduces a critical security check that prevents malicious clients from bypassing mutual authentication on a TLS v1.3 server. By verifying the completion of peer verification, the server ensures that only authorized clients can establish a connection, thereby mitigating the vulnerability.
