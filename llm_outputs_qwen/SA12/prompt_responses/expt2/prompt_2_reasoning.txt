Once the server role is confirmed, the next step is to verify if mutual authentication is required or if there is a configuration to fail the handshake when no certificate is provided. #### 3. Validate Peer Certificate Presence
Within the scope of requiring mutual authentication, the server checks two critical conditions:
- `!ssl.options.havePeerVerify`: This condition checks whether the server has verified the client's certificate. If `havePeerVerify` is false, it indicates that the client did not present a certificate or that the certificate could not be verified.
- `!ssl.options.resuming`: This condition ensures that the session is not being resumed. In resumed sessions, the client does not need to send a new `certificate_verify` message because the session keys and certificates are reused from a previous handshake. However, for a fresh handshake, mutual authentication must be enforced.

These checks together ensure that the server only proceeds with the connection if the client has provided and verified its certificate, unless the session is being resumed.

This immediate termination prevents any further communication until the client provides a valid certificate.

Finally, the server returns the error code `ret`, which is `Constants.NO_PEER_CERT`. Returning this error code to the calling function signals that the handshake has failed due to the absence of a valid client certificate during mutual authentication.
