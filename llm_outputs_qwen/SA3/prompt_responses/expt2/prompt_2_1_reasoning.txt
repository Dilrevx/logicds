### Understanding the Vulnerability

OpenSSL provides functionality to create custom ciphers using the `EVP_CIPHER_meth_new()` function and related methods. These custom ciphers are intended to allow developers to define their own encryption algorithms or configurations. However, there is a critical flaw in how OpenSSL versions 3.0.0 to 3.0.5 handle these custom ciphers when they are passed to initialization functions like `EVP_EncryptInit_ex2()`, `EVP_DecryptInit_ex2()`, and `EVP_CipherInit_ex2()`.

The flaw arises when the NID parameter, which is supposed to uniquely identify a cipher, is set to `NID_undef`. In such cases, OpenSSL incorrectly attempts to find an equivalent cipher by matching against the NID. Since `NID_undef` does not correspond to any valid cipher, OpenSSL defaults to selecting the NULL cipher, which performs no encryption at all. If the default provider or a third-party provider includes the NULL cipher, this selection will succeed, leading to unencrypted data being treated as encrypted.
