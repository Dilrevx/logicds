The vulnerability arose because the system could accept an integrity protection algorithm value that effectively represented “no integrity protection” (typically encoded as zero). When this happens, the user equipment (UE) might bypass the intended radio resource control (RRC) layer security, allowing potentially insecure or unverified commands. In essence, this flaw allowed an attacker to send a command with a non-secure integrity algorithm (identified by zero) to disable proper security checks, which undermines the security mechanisms expected to protect data integrity in the RRC protocol.

The repair addresses this vulnerability by first verifying that the integrity protection algorithm configuration is indeed present. Once the configuration is confirmed, it assigns the given value to the appropriate security setting. However, the crucial new addition in the repair is a check that explicitly tests whether the assigned integrity algorithm value is zero. Zero has been determined as a prohibited value in this context because it corresponds to a state where no valid integrity algorithm is being employed, effectively disabling the security layer that should verify the authenticity and integrity of commands.

If the repair detects that the integrity protection algorithm is zero, it logs an error indicating that a prohibited value was received in the RRC security command. Following this error log, it immediately terminates further processing (represented by a return statement in the code) to prevent any further actions using this insecure configuration. This preemptive action stops the system from ever accepting a configuration that would leave it vulnerable to attacks that exploit the absence of proper integrity protection.

Overall, the revised logic ensures that only valid, non-zero values for the integrity protection algorithm are accepted and processed. This prevents scenarios where an attacker might leverage an algorithm value of zero to bypass security activation in the RRC layer. By enforcing this additional validation, the repair helps protect the integrity and confidentiality of communications managed by the RRC protocol, thus maintaining the overall security posture of the system during critical operations.

In summary, the repair adds an extra safeguard against insecure configurations by flagging and halting operations that attempt to use an integrity algorithm value of zero. This validation is critical because it directly addresses the vulnerability where an attacker could bypass RRC layer security, ensuring that every accepted configuration actively maintains the expected security standards.
