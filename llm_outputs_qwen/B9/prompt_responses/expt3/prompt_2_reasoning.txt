### Understanding the Vulnerability

In the original code, there were separate checks for different signature algorithms (such as ED25519, ED448, ECC DSA, Falcon, and RSA). However, these checks only verified that the appropriate key was present in the certificate without ensuring that the signature algorithm matched the key type. An attacker could exploit this by sending a `certificate_verify` message with a signature algorithm that did not correspond to the public key in the certificate, potentially leading to a security breach.

### Repair Strategy

The repair strategy involves introducing a new boolean variable, `validSigAlgo`, which acts as a flag to determine whether the signature algorithm specified in the `certificate_verify` message corresponds to the public key type presented in the server's certificate. This ensures that the signature algorithm used is consistent with the certificate's public key, thereby preventing mismatches that could be exploited by attackers.
