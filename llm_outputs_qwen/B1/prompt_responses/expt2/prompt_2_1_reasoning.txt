### Understanding the Vulnerability

In a typical TLS handshake, when a server requests client authentication, the client responds with its certificate and, if applicable, a `CertificateVerify` message. The `CertificateVerify` message contains a digital signature created using the client's private key over a hash of the handshake messages up to that point. This signature serves as proof that the client indeed holds the private key corresponding to the public key in its certificate. Without this proof, an attacker could impersonate the client without knowing its private key, compromising the security of the connection.
