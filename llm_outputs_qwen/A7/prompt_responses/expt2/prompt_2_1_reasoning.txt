During this process, the function may encounter multiple potential chains that could validate the certificate. One such scenario involves identifying alternative chains, where the function finds a different path to verify the certificate. When an alternative chain is found, the function needs to manage the certificates in the current chain appropriately to ensure the integrity of the verification process.

The vulnerability arises from the way the function handles the `ctx->last_untrusted` variable. This variable keeps track of the number of untrusted certificates in the current chain. If this variable is not updated correctly, it can lead to incorrect assumptions about the trust status of the certificates, potentially allowing an attacker to introduce a spoofed CA certificate and manipulate the verification process.
