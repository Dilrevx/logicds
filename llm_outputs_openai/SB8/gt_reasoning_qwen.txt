The repair addresses a critical vulnerability in the wolfSSL library's handling of TLS 1.3 connections, specifically when a client does not receive either a Pre-Shared Key (PSK) extension or a Key Share Extension from a server during the handshake process. The original code did not adequately handle scenarios where these extensions were missing, leading to the use of a default, predictable buffer as the Input Keying Material (IKM) for generating the session master secret. This predictability could allow an attacker to reconstruct the session keys, compromising the security of the encrypted communication.

The vulnerability arises because the TLS 1.3 protocol mandates that at least one of these extensions must be present for secure key establishment. If neither is provided, the protocol specifies that the connection should fail rather than proceed with a default, insecure IKM. The original code failed to enforce this requirement, thus leaving the session open to potential interception and manipulation by an adversary.

The repair introduces a crucial check after attempting to negotiate a PSK. It verifies whether a PSK was successfully negotiated (`ssl.options.pskNegotiated`) and whether a named group (which would indicate the presence of a Key Share Extension) has been set (`ssl.session.namedGroup == 0`). If neither condition is met, indicating that neither a PSK nor a Key Share Extension was received, the function returns `CommonsConstants.EXT_MISSING`. This action effectively terminates the handshake process, preventing the establishment of an insecure session.

By adding this check, the repair ensures that the client adheres strictly to the TLS 1.3 specification, which requires the presence of either a PSK or a Key Share Extension for secure key exchange. This change significantly enhances the security of TLS 1.3 sessions by ensuring that all necessary cryptographic material is properly exchanged before encryption is enabled. It prevents the use of a predictable IKM, thereby thwarting attempts by attackers to reconstruct session keys and gain unauthorized access to the encrypted data.

In summary, the repair strengthens the robustness of the TLS 1.3 implementation in wolfSSL by enforcing strict adherence to the protocol's requirements for secure key exchange, thereby mitigating the risk of establishing insecure sessions due to missing critical extensions.
