The repair introduces an essential security check after handling the PSK negotiation to ensure that the session does not continue with insecure key material. Here's how it works:

Initially, the code continues to process the server hello by looking for a Pre-Shared Key (PSK) extension. It searches through the linked list of PSK entries until it finds a chosen one. If no valid PSK is found, the code clears any previous key material, effectively deactivating the PSK-related settings. If a valid PSK is present, it calls a function to set up that key and marks the internal flag (ssl.options.pskNegotiated) to indicate that a PSK has been successfully negotiated.

The critical change happens right after this PSK negotiation block. Before the code enables encryption with ssl.keys.encryptionOn and transitions to the next server state, it now checks two important conditions simultaneously:
1. Whether a PSK has been negotiated (via the flag ssl.options.pskNegotiated).
2. Whether there is valid key share information available (indicated by ssl.keys.namedGroup being non-zero).

If neither condition is met — meaning that the session lacks both a proper PSK and key share data — the repair stops the handshake by immediately returning an error code (CommonsConstants.TLS_MISSING_EXTENSION_ERROR). This prevents the function from continuing. Without this change, if both the PSK extension and the key share extension were missing, the implementation would have defaulted to a predictable IKM (Input Key Material) value for generating the session master secret. Such a breachable key derivation process could allow an attacker to reconstruct or tamper with the encryption keys, compromising the security of the TLS session.

In summary, the repair fixes the vulnerability by enforcing that the session master secret is not derived from insecure, predictable defaults. By adding the conditional check, the code only proceeds with enabling encryption if at least one secure mechanism — a negotiated PSK or a valid key share — is present. This mandatory check guarantees that the master secret is always generated with proper cryptographic material, ensuring robust security and preventing potential eavesdropping or session tampering by malicious actors.
