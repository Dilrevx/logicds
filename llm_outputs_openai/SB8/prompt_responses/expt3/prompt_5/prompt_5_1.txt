2. If no PSK was negotiated, the key buffer is cleared.
3. **New step:** Right after handling the PSK, before enabling encryption, we verify that at least one secure key material exists. This is done by checking if ssl.options.pskNegotiated is false (i.e. no PSK) and simultaneously ssl.keys.namedGroup is zero (i.e. no key share available). 
4. If both are missing, the function aborts the handshake by returning an error (in this example, ERROR_MISSING_KEY_EXCHANGE).
5. If either a PSK is negotiated or a valid key share is present, the code continues and enables encryption.
6. Finally, the server state is advanced.

This repair ensures that the TLS 1.3 session master secret is never derived from a default predictable IKM and that the session proceeds only when sufficient key exchange material has been established.
