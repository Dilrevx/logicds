The repair avoids falling back to plain RTP in the event of errors during SRTP processing. Previously, if srtp.bypass_srtp was true, the code might not have restarted SRTP correctly, letting the system use basic RTP which is insecure. In the repaired version, the bypass_srtp flag is no longer used as a condition after restarting SRTP. Here’s how the repair addresses the issue:

1. The original code checked whether SRTP errors (due to replay issues) occurred and then attempted to restart the SRTP transport. However, if the bypass_srtp flag was set to true, it could lead to the packet being processed insecurely via basic RTP instead of retrying the SRTP operation. This would potentially expose media to risks.

2. In the repair, irrespective of the bypass_srtp flag’s value, whenever a replay error is detected during probation, the code stops the current SRTP session by calling pjmedia_transport_srtp_stop(srtp). It then retrieves the current transmission and reception policies to restart SRTP using pjmedia_transport_srtp_start.

3. Once the restart is attempted, the code checks that the restart succeeded (i.e. status equals PJ_SUCCESS). Only then does it re-attempt packet processing using srtp_unprotect. This ensures that all media packets are processed within SRTP, preventing a scenario where the media transport might inadvertently switch to an insecure RTP transmission.

4. The removal of the check catering to bypass_srtp reinforces that no matter the configuration, SRTP will always be restarted and used for packet processing. This directly addresses the vulnerability where an attacker might cause a fallback to insecure RTP during an SRTP restart by triggering continual replay errors.

5. The fix, therefore, ensures that after restarting SRTP, the packet is again unprotected (and thus processed securely) so that the security promised by SRTP is maintained throughout the media transmission session.

In summary, by removing the reliance on srtp.bypass_srtp and making the packet reprocessing contingent solely on the success of an SRTP restart, the repair prevents insecure media transport and upholds the SRTP policy, thereby mitigating the vulnerabilities described.
