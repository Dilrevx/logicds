The vulnerability arose because the certificate serial number was being compared using a memory comparison routine that is not constant-time. In non–constant-time implementations, the time taken by the compare function may vary depending on where the first difference between the two serial numbers is found. An attacker can exploit these timing differences to deduce information about the serial numbers, potentially leading to further exploits.

To mitigate this issue, the repair changes the non–constant-time memory comparison function to one that operates in constant time. A constant-time function performs the comparison by processing all bytes of the serial number irrespective of where the mismatch might occur. This means that every invocation of the function takes the same amount of time, regardless of the contents of the two memory buffers. By doing so, no timing information is leaked that could allow an attacker to infer how many initial bytes match between two serial numbers.

In essence, the repair protects against timing side-channel attacks by ensuring that execution time does not reveal any useful information about the serial data being compared. It eliminates any data-dependent differences in execution time, thereby bolstering the security of the procedure involved in checking certificate revocation.
