Below is one way to repair the vulnerability. In the snippet the call to a non‐constant‐time memory compare (MemUtil.memcmp) is replaced by a constant‑time version (mbedtls_ct_memcmp) so that an attacker cannot exploit a timing side-channel on the certificate serial number comparison.

<repair>
            if (crt.serial.len == cur.serial.len
                    && mbedtls_ct_memcmp(crt.serial.p, cur.serial.p, crt.serial.len) == 0) {
                if (Helper.mbedtls_x509_time_is_past(cur.revocationDate))
                    return 1;
            }
</repair> 

This change ensures the serial number comparison is performed in constant time, removing the timing-based side-channel vulnerability.
