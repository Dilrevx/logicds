The vulnerability was caused by not performing any integrity check when processing messages with the security header type LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED_WITH_NEW_EPS_SECURITY_CONTEXT. In the buggy code, this case simply “breaks” from the switch statement without verifying that the NAS message hasn’t been tampered with. This could allow an attacker to send a message with a valid header type but a modified payload, bypassing integrity verification.

In the repair, a similar approach is applied to the LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED_WITH_NEW_EPS_SECURITY_CONTEXT case as used for the LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED case. Here’s what was changed:

1. For the LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED_WITH_NEW_EPS_SECURITY_CONTEXT branch, an integrity check is now explicitly performed by calling integrity_check(pdu.get()). This verifies the integrity of the payload before any further processing.

2. If the integrity check passes, the payload is decrypted by calling cipher_decrypt(pdu.get()). This step is similar to what happens in the other ciphered security header type case. Decrypting the payload only after confirming that it has not been tampered with ensures that subsequent operations (like interpretation of message contents) are performed on a verified and untampered payload.

3. If the integrity check fails, an error is logged and the function returns immediately. This prevents processing of messages that might have been altered by an attacker.

These changes ensure that every NAS message, including those with the new EPS security context (ciphered and integrity-protected), must pass the integrity check before any further processing or decryption occurs. As a result, the new vulnerability is mitigated because no NAS messages with the LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED_WITH_NEW_EPS_SECURITY_CONTEXT header will be accepted without its integrity being validated, thereby preventing possible acceptance of corrupted or malicious messages.

By aligning the handling of the new EPS security context with the integrity-checking logic used in the other ciphered cases, the repair maintains consistency in security policy across different security header types. This not only fixes the identified vulnerability but also reinforces the overall security posture of the NAS message processing, ensuring that all cryptographically protected messages undergo necessary integrity verification.
