Below is one way to implement the repair. The bug was that the code explicitly allowed messages with the header type for “integrity and ciphered with new EPS security context” to pass unchecked. In the patched version, that case is removed from the switch so that any message with that header type falls into the default error-handling branch.

Step by step:

1. Identify that the vulnerable header type is LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED_WITH_NEW_EPS_SECURITY_CONTEXT.
2. Remove the explicit case (which simply “breaks”) so that messages using this header type do not bypass the integrity check.
3. With that removal, such messages are caught by the default block and rejected.

Here’s the repaired code snippet:

--------------------------------------------------
        switch (sec_hdr_type) {
            case LIBLTE_MME_SECURITY_HDR_TYPE_PLAIN_NAS:
            case LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_WITH_NEW_EPS_SECURITY_CONTEXT:
            case LIBLTE_MME_SECURITY_HDR_TYPE_SERVICE_REQUEST:
                break;
            case LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY:
            case LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED:
                if (integrity_check(pdu.get())) {
                    if (sec_hdr_type == LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED) {
                        cipher_decrypt(pdu.get());
                    }
                    break;
                } else {
                    logger.error("Not handling NAS message with integrity check error");
                    return;
                }
            default:
                logger.error("Not handling NAS message with SEC_HDR_TYPE=%02X", sec_hdr_type);
                return;
        }
--------------------------------------------------

Now, if a message arrives with the header type LIBLTE_MME_SECURITY_HDR_TYPE_INTEGRITY_AND_CIPHERED_WITH_NEW_EPS_SECURITY_CONTEXT, it will no longer match an allowed case and will instead fall into the default clause, where the error is logged and the message is rejected.

This repair ensures that all messages must pass the integrity verification before further processing, thereby mitigating the vulnerability.
