In this version, before checking buffer space the code performs an early check to see whether it is running as a server that requires mutual authentication and whether the client's certificate has been validated (unless the session is resumed). If the certificate isn’t verified when required, then a fatal alert is raised and the handshake is aborted.

-------------------------------------------------
/* Entry point for handling TLSv1.3 Finished message */
Tls13Helper.WOLFSSL_ENTER("DoTls13Finished");

/* Early mutual-authentication check:
   - Check that we are running in server mode.
   - Confirm that the configuration requires mutual authentication.
   - Then, if the peer certificate has not been verified (and the session is not resumed),
     trigger a fatal TLS alert indicating that a certificate is required.
*/
if (ssl.isServer && ssl.config.requireMutualAuth && !ssl.peerCertVerified &&
    !ssl.sessionResumed) {
    /* Trigger a fatal alert indicating that the client did not provide
       a valid certificate (or did not send certificate_verify). */
    wolfSSL_Alert(ssl, WOLFSSL_TLS_FATAL, WOLFSSL_TLS_ALERT_CERTIFICATE_REQUIRED);
    return Constants.PEER_CERT_REQUIRED_E;  /* Custom error code for missing/invalid certificate */
}

/* Continue with the original buffer space check */
if (inOutIdx[0] + size + ssl.keys.padSz > totalSz)
    return Constants.BUFFER_E;

/* Continue with further processing... */
-------------------------------------------------

Explanation of the changes:

1. When the function is entered, we first check if the code is executing as a server that requires the client to prove its identity (mutual authentication).
2. The check uses two flags:
   • ssl.config.requireMutualAuth – indicating if the configuration demands a client certificate.
   • ssl.peerCertVerified – a flag that should be set when the client’s certificate is valid.
3. An additional flag, ssl.sessionResumed, is used to skip the certificate check if the session is being resumed, assuming prior successful validation.
4. If none of the acceptable conditions hold (i.e., the server is in mutual-auth mode, the peer’s certificate isn’t verified, and the session isn’t resumed), the code raises a fatal alert by calling wolfSSL_Alert, then returns an error code (Constants.PEER_CERT_REQUIRED_E) to abort the handshake.
5. Finally, the buffer size check remains unchanged.

This repair ensures that a TLS v1.3 server demanding mutual authentication cannot be bypassed by a client that omits the certificate_verify message.
