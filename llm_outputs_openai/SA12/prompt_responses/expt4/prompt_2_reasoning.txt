The repair adds a new conditional check right at the beginning when the TLS finished message is being processed. The goal is to ensure that if this is a server that requires mutual authentication, it does not allow a connection to proceed unless the client has been properly authenticated. Here’s how the repair works step by step:

1. The code first calls Tls13Helper.WOLFSSL_ENTER("DoTls13Finished") which logs that the function has been entered. This part remains unchanged.

2. Next, it checks if the connection is on the server side (ssl.isServer) and whether mutual authentication is required. This is determined by checking flags (ssl.mutualAuthRequired or ssl.failWithoutCertificate) that indicate the server’s configuration policy for client authentication. This ensures that the following certificate verification logic only applies to scenarios where the server explicitly demands a valid certificate from the client.

3. Within this scope, it performs another check to see if the session is not a resumed session (using ssl.isResumed) and the client's certificate has not been verified (using !ssl.peerCertVerified). The rationale here is that for new sessions where mutual authentication is required, a client must have already provided and verified a certificate. The exception is a resumed session, where prior verification might have occurred and it is acceptable to bypass these checks.

4. If the condition is met (i.e., the session isn’t resumed and the certificate hasn’t been verified), the code calls Tls13Helper.fatalAlert(Constants.alert_bad_certificate). This function triggers a fatal certificate alert, effectively terminating the handshake due to the absence of a proper client certificate. It then returns an error code (Constants.BAD_CERT_ALERT) to indicate the specific failure.

5. Finally, if none of the certificate authentication issues are present (meaning the client has been authenticated or it’s a resumed session), the function continues to execute the rest of its original logic. The subsequent check ensures that the provided buffer is large enough (inOutIdx[0] + size + ssl.keys.padSz <= totalSz), which preserves the original buffer overflow check of the buggy code.

By introducing this early conditional check, the repair blocks a scenario where a malicious client might purposely omit the certificate_verify message to bypass mutual authentication. This repair ensures that unless the peer certificate is validated, the handshake is stopped, thereby preventing unauthorized access.
