Below is one example of a fix. In the original code the check looked only at whether the parsed ACL lists were present. However, if an ACL file was specified but (after parsing) no entries were found (because the file was empty or had only comments), both aclList and aclPatterns remain NULL. That makes Mosquitto act as if no ACL file was defined and fall back to the default “allow‐everything” policy. To fix this you must distinguish between “no ACL file configured” and “ACL file configured but contains no rules.” One common fix is to add an extra flag (for example, a pointer or boolean that holds the configured ACL file path) that is non‑NULL or set if an ACL file was specified. Then only if no file was specified should we defer to the default policy. For example, if a new member securityOpts.aclFile is added (and is set when an ACL file is configured), you can change the code like this:

--------------------------------
/* If there is no ACL file configured at all, then defer.
 * Otherwise, even if the ACL file parsed to an empty list,
 * continue so that an (empty) ACL file denies access.  */
if (securityOpts.aclList == NULL && securityOpts.aclPatterns == NULL) {
    if (securityOpts.aclFile == NULL) {
        return MosqErr.MOSQ_ERR_PLUGIN_DEFER;
    }
    /* Otherwise, an ACL file was defined but contained no rules.
     * In that case we intentionally fall through to use the ACL logic,
     * which will then deny access by default. */
}

--------------------------------

Explanation:

• In the patch, we check whether any ACL file was specified (via securityOpts.aclFile).  
• If no ACL file was provided, the original “defer” behaviour (default allow) is maintained.  
• If an ACL file was provided but—for example, because it was empty—the lists are still NULL, then we continue processing so that the empty ACL file (i.e. no rules) results in denying all access (new and more secure behaviour).

You may need to adjust the exact member name (securityOpts.aclFile in this example) to match your code’s configuration structure, but this approach clearly distinguishes between “not defined” and “empty” ACL file.
