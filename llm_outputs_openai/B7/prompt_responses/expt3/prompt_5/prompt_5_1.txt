Explanation of the Changes:

1. Leaf Verification First:
   • The calls to x509_verify_cert_valid() and x509_verify_cert_hostname() have been moved ahead of the chain duplication.
   • This ensures that if either check fails, any error from leaf certificate evaluation is captured before allocating the chain copy.

2. Storing the Error:
   • If an error occurs during the leaf verifications and the error depth (here assumed to be initialized to –1) has not been updated, and it is not the specific error X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT_LOCALLY, the error is stored in the chain’s certificate errors array.
   • This prevents the original error from being overridden by later processing.

3. Robust Duplication and Finalization:
   • The certificate chain is duplicated only after passing the leaf verifications.
   • If the duplication fails, an appropriate out‑of‑memory error is returned.
   • Finally, on success the chain count is incremented and the context’s error values are updated to signal that the chain was successfully processed.

This repair addresses the original vulnerability where errors encountered during certificate verification could have been lost if a callback had advised continuation on an invalid certificate.
