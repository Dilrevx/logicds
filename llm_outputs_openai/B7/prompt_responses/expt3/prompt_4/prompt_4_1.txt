Below is one example of a patch that fixes the issue. In the original code the result of x509_verify_cert_valid is simply checked and a “0” is returned on failure – without saving the error code that the function produced. In the patched version we capture the error from the leaf certificate validity check (by passing a pointer to a local error variable) and then call x509_verify_cert_error() so that the context records the proper error and depth before returning failure. For example:

----------------------------------------------------------------
--- Original snippet:
	if (!x509_verify_ctx_validate_legacy_chain(ctx, chain, depth))
		return 0;

	/*
	 * In the non-legacy code, extensions and purpose are dealt
	 * with as the chain is built.
	 *
	 * The non-legacy api returns multiple chains but does not do
	 * any revocation checking (it must be done by the caller on
	 * any chain they wish to use)
	 */
	if ((ctx->chains[ctx->chains_count] = x509_verify_chain_dup(chain)) ==
	    NULL) {
		return x509_verify_cert_error(ctx, last, depth,
		    X509_V_ERR_OUT_OF_MEM, 0);
	}

	if (!x509_verify_cert_valid(ctx, leaf, NULL))
		return 0;

	if (!x509_verify_cert_hostname(ctx, leaf, name))
		return 0;

	ctx->chains_count++;
	ctx->error = X509_V_OK;
	ctx->error_depth = depth;
	return 1;
----------------------------------------------------------------

Below is one corrected version:

----------------------------------------------------------------
	/* Validate the legacy chain as before */
	if (!x509_verify_ctx_validate_legacy_chain(ctx, chain, depth))
		return 0;

	/*
	 * In the non-legacy code:
	 * - Extensions and purpose are processed as the chain is built.
	 * - Multiple chains may be returned, but revocation checking is left to the caller.
	 */
	if ((ctx->chains[ctx->chains_count] = x509_verify_chain_dup(chain)) == NULL) {
		return x509_verify_cert_error(ctx, last, depth, X509_V_ERR_OUT_OF_MEM, 0);
	}

	{
		/* Capture error from leaf certificate validity check */
		int err = X509_V_OK;
		if (!x509_verify_cert_valid(ctx, leaf, &err))
			/* Record the error (from the failed leaf certificate check)
			   along with the depth before returning failure */
			return x509_verify_cert_error(ctx, leaf, depth, err, 0);
	}

	if (!x509_verify_cert_hostname(ctx, leaf, name))
		return 0;

	ctx->chains_count++;
	/* Success: clear error state */
	ctx->error = X509_V_OK;
	ctx->error_depth = depth;
	return 1;
----------------------------------------------------------------

Explanation of changes:
1. A local variable “err” is added and passed by reference to x509_verify_cert_valid. This lets that function report the specific certificate validation error.
2. In case leaf certificate validation fails, the patch calls x509_verify_cert_error(ctx, leaf, depth, err, 0) so that the error value (and corresponding depth) are stored in the context.
3. The rest of the chain-building process remains unchanged.

This repair ensures that when a verification callback (or any caller) forces the validation to continue on a certificate error, the actual error from verifying the leaf certificate is not lost but is properly recorded in the context.
