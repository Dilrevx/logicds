Below is one acceptable fix that changes the branch condition so that a certificate‐verification failure (with ret==0) is not treated as a fatal error. In other words, we only report an error if ret is a negative error code. (Note that if OCSP_NOCHECKS is not in effect, a verification failure will now result in a normal failure (returning 0) rather than a fatal error.)

<repair>
    if (ret < 0) {
        ret = X509_STORE_CTX_get_error(ctx);
        ERR_raise_data(ERR_LIB_OCSP, OCSP_R_CERTIFICATE_VERIFY_ERROR,
                       "Verify error: %s", X509_verify_cert_error_string(ret));
        goto end;
    }
</repair>

In this repair the condition is changed from "ret <= 0" to "ret < 0" so that a ret value of 0 (which indicates a verification failure but not a fatal error) will not trigger the error‑reporting block.
