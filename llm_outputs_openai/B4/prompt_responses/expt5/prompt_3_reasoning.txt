The original code compared the OCSP response’s certificate serial number against the certificate’s serial number as obtained by gnutls_x509_crt_get_serial. However, it used the size fields from the OCSP response (rserial.size) and the certificate (cserial.size) without accounting for the actual length (t) returned by gnutls_x509_crt_get_serial. This mismatch could allow extra trailing bytes (potentially allocated by gnutls_malloc) to be present in the OCSP response serial number. An attacker might abuse this by supplying extra bytes in the OCSP response that are never checked, thereby bypassing the intended certificate validation.

The repair changes the comparison to use the actual length (t) of the serial number as determined by the certificate. Here's what changed and how it fixes the issue:

1. After calling gnutls_x509_crt_get_serial, the function now stores the actual serial length in variable t. Instead of using cserial.size in the comparison, we use t. This ensures that only the bytes defined by the certificate’s serial number computed length are compared.

2. The code verifies that the size of the serial in the OCSP response (rserial.size) exactly matches t. This ensures there are no additional trailing bytes in the OCSP response that could be used maliciously.

3. The memcmp comparison now compares only t bytes from both the certificate serial and the OCSP response’s serial value, removing the possibility that any bytes beyond the legitimate length might be used to spoof a valid OCSP response.

By switching to the actual serial length t rather than relying on the possibly misleading size fields, the repair effectively eliminates the vulnerability related to trailing bytes. Now, if an attacker attempts to supply an OCSP response with extra bytes, the size check (rserial.size != t) will detect the discrepancy and the function will terminate with an error. This defense in depth ensures that the certificate validation mechanism only accepts an OCSP response that matches the certificate's serial number exactly, per its true length, thereby preventing bypass via crafted trailing data.
