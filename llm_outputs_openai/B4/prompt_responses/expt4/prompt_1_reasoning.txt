The repair ensures that the actual length of the certificate's serial number (returned in the variable "t") is used when comparing against the OCSP response serial. Originally, the code compared the OCSP serial (rserial.size) to an internally stored serial size (cserial.size) rather than checking that the certificate call returned the correct length. This mismatch meant that any extraneous trailing bytes (perhaps from previous allocations via gnutls_malloc) in cserial.data could be ignored if cserial.size was larger than the true serial length, allowing an attacker to craft an OCSP response with additional bytes to bypass validation.

Here’s the step-by-step explanation of the repair:

1. The function gnutls_x509_crt_get_serial now writes the true length of the certificate’s serial number into the variable "t" when successfully called. This is crucial because it explicitly represents the number of bytes that are actually meant to be part of the serial number.

2. The repair then changes the comparison logic. Instead of comparing whether the sizes stored in rserial and cserial are identical (which may have been influenced by unintended trailing bytes in cserial), it now compares rserial.size directly to t. This check ensures that the OCSP response’s serial length is exactly equal to the actual length of the certificate's serial.

3. The memcmp function is also adjusted to use "t" as the number of bytes to compare. This guarantees that only the intended serial bytes are compared between the certificate and the OCSP response, rather than potentially erroneous extra data.

In summary, by using "t" (the length returned by gnutls_x509_crt_get_serial) both for the length check and memcmp, the code now validates that:
 • The OCSP response serial is of the expected, correct length.
 • The certificate's serial (as given by "t") exactly matches the serial in the OCSP response.

Thus, any trailing bytes not part of the true serial length are effectively ignored, thereby closing the vulnerability that could allow bypassing certificate validation.
