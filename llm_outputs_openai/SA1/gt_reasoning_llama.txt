The vulnerability in the wpa_supplicant implementation of PEAP (Protected EAP) allows an attacker to bypass authentication by sending an EAP-TLV Success packet instead of starting Phase 2 authentication. This is possible when wpa_supplicant is configured to not verify the network's TLS certificate during Phase 1 authentication, and an eap_peap_decrypt vulnerability is exploited to skip Phase 2 authentication.

The root cause of this vulnerability lies in the lack of proper validation of the encryption parameters. In the buggy code, the encryption initialization function is called without verifying the length of the key and initialization vector (IV). This allows an attacker to manipulate the encryption parameters, potentially leading to a successful authentication bypass.

The repair addresses this issue by adding a check for the length of the key and IV before calling the encryption initialization function. Specifically, it checks if the parameters contain "keylen" and "ivlen" and sets them accordingly. If the parameters are invalid or cannot be set, it throws an exception.

This additional check ensures that the encryption parameters are properly validated before proceeding with the encryption initialization. By doing so, it prevents an attacker from manipulating the encryption parameters and exploiting the eap_peap_decrypt vulnerability to skip Phase 2 authentication.

In essence, the repair adds an extra layer of validation to the encryption initialization process, making it more secure and preventing the authentication bypass vulnerability. This fix is crucial in preventing attackers from impersonating Enterprise Wi-Fi networks and ensuring the security of the wpa_supplicant implementation of PEAP.
