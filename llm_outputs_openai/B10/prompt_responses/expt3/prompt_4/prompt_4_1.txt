The problem is that after successfully generating a random IV, the code immediately overwrites it with zeros by calling XMEMSET. This causes the IV to always be zero, hence defeating the purpose of using a random IV. To fix the vulnerability, simply remove the XMEMSET call so the IV retains the random bytes generated by wc_RNG_GenerateBlock.

Below is the repaired code snippet:

--------------------------------------------------
            if (args->ivSz > 0) {
                args->iv = (byte*)XMALLOC(args->ivSz, ssl->heap, DYNAMIC_TYPE_SALT);
                if (args->iv == NULL)
                    ERROR_OUT(MEMORY_E, exit_buildmsg);

                ret = wc_RNG_GenerateBlock(ssl->rng, args->iv, args->ivSz);
                if (ret != 0)
                    goto exit_buildmsg;

                /* Removed XMEMSET to avoid overwriting the random IV */
            }
--------------------------------------------------

With this change, the IV is correctly generated and remains random as intended.
