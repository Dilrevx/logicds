The repair introduces an explicit step to set a flag indicating that ChangeCipherSpec (CCS) messages are expected at this point in the handshake, thereby addressing the vulnerability that allowed a crafted CCS to be injected earlier in the process. Here’s how the repair fixes the issue:

1. When the handshake state reaches SSL3_ST_CR_FINISHED_A or SSL3_ST_CR_FINISHED_B, the code logs that it is in the Finished state. This state is critical because it’s where the Finished message is processed, confirming that the handshake parameters are correct.

2. Before calling the function to process the Finished message, the repair sets a flag (using a bitwise OR operation on a flags field) to explicitly indicate that a CCS message is allowed. By doing so, the program now signals that encountering a CCS message is legitimate at this stage of the handshake.

3. This explicit flag setting prevents any premature acceptance of a CCS message and ensures that subsequent operations checking for this flag can differentiate between an expected CCS message and one that was injected maliciously. In the original buggy code, the absence of this flag allowed a man-in-the-middle attacker to manipulate the handshake by forcing the use of a zero-length master key.

4. After setting the flag, the function ssl3_get_finished() is called, which verifies the integrity of the Finished message. If the call returns a non-positive value, the handshake process is halted immediately, ensuring that no further processing occurs under potentially compromised conditions.

5. Only after the Finished message is successfully received and the handshake integrity is confirmed does the code transition to the final handshake state (SSL_ST_OK), ensuring a secure completion of the handshake.

In summary, the repair works by explicitly permitting the CCS message only when it is expected, preventing an attacker from injecting a CCS message prematurely. This measured approach ensures that the handshake proceeds only under conditions where the CCS message is valid and the cryptographic parameters are securely established.
