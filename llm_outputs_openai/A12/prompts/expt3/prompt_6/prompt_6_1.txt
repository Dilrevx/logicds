The repair introduces an additional check at the very beginning of the function that processes the TLS v1.3 Finished message. This step is performed only if client certificates are enabled in the build configuration.

The logic considers connections that are not resuming an existing session; the check applies only for fresh handshakes where the certificate verification is critical. If the verification flag is absent, which means the client did not send a valid certificate, the function immediately sets an appropriate error code to indicate a missing peer certificate.

After setting the error code, the function calls a routine to issue a fatal alert. This alert effectively notifies the client of the failure, and the handshake is terminated promptly. By doing this, the repair stops further processing, ensuring that no secret derivation or finished message processing occurs under insecure conditions.

Following the additional check, the remainder of the original function is executed as before. This includes verifying that the size computations do not exceed the available buffer space and deriving the finished secret if the handshake has already been completed. In other words, the essential functions for message integrity and cryptographic handshake completion are preserved; the repair simply ensures that these steps occur only after confirming a valid client certificate has been provided if one is required.

Overall, the repair secures the mutual authentication mechanism in TLS v1.3 by preventing a malicious client from forging a successful handshake without providing the required certificate. It effectively closes the vulnerability by adding a robust early check that enforces the expected certificate behavior before any critical cryptographic operations are executed.
