The repair adds an explicit check to validate that when mutual authentication is required (mutualAuthRequired flag is true), the client must have sent a CertificateVerify message (represented by the flag receivedCertVerify). Here’s what happens in the repair:

1. Before processing the finished message and deriving secret keys, the repair introduces a pre-check within a conditional compilation block (using #if defined(WOLFSSL_TLS13)) to ensure that these checks are only applied for TLS 1.3. This helps maintain compatibility for other protocol versions if needed.

2. The check “if (ssl->mutualAuthRequired && !ssl->receivedCertVerify)” makes sure that if the server requires mutual authentication but the client has not yet provided its certificate verification message, the function immediately returns an error (here represented as BAD_CERTIFICATE). By aborting the handshake at this point, the repair prevents a client from bypassing the certificate verification step by not sending the CertificateVerify message.

3. By ensuring the handshake does not proceed if the certificate hasn’t been verified, the server maintains the integrity of mutual authentication. This blocks a vulnerability where a malicious client might have been able to connect inappropriately by omitting the CertificateVerify message.

4. After this additional verification, the code continues to perform normal operations (deriving the finished secret) if the handshake is in the appropriate state (handShakeDone). The separation of the check ensures that the derivation process is only performed for clients that have been properly authenticated.

In summary, the repair fixes the vulnerability by introducing a condition that enforces the requirement that a client must send the CertificateVerify message when mutual authentication is configured. Consequently, if a client omits this critical piece of the TLS v1.3 handshake, the connection is rejected instead of continuing the handshake and deriving secrets. This patch thereby prevents an attacker from bypassing the mutual authentication process, keeping the TLS handshake secure.
