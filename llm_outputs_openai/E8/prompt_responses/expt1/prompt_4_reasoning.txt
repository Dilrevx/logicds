The repair addresses a potential vulnerability where SERVICE_REJECT (and similarly, ESM_INFORMATION_REQUEST) messages were processed by legacy parsers that might not perform sufficient validation. Previously, the code would call parse_service_reject(lcid, std::move(pdu)); which could inadvertently process a PDU that hadn’t undergone appropriate verification or that had been manipulated. This could expose the system to processing potentially malicious or tampered messages.

In the revised code, instead of calling the legacy parser for SERVICE_REJECT and ESM_INFORMATION_REQUEST messages, the function now logs that the message was dropped and does not further process these messages. Specifically:

1. For SERVICE_REJECT:
   - The code logs a message indicating that a SERVICE_REJECT PDU has been dropped (using logger.info). This prevents any further handling or processing that could be exploited.
   
2. For ESM_INFORMATION_REQUEST:
   - Similarly, the code logs that an ESM_INFORMATION_REQUEST PDU has been dropped. This is important so that if such messages occur, the system does not pass these messages through any legacy processing routines that could be vulnerable.

These changes ensure that unverified or reserved message types do not get processed by legacy functions that might not enforce adequate security checks. By dropping these messages rather than processing them, the fix minimizes the risk of introducing a security flaw via unexpected or malicious message types.

This approach tightly controls which message types are allowed for further processing by verifying that only known, verified, and safe message types are handled by their corresponding parsing functions. Logging the incident provides an audit trail that can help in diagnosing issues or detecting attempted misuse.

Overall, the correction strengthens the code by:
• Preventing unauthorized or unsafe processing by filtering out compromised or insecure messages.
• Simplifying the message handling logic by explicitly handling unsupported types.
• Ensuring that the system does not inadvertently execute legacy code that has known vulnerabilities when processing certain PDUs.

This measures to drop risky message types effectively neutralize the identified vulnerability, ensuring that only messages meeting strict integrity and security criteria receive further processing.
