The vulnerability in the OpenSSL library arises from the incorrect handling of custom ciphers created using the EVP_CIPHER_meth_new() function. When an application passes NID_undef as the NID value to EVP_CIPHER_meth_new(), the library mistakenly identifies the NULL cipher as an equivalent cipher and uses it for encryption and decryption. This results in the plaintext being emitted as the ciphertext, effectively rendering the encryption useless.

The root cause of this issue lies in the fact that the library does not properly handle custom ciphers with an undefined NID. To address this vulnerability, the repair focuses on correctly identifying and handling custom ciphers.

The buggy code only checks for the presence of an engine, a temporary implementation, or an implementation. However, it fails to consider the origin of the cipher. The repair introduces additional checks to ensure that custom ciphers created using EVP_CIPHER_meth_new() are handled correctly.

The repair adds two new conditions to the if statement:

1. It checks if the cipher is not NULL and its origin is EVP_ORIG_METH, which indicates that the cipher was created using EVP_CIPHER_meth_new(). If this condition is true, the code proceeds to the legacy path.
2. It checks if the cipher is NULL, but the context's cipher is not NULL and its origin is EVP_ORIG_METH. This condition ensures that even if the cipher is NULL, the context's cipher is still checked for its origin.

By adding these conditions, the repair ensures that custom ciphers created using EVP_CIPHER_meth_new() are correctly identified and handled. If a custom cipher is detected, the code proceeds to the legacy path, where it will use the custom cipher directly instead of attempting to fetch an equivalent cipher from the available providers. This prevents the NULL cipher from being used and fixes the vulnerability.

In summary, the repair addresses the vulnerability by introducing additional checks to correctly identify and handle custom ciphers created using EVP_CIPHER_meth_new(). This ensures that the library uses the custom cipher directly and prevents the NULL cipher from being used, thereby fixing the vulnerability.
