Below is an example repair for the affected EVP_xxxInit_ex2()–style function. In this illustration the code checks whether the input or the already‐stored cipher comes from the legacy custom creation path (for example, by having its “origin” field marked as LEGACY). When a legacy custom cipher is detected, the provider lookup is skipped (and any provider‐fetched cipher is freed if already obtained), so that an unintended match to the NULL cipher cannot occur. (Note: this example is written in C‐like pseudocode to illustrate the repair strategy.)

-----------------------------------------------------------
/* Example of the original vulnerable code snippet (simplified):

int evp_cipher_init(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *cipher, ...)
{
    EVP_CIPHER *prov_cipher = NULL;
    // ... some engine and pointer checks ...

    // If no legacy mark is used, attempt to get an equivalent provider cipher.
    if (cipher == NULL)
        goto provider_lookup;

    prov_cipher = fetch_provider_cipher(cipher->nid, ...);
    if (prov_cipher == NULL)
        return 0;

    ctx->cipher = prov_cipher;
    // Continue with encryption/decryption initialisation
    return 1;

provider_lookup:
    ...
}
*/

-----------------------------------------------------------
/* The following shows the repaired version with extra conditions that check
   for a legacy custom cipher using an “origin” field. When the legacy flag is
   set, the code bypasses provider lookup and ensures any fetched provider
   cipher is freed and cleared. */

#define ORIGIN_LEGACY  0x1  /* Assume legacy ciphers mark their origin with this flag */

int evp_cipher_init(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *cipher, ...)
{
    EVP_CIPHER *prov_cipher = NULL;

    /* 
     * New repair: check if the provided cipher or the cipher in the context
     * was created using the legacy method. For example, the cipher struct
     * might have an "origin" field that is set ORIGIN_LEGACY if it is legacy.
     */
    if (cipher != NULL && (cipher->origin & ORIGIN_LEGACY))
        goto legacy_handling;

    if (cipher == NULL && ctx->cipher != NULL && (ctx->cipher->origin & ORIGIN_LEGACY))
        goto legacy_handling;

    /* Non-legacy flow: perform normal provider lookup */
provider_lookup:
    prov_cipher = fetch_provider_cipher(cipher->nid, ...);
    if (prov_cipher == NULL)
        return 0;

    /* 
     * New repair: If the fetched provider cipher is itself recognized as coming
     * from the legacy function (or if the context still holds a legacy cipher),
     * clean up and force legacy handling.
     */
    if ((prov_cipher->origin & ORIGIN_LEGACY) ||
         (ctx->cipher != NULL && (ctx->cipher->origin & ORIGIN_LEGACY))) {
        /* Free the fetched provider cipher to avoid conflict */
        EVP_CIPHER_free(prov_cipher);
        prov_cipher = NULL;
        goto legacy_handling;
    }

    /* Normal non-legacy initialization */
    ctx->cipher = prov_cipher;
    // Continue setting up the rest of the cipher context normally.
    return 1;

legacy_handling:
    /*
     * The legacy branch: ensure that any provider-fetched cipher is cleaned up,
     * and then perform legacy-specific initialisation.
     */
    if (prov_cipher != NULL) {
        EVP_CIPHER_free(prov_cipher);
        prov_cipher = NULL;
    }
    /* 
     * Force usage of the legacy cipher in the context.
     * Note: legacy_cipher may be either the provided "cipher" or the one stored in
     * the context (ctx->cipher). Here we assume legacy_initialisation() takes care of
     * the proper setup for legacy custom ciphers.
     */
    ctx->cipher = (cipher != NULL) ? (EVP_CIPHER *)cipher : ctx->cipher;
    return legacy_initialization(ctx, ...);
}

-----------------------------------------------------------
Explanation:

1. Two conditional blocks check for legacy custom ciphers:
   • If a non-null provided cipher is marked with ORIGIN_LEGACY.
   • If the provided cipher is null but the existing ctx->cipher is legacy.

2. In the provider lookup phase, we check again whether the fetched provider cipher or
   the already attached context cipher is legacy. In that case we free the provider cipher,
   clear its pointer, and jump to the legacy handling branch.

3. In the legacy branch, any conflicting state is cleaned up before calling the legacy‐specific
   initialization routine.

By applying these checks, the code avoids inadvertently substituting a legacy custom cipher with
an equivalent provider cipher – preventing the scenario where the NULL cipher might be used, which
would result in the plaintext being output as ciphertext.

This repair thus addresses the vulnerability reported in OpenSSL versions 3.0.0 to 3.0.5.
