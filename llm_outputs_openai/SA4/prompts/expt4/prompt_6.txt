<vulnerability_description>
The OpenSSL 3.0 implementation of the RC4-MD5 ciphersuite incorrectly uses the AAD data as the MAC key. This makes the MAC key trivially predictable. An attacker could exploit this issue by performing a man-in-the-middle attack to modify data being sent from one endpoint to an OpenSSL 3.0 recipient such that the modified data would still pass the MAC integrity check.

However, when the AAD data, which is typically transmitted in its plain form, is misused as the MAC key, it becomes trivially predictable. Predictability of a MAC key breaks the confidentiality guarantee and opens up the possibility for a man-in-the-middle attacker to alter data while still having it pass MAC integrity checks.

The repair step involves identifying the incorrect parameter call and replacing it with the correct one. This correct parameter, identified as the AEAD MAC key, securely stores the key used in the MAC algorithm.
