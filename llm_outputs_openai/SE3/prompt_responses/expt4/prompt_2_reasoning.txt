The repair adds an integrity check for two specific message types—registration_accept and configuration_update_command—by verifying that their header is set to the expected value (2) before processing them. Here’s how the repair works:

1. For the registration_accept case, before calling handle_registration_accept, the code checks if current_message_header equals 2. If it does, the function is called normally. If not, an error is logged and the function immediately returns an error code (SRSRAN_ERROR). This means that even if a registration_accept message arrives with a “plain header” (one that bypasses integrity protection), the code will reject it, preventing further processing.

2. Similarly, for the configuration_update_command case, the code first checks whether current_message_header equals 2. Only if the check passes does it handle the message by calling handle_configuration_update_command. Otherwise, an error is logged and the function returns SRSRAN_ERROR. This ensures that messages that are supposed to be integrity-protected won’t be processed if they’re not.

3. For all other message types that do not require such strict integrity validation, the repair leaves the processing as it was by simply routing them to their respective handling functions.

This targeted approach addresses the vulnerability by ensuring that messages expected to be integrity-protected are not processed unless their header value indicates proper protection. The check prevents attackers from sending manipulated or “plain header” messages for these critical operations, thereby closing the potential attack vector.

By logging an error and returning an error code when the header check fails, the code not only stops insecure messages from being processed, but it also provides diagnostic information which could be used for further investigation or alerting in the case of a repeated attempt to bypass integrity protections.

Overall, the repair effectively mitigates the risk by binding the correct header value to the processing of these sensitive NAS messages.
