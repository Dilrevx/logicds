Below is one approach to fix the vulnerability. The issue is that messages with plain headers (for example, registration accept and configuration update command in their plain variants) are accepted without verifying their integrity. To repair the bug you must verify the integrity of these messages before processing them. One way to do that is to use an integrity‐check function (for example, check_integrity) that returns false if the MAC (or similar security tag) is missing or invalid.

Below is an updated version of the switch statement that explicitly checks the integrity of plain header messages before calling the corresponding handler functions:

--------------------------------------------------
  // Example integrity check function (implementation depends on the context)
  bool check_integrity(const NasMessage& msg) {
      // Verify that msg contains valid integrity protection.
      // This might include computing a MAC and comparing it with an expected value.
      // Return false if the integrity verification fails.
      return msg.integrity_protected;  // For illustration purposes only.
  }

  switch (nas_msg.hdr.message_type) {

      case MsgOpts.Options.registration_accept:
          if (!check_integrity(nas_msg)) {
              logger.error("Integrity check failed for registration_accept message. Rejecting message.");
              break; // or return an error code
          }
          handle_registration_accept(nas_msg.registration_accept());
          break;

      case MsgOpts.Options.registration_reject:
          // Assuming registration_reject messages are not plain (or are handled securely)
          handle_registration_reject(nas_msg.registration_reject());
          break;

      case MsgOpts.Options.authentication_reject:
          handle_authentication_reject(nas_msg.authentication_reject());
          break;

      case MsgOpts.Options.authentication_request:
          handle_authentication_request(nas_msg.authentication_request());
          break;

      case MsgOpts.Options.identity_request:
          handle_identity_request(nas_msg.identity_request());
          break;

      case MsgOpts.Options.security_mode_command:
          // For security_mode_command, integrity has already been verified as part of security activation.
          handle_security_mode_command(nas_msg.security_mode_command(), pdu);
          break;

      case MsgOpts.Options.service_accept:
          handle_service_accept(nas_msg.service_accept());
          break;

      case MsgOpts.Options.service_reject:
          handle_service_reject(nas_msg.service_reject());
          break;

      case MsgOpts.Options.deregistration_accept_ue_terminated:
          handle_deregistration_accept_ue_terminated(nas_msg.deregistration_accept_ue_terminated());
          break;

      case MsgOpts.Options.deregistration_request_ue_terminated:
          handle_deregistration_request_ue_terminated(nas_msg.deregistration_request_ue_terminated());
          break;

      case MsgOpts.Options.dl_nas_transport:
          handle_dl_nas_transport(nas_msg.dl_nas_transport());
          break;

      case MsgOpts.Options.deregistration_accept_ue_originating:
          handle_deregistration_accept_ue_originating(nas_msg.deregistration_accept_ue_originating());
          break;

      case MsgOpts.Options.configuration_update_command:
          if (!check_integrity(nas_msg)) {
              logger.error("Integrity check failed for configuration_update_command message. Rejecting message.");
              break; // or return an error code
          }
          handle_configuration_update_command(nas_msg.configuration_update_command());
          break;

      default:
          logger.error("Not handling NAS message type: " + nas_msg.hdr.message_type);
          break;
  }
--------------------------------------------------

Explanation:

1. An integrity check function (here named check_integrity) is introduced. Its implementation must correctly verify that a message is protected by a valid integrity mechanism. (Depending on the actual framework, this implementation may be more complex.)

2. For messages known to be sent using plain headers (such as registration_accept and configuration_update_command), the code now calls check_integrity(nas_msg) before processing them. If the check fails, it logs an error and the message is dropped.

3. Other message types (or messages that are assumed to already be integrity-protected) continue to be processed as before.

This repair ensures that messages which would otherwise bypass integrity checks are now properly verified, mitigating the vulnerability.
