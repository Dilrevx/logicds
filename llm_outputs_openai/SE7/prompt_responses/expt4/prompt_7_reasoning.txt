The repair mainly adds additional integrity checks for certain NAS message types that are sensitive and should not be accepted in plaintext. Previously, messages like Detach Request, EMM Information, EMM Status, and Attach/Service Reject (when emm_cause equals 25) were permitted even if they arrived without integrity checks. This could allow an attacker to spoof these messages in plaintext and potentially disrupt service or trigger incorrect behavior.

Key changes in the repair include:

1. Integrity Enforcement for Sensitive NAS Messages:
   • The repair introduces a check when the message is received with the plaintext security header (LIBLTE_MME_SECURITY_HDR_TYPE_PLAIN_NAS). In the original code, a broad set of message types was allowed in plaintext.
   • Now, the allowed plaintext messages are restricted to only a few non-sensitive types (such as Identity Request, Authentication Request, Authentication Reject, Detach Accept, and Tracking Area Update Reject).

2. Special Handling for Attach/Service Reject:
   • For messages such as Attach Reject and Service Reject, the repair code calls LiblteMme.parseEmmCause() to extract the emm_cause value from the message.
   • If the emm_cause equals 25, the repair triggers the error path and returns an error status. This ensures that such messages, which might be used by attackers to cause denial-of-service or spoof legitimate behavior, are not accepted in plaintext.

3. Default Denial for Other Sensitive Types:
   • Sensitive messages (EMM Information, EMM Status, Detach Request, etc.) that were not explicitly allowed are rejected if they come without integrity protection. The default clause in the switch statement logs an error and returns SRSRAN_ERROR.
   • This prevents an attacker from injecting sensitive messages without proper integrity credentials.

4. Log Messages for Clarity:
   • The added error logging clearly indicates when a message is being rejected due to lack of integrity or an unacceptable emm_cause. This helps with diagnostics and provides clarity on why a particular message was not accepted.

Overall, by enforcing that sensitive NAS messages must include integrity protection—and explicitly checking that messages like Attach/Service Reject with emm_cause 25 are not processed in plaintext—the repair makes the system more robust against spoofing attacks. This means that if an attacker were to send one of these messages in plaintext, the system would log an error and discard the message rather than proceeding with vulnerable behavior.
