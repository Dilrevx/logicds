The primary goal of the repair was to ensure that NAS messages that must be integrity protected are no longer accepted when received in plaintext. The vulnerability originally allowed several sensitive NAS message types, including Detach Request, EMM Information, EMM Status, and Attach/Service Reject when accompanied by emm_cause 25, to bypass integrity protection. This could enable attackers to craft and inject malicious messages bypassing security policies.

In the repair, the first step was to limit the number of message types that are acceptable when the security header indicates that the message is in plaintext (LIBLTE_MME_SECURITY_HDR_TYPE_PLAIN_NAS). Not all NAS message types are designed to be processed without integrity protection. Only a few message types, such as Identity Request, Authentication Request, Authentication Reject, Detach Accept, and Tracking Area Update Reject, are considered safe enough to allow in plaintext under certain conditions. By restricting processing to only these messages, the repair minimizes exposure to malicious NAS messages.

For the messages that require extra caution, specifically the Attach Reject and Service Reject message types, an additional check on the emm_cause value is introduced. The vulnerability was particularly tied to the situation where emm_cause equals 25, which could be exploited in their previous handling. In the repaired code, when an Attach Reject or Service Reject message is received in plaintext, it inspects the emm_cause variable. If the emm_cause is exactly 25, the function logs an error message and immediately returns an error (SRSRAN_ERROR), hence preventing further processing. This dynamic check adds a layer of validation, ensuring that even if such message types are received, only those with safe emm_cause values (other than 25) might be processed. However, in this design, the safer approach is to deny processing of the message if it meets the vulnerable criteria.

Furthermore, the vulnerable NAS messages such as EMM Information, EMM Status, and Detach Request, which were erroneously allowed in plaintext in the original code, have been completely removed from the acceptable list. These messages have properties that could be leveraged maliciously if not protected by integrity mechanisms. By not listing them in the acceptable cases in the switch block, the “default” case of the switch will catch these messages, log an error, and return an error code. This ensures that any attempt to use these messages over an insecure channel is immediately terminated, and the event is recorded for further auditing or debugging purposes.

The logging was kept consistent, but it was enhanced to include relevant details like msg_type, sec_hdr_type, and emm_cause (in the exception of Attach/Service Reject with cause 25) to support detailed forensic analysis if the error condition is triggered. This is a critical aspect of defensive programming, where audit trails help identify potential exploitation attempts.

In summary, this repair carefully narrows the allowed plaintext NAS messages to only those that are deemed non-critical and safe, while applying an additional safeguard for vulnerable reject messages by checking the emm_cause. Any message type falling outside these strictly defined bounds is logged and rejected. This comprehensive approach ensures that the vulnerability described is effectively mitigated by enforcing integrity checks where necessary.
