Below is one way to repair the code so that unprotected NAS messages are accepted only when they are one of the allowed types (EMM Information, EMM Status, or Detach Request) or an Attach/Service Reject that carries the specific emm_cause (25). In other words, we remove the extra plain‑NAS messages and add a validation step for Attach/Service Reject messages. For example:

------------------------------------------------
/* Only allow plaintext messages for EMM Information, EMM Status, Detach Request,
   and for Attach/Service Reject (or SERVICE_REJECT) messages provided the emm_cause equals 25.
   All other messages received in plaintext must be rejected. */
if (sec_hdr_type == LIBLTE_MME_SECURITY_HDR_TYPE_PLAIN_NAS) {
    switch (msg_type) {
        case LIBLTE_MME_MSG_TYPE_EMM_INFORMATION:
        case LIBLTE_MME_MSG_TYPE_EMM_STATUS:
        case LIBLTE_MME_MSG_TYPE_DETACH_REQUEST:
            /* These messages are allowed in plaintext. */
            break;
        case LIBLTE_MME_MSG_TYPE_ATTACH_REJECT:
        case LIBLTE_MME_MSG_TYPE_SERVICE_REJECT:
            /* Only allow Attach/Service Reject / Service Reject if emm_cause is exactly 25. */
            if (emm_cause != 25) {
                logger.error(
                    "Plaintext NAS message %02X rejected due to invalid emm_cause (%d)",
                    msg_type, emm_cause
                );
                return SRSRAN_ERROR;
            }
            break;
        default:
            logger.error(
                "Not handling NAS message MSG_TYPE=%02X with SEC_HDR_TYPE=%02X without integrity protection!",
                msg_type, sec_hdr_type
            );
            return SRSRAN_ERROR;
    }
}
------------------------------------------------

Explanations of the repair:

1. Removed extra cases (such as Identity Request, Authentication Request/Reject, Detach Accept, Tracking Area Update Reject) that were previously allowed in plaintext. This now restricts acceptable plaintext messages to only the ones defined by the vulnerability description.

2. For Attach/Service Reject, an extra check is done to ensure that its emm_cause is 25. If not, the message is rejected.

This patch therefore ensures that plaintext NAS messages are handled only if they fall within the allowed types and parameters, fixing the vulnerability.
