The repair corrects the certificate chain’s state management to ensure that the untrusted certificate count accurately reflects the chain after any alterations, thereby mitigating the risk of misidentifying a leaf certificate as a trusted CA. Here’s how the changes address the vulnerability:

1. In the self-signed certificate branch for non-singleton chains, after removing the last certificate from the chain, the repair immediately resets the last_untrusted counter to the current chain size (ctx.last_untrusted = ctx.chain.size()). This guarantees that the untrusted certificate count is consistent with the actual chain length, preventing any undercounting that might allow an attacker to exploit discrepancies in trust evaluation.

2. In the loop that builds an alternative chain by fetching the issuer for the current certificate, the code now accumulates new certificates into the chain. Once moved, the chain’s size (num) and, later, the last_untrusted counter are updated accordingly. By doing so, it ensures that only correctly validated certificates contribute to the chain while eliminating leftover untrusted entries that could be abused.

3. In the alternative chain search loop (where the code iterates backward starting at a certain index), if a valid alternative issuer is found, the repair frees the temporary issuer resource and then removes any excess certificates from the end of the chain. After removals, it again resets the last_untrusted counter based on the new chain size. This step stops attackers from leveraging improperly classified trust levels by ensuring that the chain only discovers issuers based on rigorous processing of basic constraints and properly updated chain length.

Overall, by explicitly reassigning the untrusted certificate count (ctx.last_untrusted) based on the current chain length both after certificate removals and after accepting an alternative chain segment, the patch prevents attackers from “spoofing” a Certification Authority role. This thorough management of state means that even if a valid leaf certificate is present, it cannot be misinterpreted as coming from a trusted CA, because the chain state now reliably reflects the correct, updated trust metrics.
