The problem is that the code generates a random IV and then destroys that randomness by zeroing out every byte, effectively using an all-zero IV—which is insecure. To fix the vulnerability, simply remove the loop that overwrites the IV with zeros. Here’s the repaired code:

--------------------------------------------------
        if (args.ivSz > 0) {
            args.iv = new byte[args.ivSz];
            int ret = ssl.rng.generateBlock(args.iv, args.ivSz);
            if (ret != 0) {
                return ret;
            }
            ssl.lastIv = args.iv;
        }
--------------------------------------------------

With this change, the IV generated by the secure random number generator will be preserved and used as intended for AES-CBC or DES3 cipher modes in TLS/DTLS 1.2 or 1.1.
