Below is one way to repair the vulnerability. The bug was that the code simply accepted the algorithms provided by the network—even if they were “plain” (i.e. NIA0 for integrity or NEA0 for ciphering)—without verifying that this does not result in a bypass of NAS security activation. In many standards the “plain” algorithms (that is, no ciphering and/or no integrity protection) must not be accepted unless in special cases. An attacker might force the UE to use no security by including nas_sm_cmd_NIA0_plain, so the repair is to explicitly reject a Security Mode Command that selects plain (i.e. insecure) algorithms.

Below is an example of a fixed code snippet. (Note that the actual constant names for the “plain” algorithms may differ in your codebase. Adjust the names and error causes accordingly.)

------------------------------------------------
  // Reject plain algorithm requests to enforce NAS security activation
  if (security_mode_command.selected_nas_security_algorithms.ciphering_algorithm.value == CIPHERING_ALGORITHM_NONE ||
      security_mode_command.selected_nas_security_algorithms.integrity_protection_algorithm.value == INTEGRITY_ALGORITHM_NONE) {
    logger.warning("Rejecting Security Mode Command: insecure (plain) NAS algorithms requested");
    send_security_mode_reject(cause_5gmm_t::cause_5gmm_type_::insecure_nas_algorithms);
    return SRSRAN_ERROR;
  }

  // Now it is safe to assign the algorithms
  ctxt_base.cipher_algo =
      (CIPHERING_ALGORITHM_ID_ENUM)security_mode_command.selected_nas_security_algorithms.ciphering_algorithm.value;
  ctxt_base.integ_algo =
      (INTEGRITY_ALGORITHM_ID_ENUM)security_mode_command.selected_nas_security_algorithms.integrity_protection_algorithm.value;

  // Check replayed ue security capabilities
  if (!check_replayed_ue_security_capabilities(security_mode_command.replayed_ue_security_capabilities)) {
    logger.warning("Sending Security Mode Reject due to security capabilities mismatch");
    send_security_mode_reject(cause_5gmm_t::cause_5gmm_type_::ue_security_capabilities_mismatch);
    return SRSRAN_ERROR;
  }

  if (initial_sec_command) {
    set_k_gnb_count(0);
    ctxt_base.tx_count  = 0;
    initial_sec_command = false;
  }

------------------------------------------------

Explanation of the changes:
1. A check is inserted at the very beginning that verifies whether either the ciphering algorithm or the integrity algorithm was set to a “plain” (or none) value (here assumed to be represented by CIPHERING_ALGORITHM_NONE and INTEGRITY_ALGORITHM_NONE). If so, the UE logs a warning, sends the appropriate Security Mode Reject message (with a specific cause, e.g. insecure_nas_algorithms) and returns an error immediately.
2. Only if both algorithms are secure does the code continue assigning them and proceed with the rest of the security mode command processing.

This ensures that a nas_sm_cmd_NIA0_plain message doesn’t bypass security activation by forcing the use of plain (unsecured) algorithms.
