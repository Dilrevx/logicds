Below is one approach to fixing the vulnerability. The core issue is that the UE is allowed to select the insecure “NIA0_plain” (or equivalent) algorithm, which bypasses RRC security activation. To mitigate this, you should validate the algorithms before accepting the command. In other words, before applying the chosen algorithms, the code must verify that neither ciphering nor integrity is set to the insecure “plain” variant. If one is detected, the system should either fall back to a secure default or — more preferably — reject the configuration outright.

For example, if you have a method that applies the security configuration, you can add validation like this:

-----------------------------------------------------------
public enum CIPHERING_ALGORITHM_ID_ENUM {
    CIPHERING_ALGORITHM_NIA0_PLAIN,
    CIPHERING_ALGORITHM_SECURE, // other secure variants
    // ... add additional algorithms as needed
}

public enum INTEGRITY_ALGORITHM_ID_ENUM {
    INTEGRITY_ALGORITHM_NIA0_PLAIN,
    INTEGRITY_ALGORITHM_SECURE, // other secure variants
    // ... add additional algorithms as needed
}

public class RrcSecurityConfig {
    public CIPHERING_ALGORITHM_ID_ENUM cipher_algo;
    public INTEGRITY_ALGORITHM_ID_ENUM integ_algo;

    /**
     * Sets the security algorithms after validating that insecure options are not used.
     *
     * @param cipher The ciphering algorithm.
     * @param integ The integrity algorithm.
     * @throws IllegalArgumentException if an insecure algorithm is provided.
     */
    public void setSecurityAlgorithms(CIPHERING_ALGORITHM_ID_ENUM cipher,
                                      INTEGRITY_ALGORITHM_ID_ENUM integ) {

        // Validate that insecure plain modes are NOT being set
        if (cipher == CIPHERING_ALGORITHM_ID_ENUM.CIPHERING_ALGORITHM_NIA0_PLAIN ||
            integ == INTEGRITY_ALGORITHM_ID_ENUM.INTEGRITY_ALGORITHM_NIA0_PLAIN) {
            throw new IllegalArgumentException("Insecure algorithm configuration is not allowed: " +
                    "RRC security activation must not be bypassed.");
        }

        // Accept the secure algorithms
        this.cipher_algo = cipher;
        this.integ_algo = integ;
    }
}
-----------------------------------------------------------

Step by step explanation:

1. Identify the insecure algorithm (in this case, NIA0_plain) that bypasses security activation.
2. In the setter (or before applying the configuration), add a check to verify the algorithm values.
3. If the insecure value is detected, reject the configuration by throwing an exception (or taking appropriate remedial action).
4. Only assign the algorithm values if they pass the security check.

By introducing this validation step, you ensure that the RRC security activation is not bypassed by allowing a “plain” security command. This approach prevents the UE from accepting rrc_sm_cmd_NIA0_plain, thereby mitigating the vulnerability.
