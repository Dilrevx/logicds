Below is one acceptable repair. In TLS 1.3 the client MUST not fall back to a hard‐coded (and hence predictable) IKM value when no valid key exchange material is received. Instead, the handshake must be aborted. One fix is to check that (for TLS 1.3) at least one valid key exchange extension is present – either a PSK with the “chosen” flag set or a key share extension – and if neither is found, to terminate the handshake rather than continue with a default IKM value. (The same concept applies in implementations on both ends of the connection.) 

For example, assuming that your code can detect TLS 1.3 (for example, via a helper function IsTLS13(ssl) or by checking a version field), one repair is as follows:

--------------------------------------------------------------------------------
/* Patched code snippet */
if (*extMsgType == server_hello) {

#if defined(HAVE_SESSION_TICKET) || !defined(NO_PSK)
    PreSharedKey* psk = NULL;
    TLSX* ext = TLSX_Find(ssl->extensions, TLSX_PRE_SHARED_KEY);
    if (ext != NULL)
        psk = (PreSharedKey*)ext->data;
    while (psk != NULL && !psk->chosen)
        psk = psk->next;
#endif

#if defined(WOLFSSL_TLS13)
    /* For TLS 1.3, also check for a key share extension.
       TLSX_KEY_SHARE should be defined if key share extensions are present. */
    TLSX* extKSE = TLSX_Find(ssl->extensions, TLSX_KEY_SHARE);

    if (IsTLS13(ssl) && (psk == NULL && extKSE == NULL)) {
        /* Neither a valid PSK nor a valid key share extension was provided.
           Abort the handshake to prevent use of a default predictable IKM. */
        return SSL_FATAL_ERROR;  /* or use an appropriate error code */
    }
#endif

#if defined(HAVE_SESSION_TICKET) || !defined(NO_PSK)
    if (psk == NULL) {
        /* For non-TLS13 sessions without a PSK, the old behavior is acceptable. */
        ssl->options.resuming = 0;
        ssl->arrays->psk_keySz = 0;
        XMEMSET(ssl->arrays->psk_key, 0, MAX_PSK_KEY_LEN);
    }
    else {
        if ((ret = SetupPskKey(ssl, psk, 0)) != 0)
            return ret;
        ssl->options.pskNegotiated = 1;
    }
#endif

    ssl->keys.encryptionOn = 1;
    ssl->options.serverState = SERVER_HELLO_COMPLETE;
}
else {
    ssl->options.tls1_3 = 1;
    ssl->options.serverState = SERVER_HELLO_RETRY_REQUEST_COMPLETE;

    ret = RestartHandshakeHash(ssl);
}

--------------------------------------------------------------------------------

Explanation:

• In the patched code we first try to locate a PSK extension (if enabled).  
• Then, if TLS 1.3 is in use (for example via the helper IsTLS13(ssl)) we also look for a key share extension (TLSX_KEY_SHARE).  
• If neither a chosen PSK nor a key share extension is provided (psk == NULL && extKSE == NULL), we immediately abort the handshake instead of continuing with a “default” IKM value.  
• In non‐TLS 1.3 sessions the original behavior is preserved.  

This repair ensures that in TLS 1.3 mode an attacker cannot force the use of a known IKM value and compromise session key material by omitting the required key share extensions.
