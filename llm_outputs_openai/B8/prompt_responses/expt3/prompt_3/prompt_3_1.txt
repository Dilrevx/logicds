Below is one example of a repair. In older versions the code would default to a predictable “zeroed” PSK buffer when neither a PSK nor a key share (KSE) extension was found. Instead, the patched code explicitly checks that at least one necessary extension (either PSK or key share) is present. If neither is found, the handshake is aborted rather than using a weak, known IKM value. One correct repair is to detect the absence of both extensions and return an error immediately. For example:

---------------------------------------------------------
/* Sample patched code: */
if (*extMsgType == server_hello) {
#if defined(HAVE_SESSION_TICKET) || !defined(NO_PSK)
    PreSharedKey* psk = NULL;
    TLSX* ext = TLSX_Find(ssl->extensions, TLSX_PRE_SHARED_KEY);
    if (ext != NULL)
        psk = (PreSharedKey*)ext->data;
    while (psk != NULL && !psk->chosen)
        psk = psk->next;
#endif

#ifdef HAVE_KEY_SHARE
    /* Check for presence of a key share extension */
    TLSX* ks_ext = TLSX_Find(ssl->extensions, TLSX_KEY_SHARE);
#else
    TLSX* ks_ext = NULL;
#endif

    /* If neither valid PSK nor Key Share are provided, abort handshake. */
#if defined(HAVE_SESSION_TICKET) || !defined(NO_PSK)
    if (psk == NULL && ks_ext == NULL) {
#else
    if (ks_ext == NULL) {
#endif
        /* Abort handshake rather than using a default predictable IKM */
        return BAD_HANDSHAKE_EXTENSION;  /* or an appropriately defined error code */
    }

#if defined(HAVE_SESSION_TICKET) || !defined(NO_PSK)
    if (psk != NULL) {
        if ((ret = SetupPskKey(ssl, psk, 0)) != 0)
            return ret;
        ssl->options.pskNegotiated = 1;
    } else {
        /* If only Key Share is present then no PSK processing is needed */
        ssl->options.resuming = 0;
        ssl->arrays->psk_keySz = 0;
        /* It is now safe to leave ssl->arrays->psk_key uninitialized or securely cleared */
        XMEMSET(ssl->arrays->psk_key, 0, MAX_PSK_KEY_LEN);
    }
#endif

    ssl->keys.encryptionOn = 1;
    ssl->options.serverState = SERVER_HELLO_COMPLETE;
}
else {
    ssl->options.tls1_3 = 1;
    ssl->options.serverState = SERVER_HELLO_RETRY_REQUEST_COMPLETE;

    ret = RestartHandshakeHash(ssl);
}

---------------------------------------------------------

Step-by-step explanation:
1. The patch first looks for a valid PSK extension (if compiled with PSK support) and then for the key share extension (when HAVE_KEY_SHARE is defined).  
2. If neither a chosen PSK nor a key share extension is found, the handshake is immediately aborted by returning an error instead of proceeding with default (predictable) IKM values.  
3. When one of the required extensions is correctly provided, the relevant processing (such as SetupPskKey) is performed and the handshake continues normally.

This repair prevents a malicious server from forcing the client into a situation where it uses a predictable IKM value for deriving session keys.
