The original code checked whether the supplied nonce length (arg) was within a range (greater than 0 and less than or equal to CHACHA_CTR_SIZE). This range check allowed for nonce lengths other than the specified 12 bytes for ChaCha20-Poly1305, potentially up to 16 bytes. OpenSSL would then use only the last 12 bytes of any longer nonce, which could lead to scenarios where the application might believe it was using a unique nonce (by modifying the unused part), but in reality, the critical 12-byte portion could repeat. This nonce reuse would compromise the security guarantees provided by the AEAD cipher.

The repair replaces the range check with a strict equality check (if (arg != 12)). By forcing the nonce length to be exactly 12 bytes, we ensure adherence to the RFC 7539 standard by guaranteeing that the nonce conforms to the proper 96-bit (12-byte) size. This prevents any ambiguity or misuse which could lead to nonce reuse, ensuring the proper functioning of ChaCha20-Poly1305.

The update fixes the vulnerability by eliminating support for variable nonce lengths, thereby avoiding accidental reuse of significant nonce bits. Only a nonce length of exactly 12 bytes will be accepted; any deviation from that will result in an immediate failure, thus enforcing the correct and secure use of the encryption function.
