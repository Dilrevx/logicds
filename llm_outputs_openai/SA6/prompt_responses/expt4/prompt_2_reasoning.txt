By switching to CHACHA20_POLY1305_MAX_IVLEN, the code now ensures that the nonce length is validated against the appropriate constant that represents the maximum allowed IV length for ChaCha20-Poly1305. This is crucial because the ChaCha20-Poly1305 algorithm uses only the last 12 bytes of any nonce provided if it is longer than 12 bytes. Allowing a larger nonce length could mislead developers into mistakenly thinking that modifying the unused leading bytes will generate a unique nonce, which could lead to nonce reuse— a serious security flaw that compromises both the confidentiality and integrity of the encrypted message.
