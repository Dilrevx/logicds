Since only the final 12 bytes are used by ChaCha20-Poly1305, an application that “changes the leading bytes” in a nonce longer than 12 bytes may inadvertently reuse the effective nonce, risking severe confidentiality and integrity issues. To repair this, the code should enforce that the nonce length is exactly 12 bytes. For example, if CHACHA_NONCE_SIZE is defined as 12, you can change:

  if (arg <= 0 || arg > CHACHA_CTR_SIZE) {
    return 0;
  }

to

  if (arg != CHACHA_NONCE_SIZE) {
    return 0;
  }

This change disallows any nonce length other than exactly 12 bytes, ensuring that each encryption operation uses a unique and valid nonce as required by the cipher specification.
