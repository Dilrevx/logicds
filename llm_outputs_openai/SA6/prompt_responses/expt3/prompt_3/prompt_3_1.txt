The vulnerability arises because OpenSSL’s ChaCha20-Poly1305 implementation permits nonce lengths up to 16 bytes. Although only the last 12 bytes are used, an application might erroneously believe that modifying the leading bytes produces a new nonce, which can lead to nonce reuse and jeopardize security. The fix is to enforce that the nonce length must be exactly 12 bytes, as specified in RFC 7539.

Below is the repaired code snippet:

--------------------------------------------------
/* Enforce a strict nonce length of 12 bytes for ChaCha20-Poly1305 */
if (arg != 12) {
    return 0;  // nonce length invalid
}
--------------------------------------------------

By replacing the original condition (which allowed arg values from 1 up to CHACHA_CTR_SIZE) with a strict equality check, we ensure that only nonce values of the required 12 bytes are accepted and used, mitigating the possibility of nonce reuse.
