Explanation:
-------------
In the original code, when the received message’s type was not SSL3_MT_CERTIFICATE_VERIFY, the flag reuse_message was set to 1. This allowed the non‐CertificateVerify message to be “reused” later in the handshake,
opening the door to potential replay or downgrade attacks when a certificate is expected (i.e. when there is a peer and signature algorithms are negotiated).

The repair removes the assignment to reuse_message so that a handshake message that is not a CertificateVerify is never inadvertently flagged as “reusable.” If the cipher suite requires a signature (indicated by (type & EVP_PKT_SIGN)) but the message is not a CertificateVerify, an error alert is sent and the connection is terminated. Otherwise (e.g. for anonymous ciphers), the handshake continues without erroneously reusing the message.
