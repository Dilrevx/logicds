For clients that do not present a certificate, the code behaves as before by reusing the current message and proceeding with the handshake. The key change is that the presence of a client certificate unconditionally mandates the presence of the CertificateVerify message. This change adheres to the intended specification of the protocol, ensuring that any client with a certificate also proves possession of the private key associated with that certificate by properly signing the handshake message.

By eliminating the conditional check on the signing flag and always raising an error when a client certificate is present but the CertificateVerify message is missing, the repair guarantees that all clients authenticate correctly.
