The vulnerability was caused by inadvertently using the certificate's subject name rather than its issuer when retrieving the CRL (Certificate Revocation List). This meant that the code was only partially checking revocation status. Specifically, valid revoked certificates could potentially bypass CRL checks because the lookup didn't target the issuer's CRL entry.

In our repair, the critical change was to replace the incorrect parameter (subject) with the correct one (issuer) in the functions used to retrieve CRL entries. In OpenSSL, these functions need to be provided with the appropriate identifier so that CRL entries corresponding to the issuer (who signs the CRL) are accurately found and used in the validation process.

For OpenSSL versions 1.1.0 and above (as well as in the intermediate versions between 1.0.0 and 1.1.0), the code originally used "subject" as an argument for both the new and old APIs. By switching "subject" to "issuer", the code now properly instructs the CRL retrieval functions (whether using X509_STORE_CTX_get1_crls or X509_STORE_get1_crls) to search using the certificate issuer’s details. This ensures that the CRL entry that potentially contains revocation information is appropriately captured and applied during TLS verification.

The repair, therefore, addresses two key issues:
1. It ensures that the lookup for CRLs is aligned with the intended use of these APIs, which expect an issuer identifier when attempting to retrieve CRL data that would indicate whether a certificate has been revoked.
2. It tightens the security of the TLS validation logic by verifying the correct CRL entry, preventing a scenario where a revoked certificate might be mistakenly trusted.

For older OpenSSL versions (before 1.0.0), the behavior remains unchanged, serving as a reminder that it is the user’s responsibility to upgrade the underlying library since those versions may lack the proper API support or expected behavior for secure CRL verification.

By correctly leveraging the issuer instead of the subject in the CRL lookup, the patch eliminates the flaw that could allow connections to proceed with a revoked certificate, thereby enhancing the overall security of the TLS connection.
