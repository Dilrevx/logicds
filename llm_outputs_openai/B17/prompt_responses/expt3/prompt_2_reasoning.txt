The repair replaces the use of the subject identifier with the issuer identifier when retrieving CRLs during TLS verification. In the original code, both OpenSSL version conditions used the subject for the CRL lookup. However, this is problematic because a certificate should be checked against the issuer’s CRL, not just a CRL associated with the certificate’s own subject. This oversight can result in a revoked certificate being accepted if its issuer’s CRL, which actually contains the revocation entry for that certificate, isn’t checked.

To fix the vulnerability, the repair makes the following change in both OpenSSL versions 1.1.0 and higher, and 1.0.0 to 1.1.0:

• It shifts from passing “subject” to using “issuer” as the parameter in the CRL retrieval functions (X509_STORE_CTX_get1_crls and X509_STORE_get1_crls). This is critical as the issuer field is where the relevant CRL information resides—a certificate’s revocation status is determined by the CRL issued by the certificate’s issuer.

By making this change, the repaired snippet ensures that the CRL lookup accurately targets the issuer’s CRL, thereby verifying that the certificate has not been revoked. Without this fix, a revoked certificate could potentially be validated because the CRL lookup would miss the necessary issuer-specific revocation list.

The repair retains the original structure that handles different OpenSSL versions, ensuring backward compatibility. For versions of OpenSSL prior to 1.0.0, the code still sets crls to NULL with a note that upgrading is needed. This prevents any unintended side effects in environments using outdated libraries.

In summary, here’s how the repair fixes the vulnerability:
1. It identifies that comparing the certificate’s subject against the CRL might not catch a certificate whose revocation is determined by its issuer, effectively allowing a revoked certificate to pass.
2. It replaces the incorrect parameter “subject” with the correct parameter “issuer” in the functions that get CRLs.
3. This adjustment ensures that the CRL lookup now matches the proper field—using the issuer for validation—thereby correctly recognizing and preventing the use of revoked certificates.
4. The repair maintains compatibility with different OpenSSL versions, ensuring that environments with newer libraries benefit from enhanced security while clearly urging upgrades for older libraries.

Overall, by using the issuer when checking CRLs, the repaired code aligns with the intended validation process, effectively mitigating the vulnerability that could allow revoked certificates to be mistakenly accepted in a TLS connection.
