Below is one example of how you might fix the bug. In this vulnerability the library code was mistakenly “looking up” CRLs twice using the wrong field (both times passing the certificate’s subject name) when one lookup should be done on the certificate’s subject and a second lookup on its issuer. In other words, a CRL is typically tied to its issuer, so if you query only by “subject” you can miss a CRL that would properly be found via the issuer name. One way to repair the code is to perform two lookups—one using the subject‐name and one using the issuer‐name—and then combine the resulting CRL lists before continuing the verification. (It is also important to ensure that duplicates are removed.) 

For example, suppose that in the calling code the certificate to be checked is available (for example in a variable named “cert”) and that its subject and issuer names are available. Then a sample repair might look like this:

---------------------------------------------------------------
/* Assume that “cert” is the certificate being verified. */
X509_NAME *subject = X509_get_subject_name(cert);
X509_NAME *issuer  = X509_get_issuer_name(cert);
STACK_OF(X509_CRL) *crls_subject = NULL;
STACK_OF(X509_CRL) *crls_issuer  = NULL;
STACK_OF(X509_CRL) *crls = NULL;

#if OPENSSL_VERSION_NUMBER >= 0x10100000L && !defined(HAVE_LIBRESSL)
    /* For OpenSSL 1.1.x and later */
    crls_subject = X509_STORE_CTX_get1_crls(store_ctx, subject);
    crls_issuer  = X509_STORE_CTX_get1_crls(store_ctx, issuer);
#elif OPENSSL_VERSION_NUMBER >= 0x10000000L && !defined(HAVE_LIBRESSL)
    /* For OpenSSL 1.0.x */
    crls_subject = X509_STORE_get1_crls(store_ctx, subject);
    crls_issuer  = X509_STORE_get1_crls(store_ctx, issuer);
#else
    /* Your OpenSSL is before 1.0.0.  You really need to upgrade. */
    crls_subject = NULL;
    crls_issuer  = NULL;
#endif

/* A helper function that “merges” the two lists (removing duplicates)
   is assumed. You can implement this function as needed; the basic idea is
   to create a new stack, push in all CRLs from crls_subject and then add each
   CRL from crls_issuer that isn’t already present. */
crls = combine_crl_stacks(crls_subject, crls_issuer);

/* Free the temporary stacks (the individual CRL pointers are now owned in “crls”) */
if (crls_subject)
    sk_X509_CRL_pop_free(crls_subject, X509_CRL_free);
if (crls_issuer)
    sk_X509_CRL_pop_free(crls_issuer, X509_CRL_free);

/* Continue with the CRL checking logic using “crls” */
---------------------------------------------------------------

In this revised code the CRL lookup uses the proper fields—first by querying using the certificate subject and then again using the certificate issuer. The results are merged so that the verification process will include any CRL that may revoke the certificate. (Be sure to implement combine_crl_stacks() or equivalent merging logic to avoid duplicate entries.) 

This repair ensures that valid CRLs are not missed and that a revoked certificate will be properly detected.
