In the earlier version, wherever the CRLs were retrieved through calls to either the newer X509_STORE_CTX_get1_crls function or the older X509_STORE_get1_crls function (depending on the version of OpenSSL), the code passed the subject parameter. Upon reviewing the vulnerability description, it was determined that the correct approach should involve using the issuer of the certificate, as CRLs are published by the issuing authority (the issuer) and not by the subject.

The next step consisted of modifying the retrieval function call to substitute the subject with the issuer. This change is significant because it ensures that the CRL lookup accurately reflects the relationship between the certificate and its issuing authority. CRLs contain entries that are keyed by issuer information, and by directing the lookup to use the issuer, the repair ensures that the system examines the proper set of CRL entries. This update corrects the semantic error where the code was effectively checking the wrong field, hence fixing the security flaw.

Following this identification and substitution, the code was updated in both conditional compilation branches that apply to different versions of OpenSSL. For versions 1.1.0 and above, the call to the function responsible for retrieving the CRLs now uses the issuer, and similarly, for versions down to 1.0.0 (but not below, as older versions are no longer supported), the same adjustment was made. This careful update guarantees that the fix is consistently applied across different versions of the library, maintaining backwards compatibility and covering as many cases as possible.

This emphasizes the importance of maintaining up-to-date software to prevent vulnerabilities that might exist in older implementations.

By redirecting the CRL lookup from the certificate subject to the issuer, the repair successfully eliminates the loophole that could allow revoked certificates to bypass proper revocation checks. This method ensures that the CRL is correctly utilized, providing proper validation against revoked certificates, and thus upholding the intended security guarantees.
