Below is one example of a repair that forces an active close on the affected socket before proceeding with detachment. In many cases CLOSE_WAIT is caused because the server never explicitly shuts down its own write‐end (i.e. never sends its FIN). In this fix we call shutdown() and close() on the socket to force closure so that resources are released rather than waiting indefinitely for the async event to finish. (Depending on your overall architecture you may wish to move this active close into a common socket‐shutdown routine.) 

<repair>
	sock = handle->sock;

	/* 
	 * Force an active close to prevent the connection from remaining 
	 * in CLOSE_WAIT indefinitely. This ensures that the local side sends a FIN.
	 */
	if (sock->fd >= 0) {
		(void) shutdown(sock->fd, SHUT_RDWR);
		(void) close(sock->fd);
		sock->fd = -1;
	}

	if (sock->tid == isc_nm_tid()) {
		nmhandle_detach_cb(&handle FLARG_PASS);
	} else {
		isc__netievent_detach_t *event =
			isc__nm_get_netievent_detach(sock->mgr, sock);
		/*
		 * we are using implicit "attach" as the last reference
		 * need to be destroyed explicitly in the async callback
		 */
		event->handle = handle;
		FLARG_IEVENT_PASS(event);
		isc__nm_enqueue_ievent(&sock->mgr->workers[sock->tid],
				       (isc__netievent_t *)event);
	}
</repair>

This change actively shuts down the socket (with shutdown() followed by close()) so that even if a malicious TCP stream causes premature termination of the connection on the client’s side, BIND will not be left with a lingering CLOSE_WAIT—and the detached callback can finish cleaning up the reference.
