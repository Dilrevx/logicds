In the problematic code the detach is deferred via an asynchronous event (when the socket’s owner thread isn’t the current thread), which in some circumstances can delay the final close() on the underlying socket. That leaves the TCP connection in CLOSE_WAIT for an arbitrarily long time. The fix is to force the socket’s shutdown (i.e. tell the kernel that no more I/O is desired) immediately—even if the final cleanup is being done asynchronously—so that the kernel isn’t waiting on the application to finally close the descriptor. One repair is to call shutdown() (or the equivalent in your code‐base) before queuing the asynchronous detach if needed.

For example, assuming that sock->fd holds the file descriptor and that shutdown(sock->fd, SHUT_RDWR) does the job, you can modify the snippet as follows:

--------------------------------------------------
  sock = handle->sock;
  /* Force an immediate shutdown so the connection no longer stays in CLOSE_WAIT.
     This covers both immediate and asynchronous detach cases. */
  shutdown(sock->fd, SHUT_RDWR);
  
  if (sock->tid == isc_nm_tid()) {
    nmhandle_detach_cb(&handle FLARG_PASS);
  } else {
    isc__netievent_detach_t *event =
      isc__nm_get_netievent_detach(sock->mgr, sock);
    /*
     * we are using implicit "attach" as the last reference
     * need to be destroyed explicitly in the async callback
     */
    event->handle = handle;
    FLARG_IEVENT_PASS(event);
    isc__nm_enqueue_ievent(&sock->mgr->workers[sock->tid],
      (isc__netievent_t *)event);
  }
--------------------------------------------------

1. Immediately after obtaining the socket (handle->sock) the code calls shutdown(sock->fd, SHUT_RDWR). This prevents any further reading or writing on the socket and causes the kernel’s TCP stack to close the connection actively. That ensures that even if the detach callback is eventually called asynchronously, the connection will not linger in CLOSE_WAIT.

2. The rest of the logic remains the same, ensuring that the detachment callback is still executed in the proper thread context. (In the synchronous case the callback is invoked immediately; in the asynchronous case the event is enqueued on the proper worker thread.)

Note: Be sure that the socket file descriptor (sock->fd) exists and is valid; if needed, add any necessary checks or synchronization. Also, if your environment uses a different API to force closure of the underlying connection, replace shutdown() with the appropriate function.

This repair prevents malicious TCP streams from leaving the connection in CLOSE_WAIT for an indefinite period, as the underlying socket is forced closed immediately.
