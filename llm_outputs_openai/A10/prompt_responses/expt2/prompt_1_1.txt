Below is one acceptable repair. In the buggy code, when both algorithm parameters have zero length the memcmp is skipped, so a “NULL‐parameters” entry (perhaps with p == NULL) and an “empty array” (with p != NULL) are treated as equal. To fix this we explicitly check that if the length is zero then the pointer values must match – otherwise the parameters are considered different. In other words, we require an exact match of the algorithm parameters even when the length is zero.

<repair>
    if( crt->sig_oid.len != sig_oid2.len ||
        memcmp( crt->sig_oid.p, sig_oid2.p, crt->sig_oid.len ) != 0 ||
        sig_params1.len != sig_params2.len ||
        ( sig_params1.len == 0 ? ( sig_params1.p != sig_params2.p ) :
          memcmp( sig_params1.p, sig_params2.p, sig_params1.len ) != 0 ) )
    {
        mbedtls_x509_crt_free( crt );
        return( MBEDTLS_ERR_X509_SIG_MISMATCH );
    }
</repair>

This change ensures that if one algorithm parameters structure is “NULL” (pointer is NULL) while the other is an empty (but non‐NULL) array – or vice versa – the algorithm parameters are not considered a match. Any repair that forces an exact match of the algorithm parameters (not just by length) is acceptable.
