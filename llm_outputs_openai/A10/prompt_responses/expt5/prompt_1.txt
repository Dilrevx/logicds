Below is one example of how you might “repair” the code by replacing the standard memcmp calls with a constant‐time comparator. (An attacker who can distinguish the timing of the signature parameter comparison might otherwise be able to obtain information on a signature’s value.) In this example a helper function constant_time_memcmp() is defined and then used in place of memcmp.

<repair>
/* Constant‐time memory comparison: returns 0 if equal, nonzero otherwise */
static int constant_time_memcmp( const unsigned char *a, const unsigned char *b, size_t n )
{
    unsigned char diff = 0;
    size_t i;
    for( i = 0; i < n; i++ )
    {
        diff |= a[i] ^ b[i];
    }
    return diff;
}

/* Use constant‐time comparisons for signature object identifiers and parameters */
if( crt->sig_oid.len != sig_oid2.len ||
    constant_time_memcmp( crt->sig_oid.p, sig_oid2.p, crt->sig_oid.len ) != 0 ||
    sig_params1.len != sig_params2.len ||
    ( sig_params1.len != 0 &&
      constant_time_memcmp( sig_params1.p, sig_params2.p, sig_params1.len ) != 0 ) )
{
    mbedtls_x509_crt_free( crt );
    return( MBEDTLS_ERR_X509_SIG_MISMATCH );
}
</repair>

In this repair the memcmp calls have been replaced with constant_time_memcmp so that the timing of the comparison does not leak information about the values being compared. This fixes the vulnerability related to timing side-channel leaks.
