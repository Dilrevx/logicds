Below is one way to fix the vulnerability. In the buggy code the plain NAS message branch simply accepts plain messages—even if a NAS security context has been activated. According to the spec (and the vulnerability description) plain identity requests must be rejected once security is activated. In the fixed code we add a check in the plain NAS branch to reject plain messages if the security context is active.

Below is an example fix. (Note: the code assumes that a flag or function such as is_security_context_active() is available. In your actual code, substitute this with the appropriate mechanism to detect whether NAS security has been activated.)

─────────────────────────────────────────────────────────────
// Fixed Code Snippet

// Assume that "security_context_active" is a boolean global or part of
// the NAS context. Alternatively, you might have a function like:
bool is_security_context_active() {
    // Return true if NAS security is activated.
    // (Implement using your project’s context/state flag.)
    return nas_security_context_active;  
}

switch (nas_msg.hdr.security_header_type) {
    case commons.Nas5gsHdr.security_header_type_opts.plain_5gs_nas_message:
        // NEW: reject plain NAS messages if security has been activated.
        if (is_security_context_active()) {
            logger.error("Rejecting plain NAS message after security activation");
            return SRSRAN_ERROR;
        }
        break;

    case commons.Nas5gsHdr.security_header_type_opts.integrity_protected:
        if (!integrity_check(pdu.get())) {
            logger.error("Not handling NAS message with integrity check error");
            return SRSRAN_ERROR;
        }
        break;

    case commons.Nas5gsHdr.security_header_type_opts.integrity_protected_and_ciphered:
        if (!integrity_check(pdu.get())) {
            logger.error("Not handling NAS message with integrity check error");
            return SRSRAN_ERROR;
        } else {
            cipher_decrypt(pdu.get());
        }
        break;

    case commons.Nas5gsHdr.security_header_type_opts.integrity_protected_with_new_5G_nas_context:
        break;

    case commons.Nas5gsHdr.security_header_type_opts.integrity_protected_and_ciphered_with_new_5G_nas_context:
        return SRSRAN_ERROR;

    default:
        logger.error("Not handling NAS message with unknown security header");
        break;
}
─────────────────────────────────────────────────────────────

Explanation:

• In the plain NAS message branch, we now check whether the NAS security context is activated.
• If security is active, we log an error and return an error code.
• Other branches remain unchanged.

Adjust the mechanism for checking security activation (for example, the function is_security_context_active() or a flag variable) as fits your design. This ensures that after NAS security activation the UE does not inadvertently accept plain (unsigned, unencrypted) identity requests.
