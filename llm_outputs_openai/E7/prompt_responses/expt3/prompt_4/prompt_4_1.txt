Below is one example fix. In the vulnerable code the plaintext NAS interface was allowing too many message types. The specification only permits plain messages for:
 • EMM Information,
 • EMM Status,
 • Detach Request, and
 • Attach (or Service) Reject when the emm_cause value equals 25.
Any other plain NAS message must be rejected. In the fix below only these messages are accepted, and in the case of Attach/Service Reject the emm_cause field is checked before accepting it.

For example, if the variable “emm_cause” has been parsed already, the fix can be applied as follows:

----------------------------------------------------------------
  if (sec_hdr_type == LIBLTE_MME_SECURITY_HDR_TYPE_PLAIN_NAS) {
    switch (msg_type) {
      // Allowed in plaintext, by spec.
      case LIBLTE_MME_MSG_TYPE_EMM_INFORMATION:
      case LIBLTE_MME_MSG_TYPE_EMM_STATUS:
      case LIBLTE_MME_MSG_TYPE_DETACH_REQUEST:
        break;

      // Allowed plaintext only if emm_cause equals 25.
      case LIBLTE_MME_MSG_TYPE_ATTACH_REJECT:
      case LIBLTE_MME_MSG_TYPE_SERVICE_REJECT:
        if (emm_cause == 25) {
          break;
        } else {
          logger.error("Refusing plain NAS message MSG_TYPE=%02X with invalid emm_cause %d (expected 25).", 
                       msg_type, emm_cause);
          return;
        }

      default:
        logger.error("Not handling NAS message MSG_TYPE=%02X with SEC_HDR_TYPE=%02X without integrity protection!",
                     msg_type,
                     sec_hdr_type);
        return;
    }
  }
----------------------------------------------------------------

Explanation:
1. The switch-case now only accepts EMM Information, EMM Status, and Detach Request as plaintext.
2. For Attach/Service Reject the code further validates that the emm_cause equals 25.
3. All other messages (including ones such as Identity Request, Authentication Request/Reject, etc.) are rejected unless they have additional integrity protection.

This patch prevents the attacker from exploiting unintended plaintext processing of messages that should be protected.
