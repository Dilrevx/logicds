Below is one example of a repair that adds the missing check. In the original code only the transaction ID (and optionally a hash) are compared. In the fixed version we also verify that the reply comes from the same destination address and port as originally queried. (In this example we assume that the incoming reply’s sender information is available in a variable called replyAddr of type InetSocketAddress.) Here’s the repaired snippet:

-------------------------------------------------------
            if (f.sentto != null
                    && replyAddr.equals(f.sentto)  // verify address and port match
                    && f.new_id == id
                    && (hash == null || Arrays.equals(hash, f.hash))) {
                return f;
            }
-------------------------------------------------------

Explanation:
1. replyAddr.equals(f.sentto) ensures that both the address and port of the reply’s sender exactly match the expected destination of the forwarded query.
2. The remaining checks (for new_id and hash) are left intact.

This repair makes sure that all attributes required (including the source address/port) match the original query as specified by RFC5452, thereby mitigating the cache poisoning vulnerability.
