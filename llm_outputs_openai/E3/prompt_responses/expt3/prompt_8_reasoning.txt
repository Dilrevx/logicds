The repair introduces an additional integrity check for two specific NAS message types—registration_accept and configuration_update_command—that are prone to bypassing the integrity check when their headers are plain. In each modified case, before calling the respective handler, the code first checks if the header’s value is equal to 2 (the expected value indicating the message has passed the integrity check). If the condition is met, the handler for that message type is invoked, allowing normal processing. If not, the code logs an error stating that the integrity check failed for that message and does not call the handler.

By enforcing this check, the patched code prevents processing of messages that do not meet the integrity conditions, ensuring that only messages with a properly validated header are accepted. Other message types continue to be processed as before because they aren’t subject to the specific vulnerability discussed. This focused intervention reinforces message integrity by verifying the header first, thereby mitigating the risk that plain header NAS messages could bypass the intended integrity controls.
