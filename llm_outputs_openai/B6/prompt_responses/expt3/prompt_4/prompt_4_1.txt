Below is one example of a repair. In the original code the certificate’s subject alternative name (SAN) list is scanned and any SAN entry is used, regardless of its intended meaning. An attacker might, for example, get an IP‐address–typed SAN that happens to match the expected “CN” string. A safe fix is to check that the SAN entry is of the proper type (e.g. a DNS name if that is what you’re expecting) before attempting the match.

One way to fix the bug is as follows. (In this example we assume that the expected “cn” is a domain name so that only SAN entries of type MBEDTLS_X509_SAN_DNS_NAME are acceptable. Adjust accordingly if your application supports also IP literals.)

Patched code:

------------------------------------------------------------
    if( crt->ext_types & MBEDTLS_X509_EXT_SUBJECT_ALT_NAME )
    {
        // Only compare entries that are of the expected type (e.g. DNS name)
        for( cur = &crt->subject_alt_names; cur != NULL; cur = cur->next )
        {
            // Check that the subjectAltName entry is a DNS name before matching
            if( cur->type != MBEDTLS_X509_SAN_DNS_NAME )
                continue;
               
            if( x509_crt_check_cn( &cur->buf, cn, cn_len ) == 0 )
                break;
        }

        if( cur == NULL )
            *flags |= MBEDTLS_X509_BADCERT_CN_MISMATCH;
    }
    else
    {
        // Fallback: check for a matching common name in the subject name
        for( name = &crt->subject; name != NULL; name = name->next )
        {
            // Only consider Common Name (CN) entries
            if( MBEDTLS_OID_CMP( MBEDTLS_OID_AT_CN, &name->oid ) == 0 &&
                x509_crt_check_cn( &name->val, cn, cn_len ) == 0 )
            {
                break;
            }
        }

        if( name == NULL )
            *flags |= MBEDTLS_X509_BADCERT_CN_MISMATCH;
    }
------------------------------------------------------------

Explanation:

1. In the fixed SAN-check branch, before comparing the expected name to the value of a SAN list member, the code first checks whether the type of the entry (cur->type) is MBEDTLS_X509_SAN_DNS_NAME. This makes sure that a certificate issuer cannot “mix” a SAN of a different type (e.g. an IP address) so that it erroneously satisfies the DNS name match.

2. If a matching SAN entry is found the loop stops, otherwise the appropriate flag is set.

3. The fallback (where no SAN is present) still checks the subject’s common name as before.

This change properly restricts which SAN entries may be used for a name match, fixing the vulnerability described.
