The original code skipped the leaf (first) certificate by starting the loop at index 1. This allowed a certificate at position 0 to bypass the check for an invalid certificate policy extension. Due to the vulnerability described, if an attacker could craft a leaf certificate with invalid certificate policies, those policies would be ignored during the validation process. In other words, the attacker could circumvent policy checks by exploiting the fact that the leaf certificate was never checked for EXFLAG_INVALID_POLICY.

In the repair, the loop has been modified to start at index 0 instead of index 1, ensuring that every certificate in the chain—from the leaf certificate to the higher-level certificates—is examined. This fix addresses the vulnerability by guaranteeing that even if the leaf certificate asserts invalid policies, those policies will be detected. Specifically, the CB_FAIL_IF macro will trigger a failure if any certificate in the chain (including the leaf) has the EXFLAG_INVALID_POLICY flag set, resulting in the error X509_V_ERR_INVALID_POLICY_EXTENSION being reported.

By checking the entire chain, the repair ensures a consistent and robust verification process that complies with the specification which expects the certificate policies extension to be processed correctly. The malicious CA can no longer rely on the omission of the leaf certificate to bypass certificate policy checks. This significantly mitigates the vulnerability, as it forces the validation procedure to reject certificates that deviate from the expected policy structure at any point in the chain.

In summary, the repair ensures that the integrity of the entire certificate chain is validated. By starting the iteration at index 0, the fix ensures that the leaf certificate, which could potentially contain dangerous or manipulated policy information, is properly scrutinized. This change directly addresses the security flaw where invalid certificate policies in the leaf certificate were being ignored, thereby maintaining a stricter adherence to policy checking rules and improving the overall security of the certificate verification process.
