The problem is that the code only checks certificates starting at index 1 in the chain, skipping the leaf certificate at index 0. With the current loop, a malicious CA can deliberately include invalid certificate policies in the leaf certificate – which is the one that gets verified against the user‐supplied options – and avoid triggering any callback or error. In short, the vulnerability is that invalid policies are silently ignored in the leaf (first) certificate.

A repaired version fixes this by iterating over the full chain (including the leaf certificate) so that any certificate that has invalid policy extensions will be caught. For example:

--------------------------------------------------------
if (ret == X509_PCY_TREE_INVALID) {
    int i;
    /* Locate certificates with bad extensions and notify callback.
       Start at 0 to include the leaf certificate in the checks. */
    for (i = 0; i < sk_X509_num(ctx->chain); i++) {
        X509 *x = sk_X509_value(ctx->chain, i);
        CB_FAIL_IF((x->ex_flags & EXFLAG_INVALID_POLICY) != 0,
                   ctx, x, i, X509_V_ERR_INVALID_POLICY_EXTENSION);
    }
    return 1;
}
--------------------------------------------------------

Explanation:
• The loop now starts at i = 0 rather than i = 1. This ensures that the leaf certificate is not skipped.
• With this check in place the verification process will trigger a callback (or error) if any certificate in the chain—including the leaf—is marked with the EXFLAG_INVALID_POLICY flag, mitigating the risk of policy bypass.

This change addresses the vulnerability by ensuring that invalid certificate policies are not silently ignored due to an incomplete check of the certificate chain.
