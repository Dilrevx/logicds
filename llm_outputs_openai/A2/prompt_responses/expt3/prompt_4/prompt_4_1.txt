Below is one way to address the vulnerability:

─────────────────────────────────────────────  
Bug Explanation:
─────────────────────────────────────────────  
The current code intentionally skips the leaf certificate (using i = 1) when checking for invalid policy extensions. This is problematic because the vulnerability description indicates that if a malicious CA asserts invalid certificate policies in the leaf certificate, those invalid policies are not caught—allowing the attacker to circumvent certificate policy checks.

─────────────────────────────────────────────  
Repair:
─────────────────────────────────────────────  
To fix the issue, make sure that the loop verifies every certificate in the chain—including the leaf certificate. One fix is to start the loop at index 0 instead of 1. For example:

------------------- Begin Fixed Code -------------------
    if (ret == X509_PCY_TREE_INVALID) {
        int i;
    
        /* Locate certificates with bad extensions, including the leaf certificate,
         * and notify callback. */
        for (i = 0; i < sk_X509_num(ctx->chain); i++) {
            X509 *x = sk_X509_value(ctx->chain, i);
    
            CB_FAIL_IF((x->ex_flags & EXFLAG_INVALID_POLICY) != 0,
                       ctx, x, i, X509_V_ERR_INVALID_POLICY_EXTENSION);
        }
        return 1;
    }
------------------- End Fixed Code -------------------

─────────────────────────────────────────────  
Explanation of the Fix:
─────────────────────────────────────────────  
• Changing the loop to start at index 0 ensures that all certificates—including the leaf certificate—are checked for the EXFLAG_INVALID_POLICY flag.  
• This prevents a malicious CA from embedding invalid policies in the leaf certificate to bypass proper policy validation.

Using this repair, the vulnerability is mitigated by ensuring the leaf certificate's extensions are checked just like those in the rest of the chain.
