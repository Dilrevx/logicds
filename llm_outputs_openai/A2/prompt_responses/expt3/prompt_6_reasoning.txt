The repair addresses a logical oversight in the loop that processes the certificate chain. Originally, the loop started at index 1, which means the very first certificate in the chain (at index 0) was never examined. If that first certificate had an invalid policy extension, it would not trigger the callback, leaving a potential vulnerability undetected.

By changing the starting index from 1 to 0, the repaired code now iterates through the entire certificate chain, ensuring that every certificate—including the very first one—is checked for the invalid policy extension flag. This comprehensive check helps guarantee that any certificate with a flawed extension is correctly identified and reported via the callback.

Thus, the vulnerability is fixed because the error detection mechanism now consistently examines all certificates. This prevents scenarios where an attacker might exploit the oversight by placing a certificate with a bad extension at the beginning of the chain, which previously would have been overlooked due to the loop starting at the wrong index.
