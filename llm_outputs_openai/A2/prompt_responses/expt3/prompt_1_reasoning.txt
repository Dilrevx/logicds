The fix changes the loop's starting index from 1 to 0 so that every certificate in the chain—including the leaf certificate—is examined for invalid policy extensions. In the original code, the loop began at index 1, skipping the leaf certificate at index 0. This omission was dangerous because if a malicious CA placed an invalid certificate policy specifically in the leaf certificate, that invalid policy could be ignored. Consequently, the attack could bypass stricter checks and undermine the certificate verification process.

By iterating from index 0 (i.e., checking all certificates in the chain), the repair ensures that no certificate, including the leaf certificate, escapes scrutiny. Any certificate with the EXFLAG_INVALID_POLICY flag will properly trigger the failure callback. This approach closes the vulnerability by removing the opportunity for a malicious actor to take advantage of the initial oversight.

To summarize:
1. The repair modifies the loop to start with i = 0 instead of 1.
2. The leaf certificate is no longer excluded from the check.
3. Invalid policy extensions in any certificate in the chain now reliably trigger the designated error callback.
4. This prevents attackers from bypassing certificate policy checks by exploiting unchecked fields in the leaf certificate, thereby reinforcing the overall security of the certificate verification process.
