Previously, the code would have returned MOSQ_ERR_PLUGIN_DEFER in such a scenario. By returning MOSQ_ERR_ACL_DENIED instead, the fix ensures that an explicitly configured but empty ACL file does not inadvertently open up access. This prevents an administrator’s explicit intention (even if it results in denying all operations) from being undermined by a fallback to permissive behavior.

The remainder of the function still processes any ACLs that are defined in the ACL file or provided via patterns. This is a safety check to prevent bypasses using wildcard characters in these identifiers. By ensuring that both concrete ACL entries and pattern ACLs are processed properly, the function maintains correct, intended behavior in all scenarios.

In summary, the repair fixes the vulnerability by correctly enforcing restrictions when an ACL file is empty.
