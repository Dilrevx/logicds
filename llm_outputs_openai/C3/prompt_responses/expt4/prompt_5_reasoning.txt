The repair changes the behavior when an ACL file has been configured but effectively contains no valid ACL entries (because it’s empty or contains only comments/blank lines). In the original code, if no ACL entries were set (i.e. both acl_list and acl_patterns are NULL), the function returned MOSQ_ERR_PLUGIN_DEFER. This return value defers the access decision to the plugin mechanism, which by default allowed access. This unintentionally resulted in a “default allow” policy even when an ACL file was present but empty.

In the repaired code, we modify that behavior. The early condition now checks whether both acl_list and acl_patterns are NULL, and if they are, the function returns MOSQ_ERR_ACL_DENIED instead of deferring. This change means that when an ACL file is defined but empty (or its entries are only comments or blank lines), the broker explicitly denies access rather than defaulting to allow.
