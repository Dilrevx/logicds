Below is one way to “fix” the vulnerability. In the original code the check

  if (!security_opts->acl_list && !security_opts->acl_patterns) {
    return MOSQ_ERR_PLUGIN_DEFER;
  }

causes an empty ACL file (or one with only comments/whitespace) to be treated as if no ACL was configured at all, so that Mosquitto falls back to its default (allow) policy. To change the behavior so that an empty ACL file means “deny everything”, one fix is to remove the “defer” return and instead return a code that causes the operation to be denied. (In Mosquitto’s plugin API there is generally a constant such as MOSQ_ERR_ACL_DENIED to signal this; if you have defined a different constant or error‐logic in your code base, use that.) 

For example, the patched code might look like this:

  if (!security_opts->acl_list && !security_opts->acl_patterns) {
    /* ACL file was loaded but is empty (or contains only comments/whitespace).
     * Instead of deferring (and therefore allowing access), deny all access.
     */
    return MOSQ_ERR_ACL_DENIED;
  }

This change ensures that if a user configures Mosquitto with an ACL file that turns out to be empty, the broker will deny any access attempts rather than falling back to the default allow policy.

Note:
 • If your code base does not have MOSQ_ERR_ACL_DENIED defined you may need to define it (or use an appropriate alternative error code) so that the plugin’s caller properly interprets this as “access denied.”
 • You may also want to log a warning or error indicating that an empty ACL file was encountered, so that administrators can correct the configuration if the “deny all” behavior is not what was intended.
