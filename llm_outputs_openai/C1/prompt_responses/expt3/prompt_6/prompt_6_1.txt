Below is an example patch (in C) that shows how the certificate verification code is modified. In this example the code distinguishes between having an application‐provided certificate verification callback and not having one. When no callback is provided, the code calls the internal verification function (X509_verify_cert()) and, if its return value is negative, resets it to zero. This prevents a negative value from being propagated up the call stack and avoids causing unexpected SSL errors such as SSL_ERROR_WANT_RETRY_VERIFY.

────────────────────────────────────────────
/* Example code before the patch (buggy): */

int verify_server_cert(SSL_CTX *ctx, X509_STORE *store, X509 *cert)
{
    int ret;

    if (ctx->app_cert_verify_callback != NULL) {
        /* Application has provided its own callback,
           so call it directly. */
        ret = ctx->app_cert_verify_callback(ctx, store, cert);
    } else {
        /* No callback was set.
           Call the internal certificate verification function. */
        ret = X509_verify_cert(cert);
    }
    return ret;
}

────────────────────────────────────────────
/* Patched version to fix the vulnerability:
 *
 * If no application-specific certificate verification callback is provided,
 * then immediately after calling X509_verify_cert(), if the result is negative
 * (indicating an internal error), the negative return value is replaced by 0,
 * ensuring that only a simple verification failure is reported.
 */

int verify_server_cert(SSL_CTX *ctx, X509_STORE *store, X509 *cert)
{
    int ret;

    if (ctx->app_cert_verify_callback != NULL) {
        /* If the application provided its own verification callback,
           use it unchanged */
        ret = ctx->app_cert_verify_callback(ctx, store, cert);
    } else {
        /* No application callback is set. Call the internal verification function */
        ret = X509_verify_cert(cert);

        /* If X509_verify_cert() reports an internal error (negative value),
           reset it to 0 so that it is treated as a plain verification failure.
           This avoids propagating a negative value (and unexpected SSL_ERROR_WANT_RETRY_VERIFY)
           to higher-level functions. */
        if (ret < 0)
            ret = 0;
    }
    return ret;
}

────────────────────────────────────────────
Explanation:

1. When an application-specific certificate verification callback is in place (ctx->app_cert_verify_callback is non-NULL), the code continues to use that callback so that the application can interpret the verification outcome as needed.

2. If no callback is set, the internal function X509_verify_cert() is called. Immediately after the call, the code checks if the return value (ret) is negative. If so, it resets ret to 0. This normalization ensures that the internal error is no longer signaled by a negative value, preventing higher-level SSL functions such as SSL_connect() or SSL_do_handshake() from deriving the unexpected error code (SSL_ERROR_WANT_RETRY_VERIFY).

This patch preserves the intended behavior for application callbacks and ensures that internal certificate verification errors are handled predictably as simple verification failures when no application-supplied callback is installed.
