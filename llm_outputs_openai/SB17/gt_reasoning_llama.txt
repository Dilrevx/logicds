The vulnerability in the tls_verify_crl function arises from an incorrect check when verifying certificate revocation lists (CRLs). Specifically, the function is checking the subject field of a CRL entry twice, instead of checking the subject and issuer fields once each. This oversight prevents some valid CRLs from being considered, allowing clients with revoked certificates to establish a connection to the server.

The root cause of this issue lies in the lines of code responsible for retrieving CRLs from the store context. In the buggy code, the function is called with the subject as the argument, regardless of the OpenSSL version being used. However, to correctly verify CRLs, the function should be called with the issuer as the argument.

The repair addresses this issue by changing the argument passed to the get1_crls function from subject to issuer. This ensures that the function checks the issuer field of the CRL entry, rather than the subject field twice. By doing so, the function can correctly identify and consider all relevant CRLs, preventing clients with revoked certificates from establishing a connection to the server.

The change is applied consistently across different OpenSSL versions, ensuring that the fix is effective regardless of the version being used. By making this simple yet crucial change, the vulnerability is effectively addressed, and the security of the tls_verify_crl function is significantly improved. The corrected code ensures that CRLs are properly verified, and only clients with valid certificates can establish a connection to the server.
