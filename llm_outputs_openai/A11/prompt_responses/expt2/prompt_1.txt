Below is one acceptable repair. The vulnerability arose because the CRL entry was only considered revoked if the local clock had passed its revocation_date. An attacker able to manipulate the system time could force mbedtls_x509_time_is_past() to return false and have a revoked certificate accepted. One proper fix is to remove the reliance on the local clock – if a CRL contains an entry with a matching serial number the certificate should be treated as revoked regardless of any “revocation_date”. That is, we no longer delay revocation‐action until the revocation date is reached.

Below is one repair that replaces the conditional call to mbedtls_x509_time_is_past() with an immediate rejection if the certificate’s serial number is found in the CRL:

<repair>
    if( crt->serial.len == cur->serial.len &&
        memcmp( crt->serial.p, cur->serial.p, crt->serial.len ) == 0 )
    {
        /* Remove dependency on system time: if a matching serial number is found,
           reject the certificate as revoked immediately */
        return( 1 );
    }
</repair>

This repair forces the CRL to be enforced irrespective of the local clock setting, thereby fixing the vulnerability.
