The repair adds an extra conditional check to confirm that the subject alternative name (SAN) being evaluated is of the DNS type. Previously, the code compared the expected common name (CN) against every SAN entry in the certificate, regardless of its type (e.g., IPv4, IPv6, email, etc.). This meant that if an attacker could obtain a certificate with an IP address in the SAN (even though they control that IP address), it might be possible to impersonate a hostname. In other words, any alternative name in the certificate that matched—even if it wasn’t a DNS name—could be used to satisfy the verification.

In the repair, before calling the helper function CommonUtils.x509_crt_check_cn, the code now checks whether the current SAN entry's type (held in cur.tag) equals MBEDTLS_X509_SAN_DNS_NAME. By doing so, the verification process will only consider SAN entries that are explicitly DNS names when comparing them with the expected hostname. This prevents any non-DNS types (such as IP addresses) from being matched against a hostname, thereby eliminating the vulnerability where an attacker might exploit the broader matching logic.

The fixed code snippet essentially reads: “If the current SAN entry is of type DNS and its contents match the expected hostname, then break out of the loop.” This ensures that only valid DNS names are used for hostname validation, aligning the check with the intended logic and standard practices for certificate verification.

Overall, the change enhances the security of the certificate validation process by:
1. Restricting the evaluation to SAN entries that actually correspond to domain names.
2. Preventing potential impersonation scenarios where non-DNS SAN entries improperly satisfy the expected CN match.
3. Following the principle of least privilege by comparing only relevant data elements for the task at hand.

This targeted check helps ensure that the application validates certificates accurately, reducing the risk of man-in-the-middle or impersonation attacks that stem from incorrect SAN type handling.
