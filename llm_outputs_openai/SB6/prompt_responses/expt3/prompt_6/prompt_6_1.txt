Below is an example patch in C that shows how to replace the old “verify‐common-name” code with a new function that explicitly distinguishes the SAN types. In the patched code the certificate’s SAN extension is first checked, and if present only SAN entries of the expected type (for example, DNS names versus IP addresses) are compared against the expected name. In the event that no SAN extension is present the code falls back to checking the certificate’s common name, as before.

Below is the illustrative patched snippet:

------------------------------------------------------------
/* Example patched code for verifying the expected certificate name */
#include "mbedtls/x509_crt.h"
#include "mbedtls/asn1.h"
#include "mbedtls/platform_util.h"
#include <string.h>
#include <stdio.h>

/*
 * expected_type should be one of:
 *    MBEDTLS_X509_SAN_DNS_NAME    (for a domain name)
 *    MBEDTLS_X509_SAN_IP_ADDRESS  (for an IP address)
 *
 * The following function returns 0 on success (match found), or -1 on failure.
 */
int verify_certificate_hostname( const mbedtls_x509_crt *crt,
                                 const char *expected_name,
                                 int expected_type )
{
    const mbedtls_x509_sequence *san_seq = &crt->subject_alt_names;
    int san_present = ( san_seq != NULL && san_seq->buf.len > 0 );
    int match_found = 0;

    /* If the SAN extension is present, use it and ignore the CN.
     * Only compare SAN entries of the expected type. */
    if( san_present )
    {
        const mbedtls_x509_sequence *cur = san_seq;
        while( cur != NULL )
        {
            /*
             * In our ASN.1 parsing of the SubjectAltName extension,
             * we assume that cur->buf.p contains an encoded X509 GeneralName.
             * The first octet indicates the type.
             *
             * For illustration purposes we assume the following:
             *   2 = DNS Name (MBEDTLS_X509_SAN_DNS_NAME)
             *  7 = IP Address (MBEDTLS_X509_SAN_IP_ADDRESS)
             *
             * In a real implementation the dummy parser below would be
             * replaced by the actual parsing routines provided by mbedtls. 
             */
            unsigned char gn_type = cur->buf.p[0];

            /* Only consider entries with the expected type */
            if( gn_type == (unsigned char) expected_type )
            {
                /* Pointer to the name field (skip the type byte) */
                const char *name_ptr = (const char *)( cur->buf.p + 1 );
                size_t name_len = cur->buf.len - 1;

                /* For DNS names compare strings (case-insensitive) */
                if( expected_type == MBEDTLS_X509_SAN_DNS_NAME )
                {
                    /* Ensure the expected name fits into the SAN entry */
                    if( strlen( expected_name ) == name_len &&
                        strncasecmp( expected_name, name_ptr, name_len ) == 0 )
                    {
                        match_found = 1;
                        break;
                    }
                }
                /* For IP addresses perform a binary comparison.
                 * Note: expected_name is expected to be in binary form
                 *       or converted accordingly prior to the call. */
                else if( expected_type == MBEDTLS_X509_SAN_IP_ADDRESS )
                {
                    /* name_len should match the expected IP address length
                     * (4 bytes for IPv4 or 16 bytes for IPv6). */
                    size_t expected_ip_len = ( name_len == 4 || name_len == 16 )
                                                ? name_len : 0;
                    if( expected_ip_len > 0 &&
                        memcmp( expected_name, name_ptr, name_len ) == 0 )
                    {
                        match_found = 1;
                        break;
                    }
                }
            }
            cur = cur->next;
        }

        if( match_found )
            return 0;
        else
        {
            /* SAN extension present but no valid match */
            // Optionally, emit a warning: "Certificate SAN mismatch"
            return -1;
        }
    }
    else
    {
        /* Fall back to checking the Common Name (CN) if no SAN extension exists */
        /* get_common_name() is assumed to extract the CN from crt->subject */
        char cn[256] = {0};
        if( get_common_name( crt, cn, sizeof(cn) ) == 0 )
        {
            if( expected_type == MBEDTLS_X509_SAN_DNS_NAME )
            {
                if( strcasecmp( expected_name, cn ) == 0 )
                    return 0;
            }
            else if( expected_type == MBEDTLS_X509_SAN_IP_ADDRESS )
            {
                /* When no SAN extension exists, the CN is assumed to hold an IP address
                 * in a canonical form. A proper conversion should be applied before comparing;
                 * for brevity, a simple string comparison is shown here. */
                if( strcmp( expected_name, cn ) == 0 )
                    return 0;
            }
        }
    }
    return -1;
}

/*
 * A dummy implementation of get_common_name() which extracts the CN from the certificate subject.
 * The real implementation should correctly parse the subject string.
 */
int get_common_name( const mbedtls_x509_crt *crt, char *cn, size_t cn_size )
{
    /* For illustration, assume that crt->subject contains the CN at a known offset.
     * In practice, this requires proper ASN.1 parsing of crt->subject. */
    if( crt->subject.p != NULL && crt->subject.len < cn_size )
    {
        memcpy( cn, crt->subject.p, crt->subject.len );
        cn[ crt->subject.len ] = '\0';
        return 0;
    }
    return -1;
}

/*
 * In the main certificate verification function, the change is a single line:
 * we now call verify_certificate_hostname() instead of the old function that did not consider
 * the specific type of SAN entries.
 *
 * For example, originally the code might have been:
 *
 *   retval = verify_common_name( crt, expected_name );
 *
 * It is now replaced with:
 *
 *   retval = verify_certificate_hostname( crt, expected_name, MBEDTLS_X509_SAN_DNS_NAME );
 *
 * (or MBEDTLS_X509_SAN_IP_ADDRESS, depending on the context).
 */
------------------------------------------------------------

Explanation of the Patch:

1. The new function verify_certificate_hostname() first checks for the presence of the SAN extension.
2. It iterates over each entry in the SAN list and only compares those entries that match the expected type (DNS name or IP address).
3. For DNS names, a case-insensitive string comparison is performed. For IP addresses, a binary comparison is made (after ensuring that the lengths, such as 4 bytes for IPv4 or 16 bytes for IPv6, match).
4. If a match is found, the function returns 0 (success). If no match is found in the SAN extension, the function falls back to comparing the certificate’s common name (CN), preserving legacy behavior when no SAN extension exists.
5. Finally, in the main certificate verification control flow, a single line is updated to call verify_certificate_hostname() rather than the older, less secure common-name verification function.

This patch thereby ensures that the certificate is only accepted if the expected name (whether a domain name or an IP address) properly corresponds to an entry of the appropriate type in the SAN field, mitigating the vulnerability described.
