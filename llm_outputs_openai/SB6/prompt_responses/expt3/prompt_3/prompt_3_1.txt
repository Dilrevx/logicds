Below is one way to fix the bug. The underlying issue is that the code was comparing the expected name (passed in as cn) to every name found in the certificate’s subjectAltName extension without first checking the type (for example, IP address versus dNSName). An attacker could use a certificate with only an IP address entry (which happens to “match” a short expected name) to spoof a domain name. To repair this, we must ensure that the certificate name is only compared to subjectAltName entries of the proper type (for example, only compare a hostname against dNSName entries).

One repair approach is to update the helper function so that it takes an extra parameter indicating the expected type. For example, using a constant (say, X509_CN_TYPE_DNS) to indicate that we should only consider subjectAltName entries that are dNSName. Then the code would look like this:

------------------------------------------------------------
/* Revised code snippet after repair */

#define X509_CN_TYPE_DNS 1  // expected type for DNS names

/* 
 * Updated x509_crt_check_cn() now examines certificate names.
 * It compares the supplied cn (and its length) only to certificate names
 * that are of type X509_CN_TYPE_DNS (ignoring IP address entries).
 */
if (CommonUtils.x509_crt_check_cn(cur.buf, cn, cn_len, X509_CN_TYPE_DNS) == 0)
    break;
------------------------------------------------------------

Inside the updated x509_crt_check_cn() function, it should iterate over the subjectAltName entries and for each name:

1. Check that the entry's type matches X509_CN_TYPE_DNS.
2. Only then compare it against the expected name.

For example, a pseudocode snippet inside the helper might be:

------------------------------------------------------------
int CommonUtils.x509_crt_check_cn(buffer, expected_cn, expected_cn_len, expected_type)
{
    // Parse the certificate buffer and iterate over subjectAltName entries
    for (each altName in certificate.subjectAltName) {
        if (altName.type != expected_type) {
            continue;   // Skip if the type doesn’t match what is expected.
        }
        if (compare(altName.value, expected_cn, expected_cn_len) == 0) {
            return 0;  // Found a match.
        }
    }
    // Also consider the certificate’s commonName if no matching altName is found.
    if (compare(certificate.commonName, expected_cn, expected_cn_len) == 0) {
        return 0;
    }
    return -1;
}
------------------------------------------------------------

This change ensures that an expected domain name is not matched against an IP address even if the certificate includes an altName of that type, for example, IPv4 or IPv6 addresses.

By adding the expected type parameter and enforcing the correct filter when traversing the extension, we close the loophole that allowed an attacker to match short names via IP address entries.
