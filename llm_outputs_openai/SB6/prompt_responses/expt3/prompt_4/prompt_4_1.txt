Below is one approach to “repair” the vulnerability. In the original code the function
  CommonUtils.x509_crt_check_cn(cur.buf, cn, cn_len)
compares the expected name (cn) against every subject alternative name (SAN) present in the certificate—even if a given SAN is not a DNS name. This lets an attacker who can obtain a certificate with an iPAddress (or another non-DNS name) in the SAN “match” the expected name. To fix this, the code must compare the expected name only against SAN entries known to be DNS names rather than any name regardless of its type.

For example, assume that we have parsed the certificate and ended up with a list (or linked list) of parsed SAN entries. Each entry carries a “type” (for instance, MBEDTLS_X509_SAN_DNSNAME, MBEDTLS_X509_SAN_IPADDRESS, etc.) and the associated name string. The fix is to consider only entries where the type is MBEDTLS_X509_SAN_DNSNAME when comparing against the expected name.

Below is a sample patch that illustrates the “repair.” (The exact data structures and APIs may differ in your environment; adjust the code accordingly.)

─────────────────────────────
// Example patched code snippet

/* Assume the following definitions:
   - “struct x509_alt_name” represents one subjectAltName entry with:
         int type;         // e.g., MBEDTLS_X509_SAN_DNSNAME, MBEDTLS_X509_SAN_IPADDRESS, etc.
         char *name;       // string representation of the name.
         struct x509_alt_name *next;  // Next SAN in the list.
   - MBEDTLS_X509_SAN_DNSNAME is the constant for DNS names.
   - cn is the expected hostname and cn_len its length.
*/

struct x509_alt_name *cur = certificate->subject_alt_names;
int cn_found = 0;

while (cur != NULL) {
    // Only consider SAN entries that are DNS names.
    if (cur->type == MBEDTLS_X509_SAN_DNSNAME) {
        if (strlen(cur->name) == cn_len &&
            /* For case-insensitive comparison, you may use a helper like strcasecmp */
            strcasecmp(cur->name, cn) == 0)
        {
            cn_found = 1;
            break;
        }
    }
    cur = cur->next;
}

/* If a SAN matching the expected DNS name was found, then the certificate is valid
   (as far as hostname verification is concerned). Otherwise, the verification must fail.
*/
if (!cn_found)
{
    /* Verification failure: none of the DNS SAN entries match the expected name. */
    return CERTIFICATE_VERIFY_ERROR;
}

/* Otherwise, continue processing the certificate verification normally. */

─────────────────────────────

Explanation of the patch:
1. Instead of unconditionally comparing the expected name (cn) to every subjectAltName obtained (which might include IP addresses), we loop over the SAN list.
2. We explicitly check for SAN entries where the type equals MBEDTLS_X509_SAN_DNSNAME.
3. Only if the expected string “cn” matches one of these DNS names (using length and case-insensitive matching) do we consider the certificate valid.
4. If no match is found, we signal a verification error.

This repair ensures that a certificate presenting alternative names of types other than DNS (such as an iPAddress entry) won’t falsely satisfy a hostname verification check.
