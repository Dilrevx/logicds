The vulnerability originally stemmed from unconditionally clearing the error code X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT_LOCALLY when that error was encountered during chain validation. This could allow a certificate chain with a missing issuer to be incorrectly marked as valid without verifying whether the certificate truly belongs to a trusted anchor. In other words, the original logic might inadvertently ignore an important error, even when it should prevent processing a potentially insecure certificate chain.

In the repair, we insert an additional check to ensure that the error is only cleared when it is safe to do so. Here’s how the fix works step by step:

1. After validating the legacy chain with the function x509_verify_ctx_validate_legacy_chain, the code examines the specific error at the depth corresponding to the problematic certificate. If the error is X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT_LOCALLY, processing continues in the new conditional block.

2. Instead of immediately setting the error value to X509_V_OK (which would signal no error), the repaired code calls another function, x509_is_trusted_cert, to check whether the last certificate in the chain (i.e., the one believed to be the potentially trusted anchor) is indeed trusted. This check is essential because only if the certificate is trusted can the error be safely cleared.

3. If x509_is_trusted_cert returns false (meaning the certificate is not a trusted anchor), then the code returns the error using the x509_verify_cert_error function. This stops further processing of the certificate chain under compromised conditions, thereby preventing the chain from being incorrectly marked as valid.

4. Conversely, if the function confirms that the certificate is trusted, then the error is cleared by setting chain.cert_errors[depth] to X509_V_OK, allowing the chain processing to continue normally.

5. Finally, after processing the error check, the certificate chain is added to the verification context and the overall result is returned as success.

By tying error clearing to an explicit trust check, the fix prevents scenarios where a missing issuer certificate might mistakenly be overlooked. This change ensures that only chains with a properly trusted anchor will have the error reset, preserving the integrity of the certificate verification process and preventing potential exploitation through improperly validated certificates.
