Below is one example of how you could patch the vulnerability by rejecting Security Mode Commands that propose “plain‐text” integrity (NIA0) (and/or ciphering) algorithms. In our patch we add an explicit check after decoding the selected NAS security algorithms. If the UE asks to use a “plain” integrity algorithm (which by definition bypasses NAS layer security activation), we immediately log the error, send a Security Mode Reject and return an error – rather than continuing with activation.

For example, suppose your IntegrityAlgorithmIdEnum has a constant (e.g. NIA0_PLAIN) that represents the “plain” (no integrity protection) mode. You can add a check like this:

------------------------------------------------------------
        // Set the cipher and integrity algorithms as selected by the UE
        ctxt_base.cipher_algo = CipheringAlgorithmIdEnum.fromValue(
                security_mode_command.selected_nas_security_algorithms.ciphering_algorithm.value
        );
        ctxt_base.integ_algo = IntegrityAlgorithmIdEnum.fromValue(
                security_mode_command.selected_nas_security_algorithms.integrity_protection_algorithm.value
        );
        
        // Added check: if the UE requests a plain (insecure) integrity algorithm, reject the command.
        if (ctxt_base.integ_algo == IntegrityAlgorithmIdEnum.NIA0_PLAIN) {
            logger.warning("Rejecting Security Mode Command because it specifies plain NAS integrity (NIA0_plain)");
            send_security_mode_reject(Cause5gmmType.Cause.ue_security_capabilities_mismatch);
            return SRSRAN_ERROR;
        }
        
        // (Optionally, you may also wish to verify that the ciphering algorithm is not plain.)
        // if (ctxt_base.cipher_algo == CipheringAlgorithmIdEnum.NEA0_PLAIN) {
        //     logger.warning("Rejecting Security Mode Command because it specifies plain NAS ciphering (NEA0_plain)");
        //     send_security_mode_reject(Cause5gmmType.Cause.ue_security_capabilities_mismatch);
        //     return SRSRAN_ERROR;
        // }
        
        if (!check_replayed_ue_security_capabilities(
                security_mode_command.replayed_ue_security_capabilities
        )) {
            logger.warning("Sending Security Mode Reject due to security capabilities mismatch");
            send_security_mode_reject(Cause5gmmType.Cause.ue_security_capabilities_mismatch);
            return SRSRAN_ERROR;
        }
        
        if (initial_sec_command) {
            set_k_gnb_count(0);
            ctxt_base.tx_count = 0;
            initial_sec_command = false;
        }
------------------------------------------------------------

Explanation:

1. After assigning the ciphering and integrity algorithms using their respective fromValue calls, we now check if the integrity algorithm is set to NIA0_PLAIN. This “plain” setting would bypass any NAS layer security activation, so we reject the security mode command upfront.

2. (Optionally, a similar check can be added for the ciphering algorithm if your implementation allows a “plain” (no ciphering) option that should also be disallowed.)

3. The rest of the code continues only if the selected algorithms meet the security requirements.

This patch prevents the UE from bypassing security activation by rejecting any Security Mode Command that asks to use the insecure plain-text integrity algorithm.
