The repair introduces an extra validation step immediately after determining the NAS signaling cipher and integrity algorithms. Specifically, it checks whether the integrity algorithm selected by the UE is NIA0, which represents “plain” (i.e., no protection). Accepting NIA0 could allow the UE to bypass the intended NAS layer security activation, thus compromising integrity protection.

In detail, the changes are as follows:

1. The code still sets the ciphering (ctxt_base.cipher_algo) and integrity (ctxt_base.integ_algo) algorithms based on the received security mode command. This part remains unchanged.

2. Immediately after setting these values, a new conditional statement was added. This condition explicitly checks if the integrity algorithm (ctxt_base.integ_algo) is set to NIA0. Since NIA0 indicates that no integrity protection is applied, using it could lead to a security gap where sensitive NAS communications might be intercepted or altered without detection.

3. If the integrity algorithm is found to be NIA0, the code logs a warning message indicating that such a configuration is not acceptable. Subsequently, it sends a “Security Mode Reject” message using the dedicated method (send_security_mode_reject). The rejection’s cause is flagged as a mismatch in UE security capabilities. Finally, the function returns an error code (SRSRAN_ERROR), effectively terminating the further processing of the security mode command.

4. After this extra security check, the traditional logic regarding the UE’s security capabilities (using check_replayed_ue_security_capabilities) and handling of initial security commands continues as before. This ensures that the added integrity algorithm validation is integrated seamlessly without affecting the overall control flow for proper cases.

By inserting this extra check, the vulnerability is fixed because it prevents a scenario where a UE might intentionally or inadvertently set its integrity algorithm to NIA0 (plain) and bypass the necessary security measures at the NAS level. Instead of proceeding with an insecure setup, the system now actively rejects any security mode command that attempts to use an unprotected integrity algorithm, enforcing the security policy effectively.

In summary, the repair makes sure that before any subsequent processing of the security mode command occurs, the integrity algorithm is verified to be secure. If it isn’t (i.e., if it is NIA0), the command is rejected outright, thereby closing the security loophole described.
