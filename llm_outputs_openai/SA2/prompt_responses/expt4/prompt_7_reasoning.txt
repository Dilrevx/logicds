The repair addresses the vulnerability by ensuring that the certificate validation loop checks every certificate in the chain, including the leaf certificate. In the original code snippet, the loop started at index 1:

  for (int i = 1; i < ctx.chain.size(); i++)

This skipped the first certificate (typically the leaf certificate). As a result, if a malicious CA deliberately inserted invalid certificate policies into the leaf certificate, those invalid policies would go unchecked, allowing an attacker to potentially bypass strict policy checks.

In the repaired code, the loop now starts at index 0:

By iterating from the beginning of the certificate chain, the code now verifies that every certificate—both the leaf and any intermediate certificates—adheres to the expected policy behavior. This change ensures that if a leaf certificate contains an invalid policy (one that could be used to circumvent certificate policy checks), it is detected by the cbFailIf() function.

The cbFailIf function likely performs a check that causes the function to fail if the certificate is null or if an invalid policy flag is set (as determined by (x.hashCode() & EXFLAG_INVALID_POLICY) != 0). With the new loop boundary, even if the leaf certificate carries such an invalid policy, the error is raised in a consistent manner.

To summarize:
• The vulnerability stemmed from skipping the leaf certificate during policy validation, potentially letting a malicious CA inject an invalid policy that is then silently ignored.
• The repair removes this loophole by checking all certificates in the chain.
• Starting the loop at 0 guarantees that each certificate (including the leaf) is scrutinized, thereby preventing the deliberate introduction of invalid policies designed to bypass policy checks.
