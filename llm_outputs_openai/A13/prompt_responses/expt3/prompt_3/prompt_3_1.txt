Below is one sample fix. In the original code the DLZ “allow zone transfer” check was only performed inside a conditional that only looked at the non‐empty dlz_searched list. That meant that for writable DLZ zones the dns_dlzallowzonexfr() call was sometimes bypassed. In the fix the allowzonexfr check is always performed for DLZ zones (and if needed, over every DLZ instance) so that the proper zone transfer policy is enforced even for writable zones.

Below is one possible patched snippet:

--------------------------------------------------
/* … earlier code … */
if (result != ISC_R_SUCCESS) {
	/*
	 * Normal zone table does not have a match.
	 * Try the DLZ database.
	 *
	 * Note: Previously only the first DLZ database was used;
	 * now we always perform the zone transfer check for DLZ zones,
	 * regardless of their writable state.
	 */
	{
		/* Instead of checking if the list is empty, always try DLZ. */
		result = dns_dlzallowzonexfr(client->view,
		                             question_name,
		                             &client->peeraddr,
		                             &db);

		if (result == ISC_R_NOPERM) {
			char _buf1[DNS_NAME_FORMATSIZE];
			char _buf2[DNS_RDATACLASS_FORMATSIZE];

			result = DNS_R_REFUSED;
			dns_name_format(question_name, _buf1, sizeof(_buf1));
			dns_rdataclass_format(question_class, _buf2, sizeof(_buf2));
			ns_client_log(client, DNS_LOGCATEGORY_SECURITY,
			              NS_LOGMODULE_XFER_OUT,
			              ISC_LOG_ERROR,
			              "zone transfer '%s/%s' denied",
			              _buf1, _buf2);
			goto failure;
		}
		if (result != ISC_R_SUCCESS) {
			FAILQ(DNS_R_NOTAUTH, "non-authoritative zone",
			      question_name, question_class);
		}
		is_dlz = true;
	}
} else {
	/* … rest of code … */
}
--------------------------------------------------

Explanations:

1. The patch removes the check for ISC_LIST_EMPTY(client->view->dlz_searched) so that we always call dns_dlzallowzonexfr(), regardless of whether the zone is writable or not. This ensures that the zone transfer policy is enforced uniformly.

2. If dns_dlzallowzonexfr() returns ISC_R_NOPERM (i.e. permission denied), the code logs the event and returns DNS_R_REFUSED.

3. For any other non-success result the failure path is taken.

By always calling dns_dlzallowzonexfr() for DLZ zones (writable or not) the patch fixes the vulnerability where zone transfer controls were not effective on writable DLZ zones.
