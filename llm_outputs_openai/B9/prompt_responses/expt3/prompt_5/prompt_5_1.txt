Below is one way to rework the control flow. In the new version, rather than immediately bailing out in each branch, we determine if the certificate matches the signature algorithm and then do one combined check. For example:

------------------------------------------------------------
/* Introduce a flag to indicate that the certificate matches the
   signature algorithm provided by the peer. */
int validSigAndCert = 0;

#ifdef HAVE_ED25519
    if (args->sigAlgo == ed25519_sa_algo) {
        validSigAndCert = ssl->peerEd25519KeyPresent;
        if (!validSigAndCert) {
            WOLFSSL_MSG("Peer sent ED25519 sig but no corresponding ED25519 cert");
        }
    }
#endif

#ifdef HAVE_ED448
    if (args->sigAlgo == ed448_sa_algo) {
        validSigAndCert = ssl->peerEd448KeyPresent;
        if (!validSigAndCert) {
            WOLFSSL_MSG("Peer sent ED448 sig but no corresponding ED448 cert");
        }
    }
#endif

#ifdef HAVE_ECC
    if (args->sigAlgo == ecc_dsa_sa_algo) {
        validSigAndCert = ssl->peerEccDsaKeyPresent;
        if (!validSigAndCert) {
            WOLFSSL_MSG("Peer sent ECC sig but no corresponding ECC cert");
        }
    }
#endif

#ifdef HAVE_PQC
    if (args->sigAlgo == falcon_level1_sa_algo ||
        args->sigAlgo == falcon_level5_sa_algo) {
        validSigAndCert = ssl->peerFalconKeyPresent;
        if (!validSigAndCert) {
            WOLFSSL_MSG("Peer sent Falcon sig but no corresponding Falcon cert");
        }
    }
#endif

#ifndef NO_RSA
    if (args->sigAlgo == rsa_sa_algo) {
        /* The PKCS#1.5 algorithm is not valid in TLS 1.3 so we return an error immediately */
        WOLFSSL_MSG("Peer sent PKCS#1.5 RSA sig algorithm which is not allowed in TLS 1.3");
        ERROR_OUT(INVALID_PARAMETER, exit_dcv);
    }
    if (args->sigAlgo == rsa_pss_sa_algo) {
        validSigAndCert = (ssl->peerRsaKey != NULL && ssl->peerRsaKeyPresent);
        if (!validSigAndCert) {
            WOLFSSL_MSG("Peer sent RSA-PSS sig but no corresponding RSA cert");
        }
    }
#endif

/* Final check: if the signature algorithm does not match the provided certificate, reject */
if (!validSigAndCert) {
    ret = SIG_VERIFY_E;
    goto exit_dcv;
}

------------------------------------------------------------

Step by step explanation:

1. We start by introducing a flag variable (here, validSigAndCert) to capture whether the peer’s signature algorithm corresponds to the expected certificate key.

2. For each supported algorithm (ED25519, ED448, ECC, Falcon variants, and RSA-PSS), we check if args->sigAlgo corresponds to that algorithm. Instead of aborting immediately, we set validSigAndCert according to whether the corresponding certificate flag is present in the ssl structure. If the flag is missing, we log an appropriate message.

3. For RSA using PKCS#1.5, we continue to immediately error out because that signature mode is not allowed in TLS 1.3.

4. Finally, after evaluating all possible algorithms, we perform one final check. If validSigAndCert is false (i.e. falsey), then we stop processing. This ensures that the certificate check is only considered successful when the certificate type matches the signature algorithm.

This restructuring ensures that a mismatch between the signature algorithm and the provided certificate is never overlooked, thereby closing the vulnerability.
