Below is one example of a fixed version. In the original code the reply is “matched” only by the query‐ID (and, optionally, by a hash) even though the reply’s destination address and port (i.e. the one to which the upstream server sent its reply) must also be verified. In this fixed version we additionally compare the reply’s destination (address/port) with the information stored for the forwarded query. (Note that the actual names or types for the reply’s destination may vary in your code; adjust accordingly so that the reply’s address/port is compared against the query’s.)

<repair>
    /* Now also compare the reply’s destination address/port (reply_dest)
       with the original destination used when sending the forwarded query.
       This ensures that the reply is matched to an exact pending query.
       (Assuming that “reply_dest” is a pointer to a struct sockaddr, and that
       f->sentto points to the original destination address data.) */
    if (f->sentto && f->new_id == id &&
        reply_dest && memcmp(reply_dest, f->sentto, sizeof(struct sockaddr)) == 0 &&
        (!hash || memcmp(hash, f->hash, HASH_SIZE) == 0))
      return f;
</repair>

In this repair the extra check using memcmp() makes sure that the reply’s destination (port and address) exactly matches the one used when the query was forwarded – thus complying with RFC5452 and preventing the possibility of a cache poisoning attack.
