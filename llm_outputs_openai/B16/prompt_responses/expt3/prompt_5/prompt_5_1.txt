Below is one example of how you could change the code. In the original code only the query’s id (and optionally a hash) is verified. In the patched version the code also checks that the reply came over the same network channel (socket) that was used to forward the DNS request. For example, if a query was sent using an IPv4 socket, we must verify that the file descriptor (fd) on which the reply is received is identical to the one used for sending the query; the same idea applies for IPv6 or any query that was transmitted through a socket bound to a specific upstream interface.

Below is one repair implementation that illustrates the three-pronged approach described in the repair description:

--------------------------------------------------
/* Example patched snippet */
if (f->sentto && f->new_id == id &&
    (!hash || memcmp(hash, f->hash, HASH_SIZE) == 0)) {

    /*
     * Additional socket validations:
     *
     * (1) IPv4 check.  If the query was sent over an IPv4 socket (AF_INET),
     *     then the incoming reply must have arrived on that same socket.
     */
    if (f->af == AF_INET) {
        if (f->fd != reply_fd)  /* reply_fd is the file descriptor the reply came in on */
            return NULL;        /* failed socket check */
    }

    /*
     * (2) IPv6 check. If the query was sent over IPv6 (AF_INET6),
     *     then similarly, verify that the reply came on the same socket.
     */
    else if (f->af == AF_INET6) {
        if (f->fd != reply_fd)
            return NULL;
    }

    /*
     * (3) Bound upstream interface. In some cases the query may have been
     *     sent from a socket bound to a specific upstream interface. If so,
     *     check that the reply arrived on that same fd.
     */
    if (f->bound_fd != -1) {
        if (f->bound_fd != reply_fd)
            return NULL;
    }

    /* All conditions met: query id, optional hash, and correct socket */
    return f;
}
--------------------------------------------------

Step by Step Explanation:

1. The existing code checked that a pending query (f) exists (f->sentto is non-NULL), that the reply’s ID (id) matches f->new_id, and, if a hash is provided, that the hashes match.
2. The patch then introduces additional file descriptor (socket) checks:
   • For IPv4 queries (f->af == AF_INET), it compares the file descriptor used for the original query (f->fd) with the descriptor on which the reply is received (reply_fd). If they differ, the reply is rejected.
   • Similarly, for IPv6 queries (f->af == AF_INET6), the same check is performed.
3. Sometimes the query is sent using a socket bound to a specific upstream interface (represented by f->bound_fd). When such a binding exists (f->bound_fd is not -1), the patch ensures that the reply originates from that exact socket.
4. Only if all conditions (ID, optional hash, and correct socket) match does the function return the query (f). Otherwise, it returns NULL (or continues the search/reply matching process).

This implementation makes forging a reply much harder because an attacker would now have to both guess the query’s parameters and also control the network channel (i.e. the same socket file descriptor) for the reply to be accepted—thus mitigating the DNS cache poisoning vulnerability.
