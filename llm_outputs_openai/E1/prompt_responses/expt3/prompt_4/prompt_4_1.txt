Below is one example of a repair. In the buggy code the plain NAS messages are simply accepted (as indicated by the empty break) even after the UE’s NAS security has been activated. This could allow an attacker to send an identity request in clear text when integrity protection has already been negotiated. One fix is to add a check for an active security context before accepting plain (identity_req_plain) messages. For example, assuming you have a mechanism (such as a flag or context state) called security_is_activated(), you can modify the case for plain NAS messages to reject them if security is already active.

Repaired code snippet:

--------------------------------------------------
  // Assume that "security_is_activated()" returns true if NAS security is active.
  switch (nas_msg.hdr.security_header_type) {
    case nas_5gs_hdr::security_header_type_opts::plain_5gs_nas_message:
      // Reject plain NAS messages if security is already activated.
      if (security_is_activated()) {
        logger.error("Plain NAS message not allowed after NAS security activation");
        return SRSRAN_ERROR;
      }
      break;
      
    case nas_5gs_hdr::security_header_type_opts::integrity_protected:
      if (!integrity_check(pdu.get())) {
        logger.error("Not handling NAS message with integrity check error");
        return SRSRAN_ERROR;
      }
      break;
      
    case nas_5gs_hdr::security_header_type_opts::integrity_protected_and_ciphered:
      if (!integrity_check(pdu.get())) {
        logger.error("Not handling NAS message with integrity check error");
        return SRSRAN_ERROR;
      } else {
        cipher_decrypt(pdu.get());
      }
      break;
      
    case nas_5gs_hdr::security_header_type_opts::integrity_protected_with_new_5G_nas_context:
      break;
      
    case nas_5gs_hdr::security_header_type_opts::integrity_protected_and_ciphered_with_new_5G_nas_context:
      return SRSRAN_ERROR;
      
    default:
      logger.error("Not handling NAS message with unknown security header");
      break;
  }
--------------------------------------------------

Key Points of the Repair:
1. In the plain message case, we now check if the NAS security context is activated. If it is, the plain message is rejected.
2. This ensures that a plain identity request (or similar plain NAS messages) is not accepted once the security has been activated, closing the vulnerability.

Replace security_is_activated() with your actual method or flag that indicates whether NAS security activation has taken place.
