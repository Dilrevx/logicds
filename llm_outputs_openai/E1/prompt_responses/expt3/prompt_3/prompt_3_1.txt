This means that after security activation a plain identity request (or any plain NAS message) will be accepted. To fix the vulnerability you can add a check to reject any plain NAS messages if the NAS security context is already active. For example, suppose you have a function or flag (here called is_security_active()) that indicates whether NAS security is active; you could modify the case as follows:

---------------------------------------------------------
switch (nas_msg.hdr.security_header_type) {
  case nas_5gs_hdr::security_header_type_opts::plain_5gs_nas_message: {
      // If security is already active, reject plain NAS messages.
      if (is_security_active()) {
        logger.error("Rejecting plain NAS message because NAS security is activated");
        return SRSRAN_ERROR;
      }
      break;
  }
  case nas_5gs_hdr::security_header_type_opts::integrity_protected:
      if (!integrity_check(pdu.get())) {
        logger.error("Not handling NAS message with integrity check error");
        return SRSRAN_ERROR;
      }
      break;
  case nas_5gs_hdr::security_header_type_opts::integrity_protected_and_ciphered:
      if (!integrity_check(pdu.get())) {
        logger.error("Not handling NAS message with integrity check error");
        return SRSRAN_ERROR;
      } else {
        cipher_decrypt(pdu.get());
      }
      break;
  case nas_5gs_hdr::security_header_type_opts::integrity_protected_with_new_5G_nas_context:
      break;
  case nas_5gs_hdr::security_header_type_opts::integrity_protected_and_ciphered_with_new_5G_nas_context:
      return SRSRAN_ERROR;
  default:
      logger.error("Not handling NAS message with unknown security header");
      break;
}
---------------------------------------------------------

Explanation of the repair:
1. In the plain message branch (case plain_5gs_nas_message), we first check if the NAS security context is active.
2. If is_security_active() returns true, we log an error and return an error code rather than processing the message as if it were acceptable.
3. This prevents the UE from accepting plain identity requests (or other plain NAS messages) once security has been established.

Note: Replace is_security_active() with however your implementation determines that the security context is active. This change ensures that the system won’t inadvertently process insecure plain messages after security activation.
