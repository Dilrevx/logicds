The provided repair aims to address a vulnerability in the client-side SSH code that allows an SSH server to manipulate the login process by sending multiple `msg_userauth_success` messages. The original buggy code does not check if the `msg_userauth_success` message is received multiple times, which can lead to the authentication state being reset or modified by the server. To fix this vulnerability, the repair introduces a check to ensure that the `msg_userauth_success` message is only processed once.

2.  **Moved the authentication state update inside the conditional statement**: The update of the `ses.authstate.authdone` and `cli_ses.state` variables, as well as the cleanup of the public key authentication (`cli_auth_pubkey_cleanup()`), are moved inside the conditional statement. This ensures that these actions are only performed once, when the first `msg_userauth_success` message is received.
3.  **Added a log message for duplicate messages**: If the `cli_ses.state` is already `USERAUTH_SUCCESS_RCVD`, a log message is printed to indicate that a duplicate `msg_userauth_success` message was received. This helps with debugging and monitoring potential attacks.

By introducing this check, the repair prevents the SSH server from manipulating the authentication state by sending multiple `msg_userauth_success` messages.
