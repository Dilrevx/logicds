The vulnerability stems from the fact that the RC4-MD5 ciphersuite in OpenSSL 3.0 was erroneously using the additional authenticated data (AAD) as the key for the MAC (Message Authentication Code). Since the AAD is predictable or even known by an attacker, this mistake rendered the MAC key trivial to guess. Such predictability paves the way for a man-in-the-middle attacker to intercept and alter data in transit without being detected by the integrity verification step, which is intended to protect the data's authenticity.

The repair addresses this issue by ensuring that the system retrieves and uses the correct cryptographic parameter. In the vulnerable implementation, the code mistakenly looks up the parameter associated with the AAD instead of the one associated with the MAC key. The revised approach changes this lookup to target the correct parameter designated for the MAC key. By doing so, the MAC is ultimately computed using a cryptographically secure and unpredictable key rather than a predictable piece of information.

This adjustment is significant because the MAC key must be kept secret and randomized to maintain the security guarantees of the cryptographic protocol. Using the proper parameter eliminates the risk of an attacker knowing or controlling the MAC key. When the system correctly fetches the MAC key parameter, any adversary who might intercept and modify the communication will not be able to correctly forge the MAC, thus ensuring that tampering is detectable.

Essentially, the fix reinforces the separation of roles between different parts of the cryptographic process. The AAD is meant to carry non-secret data that aids in the context of encryption, whereas the MAC key is engineered to ensure data integrity through its unpredictability and secrecy. By correcting the parameter lookup from one that inadvertently exposes a sensitive element (the MAC key) to one that properly retrieves it, the integrity check mechanism is restored to its secure state.

In summary, the reasoning behind the repair is to eliminate a critical security flaw by replacing an incorrect reference with the correct one. This ensures that an unpredictable, secure MAC key is used for computing the message authentication code, thereby preventing attackers from exploiting the vulnerability to bypass data integrity checks through malicious modifications.
