The repair addresses the issue by ensuring that errors encountered during the leaf certificate verification are properly recorded and preserved, even when a verification callback instructs the verifier to continue. In the original implementation, errors that occurred during the leaf certificate checks were effectively lost because the code duplicated the certificate chain without first capturing these errors. As a result, when a callback allowed continuation after detecting an invalid certificate, the final error reported might not accurately reflect the actual problem encountered.

In the fixed version, the first change is to perform the certificate and hostname validations before attempting to duplicate the certificate chain. This reordering is crucial because it ensures that any errors resulting from these validations are identified earlier in the process. Specifically, when the certificate is at the leaf (indicated by a depth of zero) and the error is not simply due to an unreachable issuer certificate, the error is stored directly in the certificate chain’s error array. This guarantees that the exact error context is preserved for the leaf certificate, rather than being overwritten or ignored later on.

After capturing the error, the code then proceeds to duplicate the certificate chain. If this duplication fails due to resource constraints (for example, out-of-memory conditions), an appropriate error is returned immediately. Only after successfully duplicating the chain does the code increment the chain count and reset the general error indicator to “OK,” while also updating the error for the current chain depth.

In summary, the repair rearranges the operations to capture and store the verification errors from the leaf certificate before potentially overwriting them by duplicating the chain structure. This approach ensures that any invalid certificate, even if the callback directs the process to proceed, will leave behind accurate error information. As a result, the system is now able to return the correct error information, thereby effectively mitigating the vulnerability.
