The core of this repair is to tighten the conditions under which plaintext NAS messages are processed in order to mitigate potential exploitation. In the original implementation, the code allowed several message types without requiring any integrity protection. This included not only messages that are relatively benign when unprotected, but also some messages that are sensitive in nature, such as EMM Information, EMM Status, and Detach Request. Permitting these messages in plaintext poses a vulnerability because an attacker could potentially manipulate or misuse them, leading to unauthorized state changes or other unpredictable behavior in the network.

The repair addresses this vulnerability by explicitly narrowing the list of message types that are permitted when no integrity protection is provided. By removing EMM Information, EMM Status, and Detach Request from the accepted list, the modified code now only processes a smaller set of messages in plaintext. These remaining messages—like Identity Request, Authentication Request and Reject, Attach Reject, Detach Accept, Tracking Area Update Reject, and Service Reject—are deemed to be less risky when transmitted without additional security safeguards. Essentially, the repair enforces a stricter policy: if a message is not one of the few specially validated types, it will not be handled unless it has proper integrity protection.

This narrowing of acceptable plaintext messages helps ensure that any message capable of altering the network state or signaling significant events is not inadvertently trusted just because it fits a broad accept condition. For example, handling a Detach Request in plaintext could allow an attacker to force disconnections or induce network instability, while EMM Information and Status might leak sensitive internal states or trigger erroneous behavior. By only allowing a limited subset that is known to be safe even in the absence of added security checks, the repair minimizes potential attack vectors.

Overall, this change reflects a risk-aware approach: it acknowledges that not all NAS messages are suitable to be processed without additional security measures such as integrity protection. By explicitly rejecting any plaintext messages that are not in the safe, vetted list, the repair significantly reduces the risk that critical signaling messages might be exploited by an attacker. This ensures that the protocol adheres more strictly to security principles, thereby bolstering the overall safety and reliability of the system.
