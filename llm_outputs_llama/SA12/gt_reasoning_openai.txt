The vulnerability arises when a TLS v1.3 server that requires mutual authentication could allow a connection from a malicious client simply by omitting the certificate_verify message. This means that even if the server is configured to require a certificate from connecting clients, a client might bypass this security check by not providing the necessary message that proves ownership of the certificate. Consequently, an unauthorized client might establish a secure connection without the proper credentials.

The repair addresses this flaw by adding an explicit check designed to enforce the certificate verification process. The new logic first determines if the connection is on the server side and whether properties have been set that require mutual authentication. These options indicate that the server should reject any connection attempt unless the client has completed the certificate verification step.

Once it is confirmed that the connection should have a verified certificate (due to mutual authentication or an option that fails the connection when no certificate is provided), the revised code then explicitly checks if the peer certificate verification flag is not set, meaning that the expected certificate verification has not occurred, and also ensures that this check is not bypassed during a session resumption. If the client failed to provide the necessary certificate verification message, the server now returns an appropriate error code, simultaneously generating a fatal alert to signal the problem immediately and terminate the handshake.

By incorporating this explicit check, the repair prevents a scenario where the absence of the certificate_verify message would allow a connection to proceed unchecked. Essentially, instead of falling through to perform further processing of the client’s message stream (which would be a vulnerability if the verification step is omitted), the code now intervenes early in the handshake process. If the required verification step did not occur, not only is the connection refused, but also a fatal alert is dispatched to ensure that the client receives a clear signal that there was an error with its credentials.

This additional security check serves to enforce the integrity of the mutual authentication process, guaranteeing that a client cannot simply ignore the certificate verification step to gain access. In summary, the repair strengthens the protocol by ensuring that any connection which does not conform to the required authentication standards is promptly rejected, thereby mitigating the risk of unauthorized access through an incomplete handshake process.
