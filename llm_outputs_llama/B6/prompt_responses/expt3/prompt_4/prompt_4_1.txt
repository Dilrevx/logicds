**Vulnerability Repair: X.509 Certificate Verification**

The provided code snippet has a vulnerability in the verification of X.509 certificates when matching the expected common name with the actual certificate name. The issue arises when the subjectAltName extension is present, and the expected name is compared to any name in that extension regardless of its type. This can be exploited by an attacker to impersonate a domain by getting a certificate for the corresponding IP address.

**Repaired Code:**

To fix this vulnerability, we need to ensure that the expected common name is compared only to the DNS names in the subjectAltName extension, and not to IP addresses. We can achieve this by checking the type of the subjectAltName entry before comparing it with the expected common name.

```c
if( crt->ext_types & MBEDTLS_X509_EXT_SUBJECT_ALT_NAME )
{
    for( cur = &crt->subject_alt_names; cur!= NULL; cur = cur->next )
    {
        if( cur->type == MBEDTLS_ASN1_DNS_NAME )
        {
            if( x509_crt_check_cn( &cur->buf, cn, cn_len ) == 0 )
                break;
        }
    }

    if( cur == NULL )
        *flags |= MBEDTLS_X509_BADCERT_CN_MISMATCH;
}
else
{
    for( name = &crt->subject; name!= NULL; name = name->next )
    {
        if( MBEDTLS_OID_CMP( MBEDTLS_OID_AT_CN, &name->oid ) == 0 &&
            x509_crt_check_cn( &name->val, cn, cn_len ) == 0 )
        {
            break;
        }
    }

    if( name == NULL )
        *flags |= MBEDTLS_X509_BADCERT_CN_MISMATCH;
}
```

**Explanation:**

In the repaired code, we added a check for the type of the subjectAltName entry (`cur->type == MBEDTLS_ASN1_DNS_NAME`) before comparing it with the expected common name. This ensures that only DNS names are considered for the comparison, and IP addresses are ignored.

**Example Use Case:**

To test the repaired code, you can create a test certificate with a subjectAltName extension containing a DNS name and an IP address. Then, verify the certificate using the repaired code and check that it correctly identifies the DNS name as the expected common name.

**Note:**

This repair assumes that the `MBEDTLS_ASN1_DNS_NAME` constant is defined in the mbedtls library. If this constant is not defined, you may need to use a different value or approach to identify DNS names in the subjectAltName extension.
