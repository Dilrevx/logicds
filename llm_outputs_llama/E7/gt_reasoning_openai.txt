The core issue stemmed from the fact that the original implementation permitted certain critical NAS messages to be processed without integrity protection. In secure communications, allowing messages that can affect session state or control signaling to be accepted in plaintext is a significant security weakness. Plaintext messages are not protected against tampering or spoofing, which means that an attacker could potentially inject or replay messages like Detach Request, EMM Information, and EMM Status to disrupt network services or manipulate the state of a connection.

The repair addresses this vulnerability by ensuring that the system no longer accepts these specific message types in an unprotected, plaintext format. Essentially, the patch removes the acceptance of EMM Information and EMM Status messages from the plaintext handling routine. It also comments out the handling of the Detach Request message in plaintext. By doing so, the system forces these messages to be evaluated under the assumption that they must have proper integrity protection before being processed.

This change is significant for several reasons. First, it reduces the attack surface by not trusting critical signaling messages unless they meet stringent security checks. By rejecting these messages when they are not accompanied by integrity protection, the system ensures that any message capable of affecting user sessions or network connectivity must have passed through appropriate authentication and integrity verification routines. This minimizes the risk that an attacker could manipulate session state or service behavior by sending a forged message.

In addition, the repair helps maintain the integrity of the connection by ensuring that only authenticated and verified messages are acted upon. This is crucial because messages like Detach Request, if accepted in plaintext, could lead to unauthorized disconnections or other service disruptions, which could be exploited in denial-of-service attacks or other forms of network abuse.

Moreover, this patch represents a targeted security measure corresponding with a specific security level (noted as SL10 in the patch comments), highlighting that the decision to reject these plaintext messages is deliberate and meets the required security criteria. By making this change, the developers enforce that integrity protection is mandatory for any message that could potentially influence the state of the network or user sessions.

Overall, the rationale behind the fix is to ensure that sensitive and critical network messages are always transmitted securely. This protects both the users and the network infrastructure from potential attacks that exploit the acceptance of unprotected messages, leading to a more robust and resilient implementation overall.
