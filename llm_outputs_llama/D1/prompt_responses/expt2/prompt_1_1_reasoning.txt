The provided repair addresses a vulnerability in the PJSIP library where SRTP (Secure Real-time Transport Protocol) media transport is incorrectly switched to basic RTP (Real-time Transport Protocol) upon SRTP restart. This vulnerability impacts all PJSIP users who utilize SRTP, resulting in media being sent insecurely.

The buggy code snippet handles a specific condition where the stream is updated, and SRTP is restarted. However, during this process, some old packets may still be coming in, causing SRTP to learn the wrong RTP sequence. When the newly initialized RTP sequence arrives, SRTP incorrectly identifies it as a replayed sequence, leading to an error.

The original code attempts to resolve this issue by stopping SRTP, restarting it, and then re-processing the packet. However, it fails to ensure that the transport is reset to SRTP after the restart. This oversight allows the transport to potentially switch to basic RTP, compromising the security of the media transmission.

The repair addresses this vulnerability by adding a crucial step after stopping SRTP and before restarting it. The line `transport->flags &= ~PJMEDIA_TRANSPORT_FLAG_RTP;` ensures that the transport is explicitly reset to SRTP after the restart. This modification guarantees that the transport remains in SRTP mode, preventing it from switching to basic RTP.

By adding this line, the repair ensures that the transport's flags are updated correctly, maintaining the secure SRTP mode even after the restart. This fix prevents the vulnerability from occurring, ensuring that media is transmitted securely using SRTP.
