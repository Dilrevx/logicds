The repair provided for the OpenSSL vulnerability, also known as the "CCS Injection" vulnerability, is designed to prevent man-in-the-middle attackers from triggering the use of a zero-length master key in certain OpenSSL-to-OpenSSL communications. The vulnerability arises from the failure to properly restrict processing of ChangeCipherSpec (CCS) messages.

The root cause of the vulnerability lies in the handshake state machine, specifically in the SSL3_ST_CR_FINISHED_A and SSL3_ST_CR_FINISHED_B states. In these states, the CCS_OK flag is not being set explicitly, which allows an attacker to inject a CCS message and trigger the use of a zero-length master key.

To fix this vulnerability, the CCS_OK flag must be set explicitly in the affected states. This ensures that the flag is set before the handshake state is updated to SSL_ST_OK, preventing an attacker from injecting a CCS message and triggering the use of a zero-length master key.

The repair provided sets the CCS_OK flag explicitly in the SSL3_ST_CR_FINISHED_A and SSL3_ST_CR_FINISHED_B states by adding the line `state.ccs_ok = true;` before updating the handshake state to SSL_ST_OK. This ensures that the CCS_OK flag is set correctly, preventing the vulnerability from being exploited.
