The vulnerability arose because the system could accept a security mode command where the integrity protection algorithm was set to an insecure value, specifically zero, which effectively meant that NAS layer security activation was being bypassed. In other words, if the integrity algorithm was zero—a value representing the “plain” or non-protected mode—the UE would operate without proper security. This condition was unacceptable because it left the connection vulnerable to attacks.

To address this, the repair introduces an explicit check after setting up the chosen security algorithms. First, the system logs that it is handling the Security Mode Command, which is useful for debugging and auditing purposes. Then, the repair confirms that the ciphering and integrity algorithms provided in the command are appropriately extracted and set.

The critical change comes immediately after these assignments. The repair verifies whether the integrity algorithm is equal to zero. If it is, this situation is promptly flagged as an error by issuing a log message indicating that a prohibited value was present in the Security Mode Command. Following this, the process is terminated with an error response before any further processing is done. This approach ensures that any command attempting to use an insecure integrity algorithm (i.e., NIA0/plain) is effectively rejected, thus upholding the security of the NAS layer.

By adding this check, the repair prevents the acceptance of potentially risky settings that would allow unprotected communication. Without this safeguard, an attacker or a misconfigured UE could inadvertently or deliberately bypass necessary security measures, leading to compromised data integrity and possible exploitation of the network. The repair therefore directly addresses and eliminates the vulnerability by refusing to process any command that might leave the system exposed, ensuring that the integrity and confidentiality mechanisms are always properly activated.

Additionally, the existing validation of replayed UE security capabilities is still maintained, meaning that other aspects of the security context continue to be verified as before. The initialization of security counters that occur during the initial security command is preserved once the integrity check passes, ensuring that the session remains synchronized and secure.

In summary, the reasoning behind the fix is to enforce a security check on the integrity algorithm selection immediately after it’s been extracted from the command. Rejecting commands with an integrity algorithm value of zero prevents scenarios where the NAS security might be bypassed, thereby preserving the integrity and proper function of the security mechanisms in the system.
