The repair addresses the vulnerability by ensuring that the server enforces mutual authentication properly. In the original code, the server did not verify whether the client had actually sent a certificate when one was required. Because of this omission, a malicious client could simply omit the certificate_verify message and still complete the TLS handshake, bypassing the certificate check entirely. This meant that even in a configuration where the server demanded client certificates, the connection could be erroneously accepted if the client chose not to present any credentials.

The fix introduces an additional pre-check early in the handshake process. This check is executed only when the server side is in operation and when the server options indicate either mutual authentication is required or that failing to provide a certificate should lead to a failure. It specifically examines if the client certificate has been verified. If the flag indicating the receipt and verification of the client certificate is not set, and the connection isn’t a resumed session (where different criteria might apply), the code immediately terminates the handshake by generating an error condition. It does this by setting an error to indicate that no peer certificate was provided, and then invoking a routine that sends a fatal alert to the client, followed by returning the error code.

By incorporating this verification step before continuing with the rest of the handshake (for instance, before checking buffer sizes or completing the hash-based secret derivation), the repair ensures that no further processing is conducted on a connection that has not met the required authentication criteria. This helps thwart the potential attack where a client could otherwise bypass the certificate requirement and potentially access the server unauthenticated.

Additionally, the conditional compilation flags in the repair ensure that this check is only included when certificate-based authentication is enabled. This prevents any unintended behavior in deployments where either certificates aren’t used or client authentication isn’t desired. Overall, the fix effectively hardens the TLS handshake by adding a robust, early-check mechanism that verifies the presence of client authentication, thereby stopping attackers from exploiting the vulnerability to bypass mutual authentication.
