The provided repair is aimed at fixing a vulnerability in the TLS v1.3 server implementation, specifically in the `DoTls13Finished` function. The vulnerability allows a malicious client to bypass mutual authentication by not sending the `CertificateVerify` message, even if the server requires one.

The repair introduces a new check to ensure that the `CertificateVerify` message has been sent by the client before proceeding with the handshake. This check is performed on the server-side, specifically when the server requires mutual authentication (`ssl->options.require_cert` is set) and has requested a certificate from the client (`ssl->options.certReq` is set).

The new check is added after the verification of the `Finished` message and before the server proceeds with setting up the keys for application data messages. The check verifies that the `certSent` flag is set, which indicates that the client has sent the `CertificateVerify` message.

If the `certSent` flag is not set, the server sends a fatal alert to the client with a `handshake_failure` reason and returns an error code (`VERIFY_CERT_ERROR`). This prevents the handshake from proceeding without the client providing a valid certificate.

The reasoning behind this repair is as follows:

1.  **Mutual authentication requirement**: In TLS v1.3, mutual authentication is optional, but when required, the server must verify the client's identity. The `require_cert` option indicates that the server requires mutual authentication.
2.  **Certificate request**: The server requests a certificate from the client by setting the `certReq` option. This indicates that the client is expected to provide a certificate.
3.  **CertificateVerify message**: The client responds to the certificate request by sending a `CertificateVerify` message, which contains the client's certificate and a signature over the handshake transcript.
4.  **Verification**: The server verifies the client's certificate and signature. If the verification fails, the handshake is terminated.
5.  **Flagging certificate receipt**: To track whether the client has sent the `CertificateVerify` message, a `certSent` flag is used. This flag is set when the server receives and verifies the client's certificate.

By introducing the `certSent` flag check, the repair ensures that the server only proceeds with the handshake if the client has provided a valid certificate. This prevents a malicious client from bypassing mutual authentication by not sending the `CertificateVerify` message.

In summary, the repair adds a crucial check to the TLS v1.3 server implementation to ensure that mutual authentication is enforced when required. This prevents a potential vulnerability that could allow malicious clients to bypass authentication.
