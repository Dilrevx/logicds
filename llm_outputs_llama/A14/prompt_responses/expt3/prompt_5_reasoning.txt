The repair addresses the OpenSSL "CCS Injection" vulnerability, which allows a man-in-the-middle attacker to trigger the use of a zero-length master key, potentially hijacking sessions or obtaining sensitive information. The vulnerability arises from the way OpenSSL handles ChangeCipherSpec (CCS) messages, which are used to change the encryption cipher during a TLS/SSL handshake.

The primary issue is that OpenSSL does not properly restrict the processing of CCS messages, allowing an attacker to send multiple CCS messages and potentially bypass security checks. To fix this, the repair introduces a check for the SSL3_FLAGS_CCS_OK flag, which indicates whether a CCS message has already been processed. If this flag is set, the repair sets an alert level of SSL_AD_UNEXPECTED_MESSAGE and aborts the handshake, preventing the attacker from sending multiple CCS messages.

Another crucial aspect of the repair is verifying that a cipher is available to change to before processing the CCS message. This ensures that the handshake is not vulnerable to attacks that rely on the absence of a valid cipher. By checking for the presence of a cipher, the repair prevents the attacker from exploiting this vulnerability.

The repair also validates the record payload of the CCS message to ensure it conforms to the expected format. This includes checking the length, offset, and contents of the message. If the message does not match the expected format, the repair sets an alert level of SSL_AD_ILLEGAL_PARAMETER and aborts the handshake, preventing the attacker from sending malformed CCS messages.

Additionally, the repair invokes the message callback function if registered, allowing the application to inspect and potentially reject the CCS message. This provides an additional layer of security and allows the application to enforce its own security policies.

Finally, the repair performs the actual cipher change by calling the ssl3_do_change_cipher_spec function. However, it also clears the SSL3_FLAGS_CCS_OK flag after processing a valid CCS message, ensuring that subsequent CCS messages are properly restricted.

In summary, the repair addresses the OpenSSL "CCS Injection" vulnerability by introducing checks for the SSL3_FLAGS_CCS_OK flag, verifying the presence of a valid cipher, validating the CCS message payload, invoking the message callback function, and clearing the SSL3_FLAGS_CCS_OK flag after processing a valid CCS message. These changes prevent man-in-the-middle attackers from exploiting the vulnerability and ensure the security of the TLS/SSL handshake.
