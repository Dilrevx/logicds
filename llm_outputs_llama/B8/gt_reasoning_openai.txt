The repair addresses the vulnerability by ensuring that before the encryption is enabled, the connection has actually established a secure basis for the session master secret. In previous versions, if the client did not receive either a pre-shared key (PSK) or a key share (KSE) extension from the server, the code would default to using a predictable buffer for generating the input keying material (IKM). This predictable IKM meant that an attacker could potentially reconstruct the derived session keys, thereby compromising the entire encrypted session.

The fix introduces an additional check immediately after attempting to set up the PSK. This new check evaluates whether neither a properly negotiated PSK nor a key share (indicated by a non-zero value for the named group) is available. Essentially, if the session has not negotiated a valid PSK and there is no valid key share, then the function signals an error rather than proceeding. This error return (EXT_MISSING) stops the handshake from completing using the fallback method that would have utilized the default predictable buffer.

By enforcing this condition, the repair prevents the handshake from reaching a state where an insecure, predictable IKM might be used to generate the master secret. The TLS session will not be considered secure unless at least one of the two critical elements—a PSK or a key share—is validly established. This check is crucial because it protects the integrity of the encryption process. Without it, an attacker who can manipulate the server to omit both extensions could force the client into a state where it uses a known keying material, thereby potentially allowing eavesdropping or tampering of the session data.

In essence, the repair adds a form of sanity check that verifies the necessary cryptographic elements are in place before moving forward. If the required conditions are not met, it prevents the final stages of the handshake from being executed, thereby avoiding the risk of proceeding with a compromised key derivation process. This approach mitigates the vulnerability by ensuring that each session only proceeds when securely established, thereby preserving the confidentiality and integrity of the communication.
