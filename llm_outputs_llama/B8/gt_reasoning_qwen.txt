The vulnerability described pertains to a critical flaw in the way wolfSSL handles the absence of both the Pre-Shared Key (PSK) and Key Share Extension (KSE) during a TLS 1.3 handshake with a malicious server. When these extensions are not received, the system defaults to using a predictable buffer for the Intermediate Key Material (IKM), which is crucial for generating the session master secret. Since this IKM can be predicted, it weakens the security of the session, making it susceptible to eavesdropping and tampering.

To address this vulnerability, the repair introduces a sanity check to ensure that either a PSK or a KSE is present before proceeding with the handshake. This check is strategically placed after the existing logic that processes the PSK extension. If neither a PSK nor a KSE is found, the function returns an error indicating that essential extensions are missing (`EXT_MISSING`).

The reasoning behind this repair lies in the necessity to enforce strict adherence to the TLS 1.3 protocol requirements. According to the TLS 1.3 specification, at least one of these extensions must be included in the ServerHello message to establish a secure session. By adding this check, the system ensures that the session master secret is derived from a truly random source provided by either the PSK or KSE, thereby maintaining the integrity and confidentiality of the communication.

This change effectively prevents the use of a predictable IKM, which was the root cause of the vulnerability. It enforces a robust security mechanism that requires valid cryptographic material for key derivation, thus safeguarding against potential attacks that exploit the predictable IKM scenario. The inclusion of this sanity check is a proactive measure to prevent downgrade attacks or other manipulations by malicious servers that might attempt to bypass the necessary security steps.

In summary, the repair enhances the security posture of wolfSSL by ensuring that the TLS 1.3 handshake only proceeds under conditions where the session master secret can be securely derived. This approach aligns with the security principles of using unpredictable keys and adhering to established cryptographic standards, ultimately protecting users from vulnerabilities that could lead to unauthorized access or data breaches.
