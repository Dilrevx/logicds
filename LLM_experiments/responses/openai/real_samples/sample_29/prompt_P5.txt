Below is one acceptable repair. In this fix we require that the reply’s destination (address and port) exactly match the original forwarded query’s destination stored in f->sentto. (In this example we assume that the reply contains a variable “reply_dest” with the destination address information for the DNS reply. In your environment you may need to adjust that name and the size accordingly.) 

<repair>
    if (f->sentto &&
        /* Check that the reply’s destination (address and port) exactly match the forwarded query */
        memcmp(f->sentto, &reply_dest, sizeof(*f->sentto)) == 0 &&
        f->new_id == id &&
        (!hash || memcmp(hash, f->hash, HASH_SIZE) == 0))
      return f;
</repair>

This extra check ensures that all the query attributes (including the destination address/port) are used when matching a reply, in line with RFC5452 and fixing the DNS cache poisoning vulnerability.
