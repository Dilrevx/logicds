The repair ensures that the certificate is only trusted via the NoCheck extension if it is actually part of the validated chain. Here’s the step-by-step explanation:

1. The original code simply checked whether the certificate’s NoCheck extension was set and, if so, disabled OCSP verification by setting verify to NO_VERIFY. This was dangerous because it allowed any certificate with the NoCheck extension—even one unrelated to the certificate chain—to bypass verification.

2. In the patched code, we first still verify that we are in the OCSP verification context (i.e. verify is set to VERIFY_OCSP) and that the NoCheck extension is present.

3. The critical addition is the call to X509_check_ocsp_responder_cert(cert, chain, 0). This helper function checks that the certificate is actually authorized as an OCSP responder for the certificate chain provided. Only if the certificate is part of the trusted chain (i.e. the function returns 1), do we then bypass further OCSP verification for that certificate.

4. By including this additional chain validation step, the patch prevents a malicious responder from using a certificate with the NoCheck extension to bypass security controls on an unrelated certificate chain.

Overall, the repair effectively ensures that the NoCheck extension is only honored when it is safe to do so—specifically when the OCSP responder’s certificate is properly associated with the certificate chain being verified. This prevents attackers from exploiting the NoCheck extension to disable OCSP verification for unrelated certificates, thereby mitigating the described vulnerability.
