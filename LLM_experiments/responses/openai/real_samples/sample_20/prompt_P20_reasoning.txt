The primary issue in the original code was how the subject alternative names (SAN) list was being iterated. In the buggy version, the code sets the iterator pointer to the address of the SAN list head (using “&crt->subject_alt_names”) instead of the list head itself (using “crt->subject_alt_names”). This mistake could result in iterating over an incorrect memory location, missing valid entries or, worse, not terminating correctly. Essentially, if the list is not properly traversed, legitimate certificate names might be overlooked, leading to a false negative during certificate name verification. This is considered a logical vulnerability because it incorrectly evaluates the certificate’s names, possibly allowing certificates with mismatched names to be treated as valid.

In the repaired code, the for loop initialization for iterating over the SAN list was corrected by assigning: 

  for( cur = crt->subject_alt_names; cur != NULL; cur = cur->next )

This change ensures that the iteration starts at the actual head of the SAN list rather than the address where the pointer is stored. As a result, the loop will iterate through all the valid SAN entries that the certificate has provided. If a matching common name (CN) is found, the loop is broken successfully, preventing an erroneous flag from being set. On the contrary, if no match is found after traversing the entire list, the code correctly sets the MBEDTLS_X509_BADCERT_CN_MISMATCH flag, ensuring that name mismatches are detected.

The rest of the function (the branch dealing with the subject name when there’s no SAN extension) was already correctly iterating through the linked list, so no changes were needed there. By fixing the erroneous pointer initialization for the SAN list, the vulnerability is addressed. This repair is crucial since failing to properly iterate over the SAN entries could allow the certificate verification logic to miss a valid CN match, thereby either flagging a valid certificate as invalid or (in worst-case scenarios) permitting an invalid certificate to pass verification.

Overall, the repair ensures that the certificate's SAN entries are properly validated, which is critical for enforcing the correct identity of the certificate subject. By correcting how the linked list is traversed, the function now thoroughly checks all available CN values — both within the SAN and subject fields — guaranteeing that a proper certificate name match is found or flagged appropriately.
