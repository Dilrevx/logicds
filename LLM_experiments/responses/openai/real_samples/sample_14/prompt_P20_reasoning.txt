The repair begins by checking whether the CCS (Change Cipher Spec) message is permitted at this point based on an internal flag. The vulnerability was due to processing a CCS message even when it shouldn’t be allowed, potentially leading to a state where the record appears valid before the proper conditions for a CCS message were met.

1. First, the revised code checks if the received record’s type is CCS. Then, before further processing, it tests whether the flag SSL3_FLAGS_CCS_OK is set within the session state (s->s3->flags). If this flag is not set, the code immediately raises an error using SSLerr with SSL_R_CCS_RECEIVED_EARLY, and it goes to the error handling label (f_err). This effectively prevents processing an unexpected or early CCS record.

2. If the flag condition passes (meaning CCS messages are acceptable in the current state), the code then validates that the CCS record is exactly one byte long with offset zero and that the byte matches the expected value (SSL3_MT_CCS). This ensures the CCS record is well-formed and prevents any malformed or tampered records from being processed.

3. Next, the code checks that a new cipher has been negotiated (s->s3->tmp.new_cipher != NULL). Processing a CCS without a negotiated new cipher indicates an invalid state and, if encountered, results in an error.

4. Once these conditions are satisfied, the record’s length is reset and, if a message callback is installed, it is notified about the receipt of the CCS message. The critical state flag s->s3->change_cipher_spec is then set to indicate that the CCS has been processed.

5. Finally, it calls ssl3_do_change_cipher_spec(s) to switch the cipher spec as part of the SSL/TLS handshake. If this operation fails, it goes to an error, otherwise, it restarts the loop to process subsequent messages.

By adding this initial flag check and detailed validations, the repair ensures that a CCS message is only processed when the protocol state explicitly allows it. This prevents an attacker from sending an out-of-sequence or malicious CCS message that might otherwise trigger undefined behavior or a downgrade in security context.
