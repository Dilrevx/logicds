The repair adds an extra condition that verifies whether the password field (passwd) is empty. Previously, the code only checked if the user buffer was empty. This meant that if a connection presented a non-empty user but an empty password, the check would pass, allowing an LDAP unauthenticated bind. In other words, attackers could bypass the authentication by supplying an empty password.

By adding the condition:

  cherokee_buffer_is_empty(&conn->validator->passwd)

the function now ensures that both the user and password are provided before proceeding. If either field is empty, the function will return ret_error, effectively blocking an unauthenticated bind attempt.

This fix is important because LDAP usually distinguishes between valid and invalid bind attempts based on both username and password. A valid LDAP authentication should not allow a case where one of these components is missing. Ensuring that the password field is not empty prevents attackers from circumventing the authentication process by simply providing a username without a password.

In summary, the repair strengthens the security of the LDAP login mechanism by ensuring that an empty password cannot be used to bypass authentication.
