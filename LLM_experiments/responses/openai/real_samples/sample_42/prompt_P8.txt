Below is one acceptable repair. In this fix we no longer grant a “free‐pass” to any NAS message sent without integrity protection. In other words, if the security header indicates a “plain” NAS message then the message is logged and immediately rejected rather than “whitelisting” a few message types. (In your deployment you may wish to allow one or two specific NAS messages to be processed without integrity protection so long as application‐specific checks are done—but the change below is a simple, safe fix to close the vulnerability.) 

<repair>
  if (sec_hdr_type == LIBLTE_MME_SECURITY_HDR_TYPE_PLAIN_NAS) {
    logger.error("Received NAS message MSG_TYPE=%02X with plain NAS header. Integrity protection is missing!", msg_type);
    return;
  }
</repair>

This change forces the system to require integrity protection on all incoming NAS messages and thereby closes the vulnerability found in the original code.
