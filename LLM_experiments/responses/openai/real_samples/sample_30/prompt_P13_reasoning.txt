The repair changes the parameter passed into the CRL retrieval functions from subject to issuer. In the original code, the function calls were made using the subject field (X509 name) when obtaining CRLs (Certificate Revocation Lists), which led to the vulnerability. The vulnerability stems from checking the same field (subject name) twice instead of checking the issuer in one of the calls. This means that valid CRLs where the issuer field is critical to the revocation check could be ignored, potentially allowing the connection to proceed even if a certificate has been revoked.

In our repair, we replace subject with issuer in both function calls. This change ensures that when the library retrieves CRLs from the X509_STORE, it uses the CRL’s issuer field properly. By doing so, the CRL is accurately matched against the issuer of the intended certificate rather than its subject. This correction means that if a certificate’s revocation list is issued by a trusted authority, it will be correctly recognized and applied, thereby protecting against connections that could otherwise be established using a revoked certificate.

Specifically:
1. For OpenSSL version 1.1.0 and above, we call X509_STORE_CTX_get1_crls with issuer as the parameter.
2. For OpenSSL version 1.0.0 up to 1.1.0, we call X509_STORE_get1_crls with issuer.
3. For OpenSSL versions earlier than 1.0.0, we keep the placeholder code that advises an upgrade.

This change effectively fixes the vulnerability by ensuring that the check is performed against the proper CRL field. Instead of mistakenly reusing the subject name in both cases (which did not correctly verify against the CRL’s issuer field), the new code ensures a proper lookup based on the issuer. This adjustment guarantees that CRLs are correctly fetched and applied during the TLS certificate validation process, preventing clients with revoked certificates from establishing a secure connection.

Thus, the repair ensures robustness and strengthens the TLS verification process by aligning the CRL retrieval with the intended use of the certificate issuer field rather than redundantly using the subject field.
