The repair adds a conditional check to ensure that the client does not accept an authentication success if the authentication method was considered trivial and if the client’s configuration explicitly disallows such methods.

Here’s what the repair does step-by-step:

1. After logging that a successful authentication message was received, the repair immediately checks whether trivial authentication is disallowed (using the flag client_options.disallow_trivial_auth) and whether the last authentication type was trivial (compared against the constant AUTH_TYPE_TRIVIAL). This prevents a scenario where a trivial or less secure authentication method might be accepted.

2. If both conditions are met (meaning the client has flagged trivial authentication as unacceptable, and the session indeed used a trivial method), the repair logs an error message. Following this, it terminates the session by calling disconnect with an appropriate message. This stops any further processing and ensures that a session attempting to use only trivial authentication does not proceed.

3. Only if the session passes these security checks (i.e., trivial authentication is either allowed or not used) does the repair then continue with marking the authentication as done. It sets ses.authstate.authdone to 1, updates the client session state, and resets the last authentication type to AUTH_TYPE_NONE as before.

This conditional check is critical for preventing an attack vector. Without this verification, an attacker could potentially use a forwarded agent or exploit lax server-side policies to log in using a weak authentication method, bypassing more secure protocols like FIDO2 tokens. By enforcing that trivial authentication methods are either explicitly allowed or blocked, the repair mitigates the risk of unauthorized access through a non-compliant method.

In summary, the new check ensures that if trivial authentication is not acceptable per client configuration, any authenticated session using such methods is immediately terminated. This preserves the integrity of the authentication process and prevents potential exploitation where a bypass of stricter security protocols might otherwise occur.
