Below is one example of a repair that avoids automatically restarting SRTP on replay‐related errors. Automatically restarting the SRTP session here resets the replay protection window – an action that an attacker might be able to force by injecting old packets. In this fixed version the code simply logs the replay error and drops the offending packet rather than reinitializing the SRTP context.

<repair>
    if (srtp->probation_cnt > 0 &&
        (err == srtp_err_status_replay_old ||
         err == srtp_err_status_replay_fail))
    {
        /* 
         * Fix: Do not restart SRTP automatically.
         *
         * Restarting the SRTP context here resets the replay protection window,
         * which could be exploited by an attacker to replay previously seen packets.
         * Instead, log the event and drop the packet.
         */
        PJ_LOG(5, (srtp->pool->obj_name,
                   "Detected SRTP replay attack (err=%s), packet dropped",
                   get_libsrtp_errstr(err)));
        return err; /* Abort processing of this packet */
    }
</repair>
