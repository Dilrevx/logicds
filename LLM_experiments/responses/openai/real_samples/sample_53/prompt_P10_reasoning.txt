The repair adds an explicit check for an encoded forward slash in the URI. This vulnerability hinged on attackers using a URI containing “%2F” (or “%2f”) to bypass URL validation. Here’s how the fix works:

1. Immediately after logging the initial trace message, the code now uses the C library function strcasestr() to search the input URI (sr->uri) for the string “%2F”. The strcasestr() function is chosen because it performs a case-insensitive search, catching both “%2F” and “%2f” variations.

2. If an encoded forward slash is found in the URI, this new check logs another trace message indicating that the URL has an encoded forward slash. It then sets the HTTP status to MK_CLIENT_FORBIDDEN and returns MK_PLUGIN_RET_CLOSE_CONX, effectively closing the connection. This preemptive action stops any further processing of a crafted URI that could bypass the existing security check implemented later in the function.

3. If no encoded forward slash is found, the code continues with the original URL validation logic (mk_security_check_url()) and thereafter the hotlinking validation. This means the new check is an additional layer rather than a replacement, ensuring the original functionalities remain intact.

By adding this additional gateway check early in the function, the repair mitigates the vulnerability by ensuring that any URI containing an encoded forward slash is immediately flagged as malicious, preventing further interaction with the system that could allow bypassing access restrictions.
