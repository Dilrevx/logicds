The repair removes the dependency on checking the revocation date tied to the local clock. In the original code, when it found that the certificate’s serial number matched an entry in the Certificate Revocation List (CRL), it then checked whether the current time was past the revocation date (mbedtls_x509_time_is_past(&cur->revocation_date)). This introduced a vulnerability: an attacker who manipulates the local clock might force a revocation to be ignored or incorrectly applied, depending on the manipulated time.

In the repaired code, we simply remove the check that uses the local clock. When a matching serial number is found, the function now immediately returns that the certificate is revoked (return(1)). This change ensures that if a certificate’s serial number appears in the CRL, it is unconditionally regarded as revoked regardless of the local system time.

By eliminating the time-based check, the code is no longer vulnerable to an attacker’s manipulation of the local clock. It prevents attackers from bypassing revocation by setting the system clock to a time before the revocation_date. This direct approach to verifying revocation makes the certificate validation more robust and secure, ensuring that the CRL’s integrity is maintained without relying on external clock values.
