The repair adds a single line that copies the ACL file setting from the default listener to the newly allocated listener. In the original code, the properties of the default listener were copied over for most settings, but the acl_file property was omitted. As a result, when the MQTT broker was started with per_listener_settings set to true, it would not apply the acl_file (access control list file) from the default listener to the active listener. This created a vulnerability where the ACL rules were bypassed—even when an ACL file was specified—because the listener ended up without the intended ACL restrictions.

In the repaired code, you can see the following key line:

  /* FIX: Copy the ACL file from the default listener so that ACL rules are not bypassed */
  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;

By explicitly copying the acl_file from the default listener into the active listener configuration, we ensure that any ACL rules defined are in effect for the listener. This mitigates the vulnerability because the default listener’s security settings, including access control, are now correctly inherited by the new listener. Consequently, if per_listener_settings is true and the default listener has an ACL file configured, that ACL file will be enforced rather than being ignored.

Additionally, the remaining settings related to TCP/TLS configurations and security options continue to be copied as before, so the repair is minimal yet effective, directly addressing the oversight in copying the ACL file setting. This ensures that the Eclipse Mosquitto broker behaves as intended with proper ACL enforcement, thereby repairing the security flaw.
