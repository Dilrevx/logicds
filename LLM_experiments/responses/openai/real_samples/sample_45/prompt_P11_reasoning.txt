The repair adds a critical line that copies the ACL file setting from the default listener (if one is set) into the individual listener’s configuration. In the original code, when per_listener_settings was enabled and the configuration was using the default listener with an acl_file specified, that ACL file was never applied. This meant that even if an administrator had provided an ACL file for the default listener, the listener configuration would not enforce any ACL rules, allowing potential ACL bypass.

Here’s a breakdown of how the fix works:

1. The original code copies many configuration settings from the default listener to the active listener (like max_connections, TLS settings, security options, etc.) but omitted copying the acl_file field. By adding a line that assigns the default listener’s acl_file to the active listener:
  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;
this ensures that if an ACL file has been specified in the default listener configuration, it is correctly applied to the actual listener in use.

2. By applying the ACL file from the default listener configuration to the listener structure that is actually utilized for client connections, the fix prevents the scenario where the ACL file is accidentally ignored. This addresses the vulnerability where an attacker could target an ACL bypass due to misconfiguration or oversight in applying security policies.

3. In summary, the repair ensures consistent policy application across configurations by explicitly including the ACL file setting. With the acl_file now correctly copied, the access control lists defined for the default listener will be enforced by the broker, preventing unauthorized access that could occur if the ACL settings were skipped.

Thus, this small but significant change makes sure that even when per_listener_settings is enabled, the MQTT broker correctly applies the intended access control rules, thereby eliminating a potential security vulnerability.
