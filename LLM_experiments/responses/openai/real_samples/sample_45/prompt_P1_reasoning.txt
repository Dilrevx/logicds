The repair addresses the vulnerability by ensuring that when per_listener_settings is active and the default listener is used, the access control list (ACL) file specified in the default listener is correctly transferred to the specific listener instance. Previously, the default listener’s acl_file was completely ignored, creating an opportunity for privilege escalation or unauthorized access because the appropriate ACL rules were not enforced.

In the buggy code, all configurations were being copied from config->default_listener to the last listener in the config->listeners array, such as max_connections, protocol, and various TLS settings. However, the acl_file field was not included among these assignments. This omission meant that if a user had defined an acl_file in the default_listener configuration, it would not be applied to any of the listeners that relied on default settings. Consequently, even if an acl_file was intended to limit or restrict broker access, that crucial security measure would be bypassed, creating a potential vulnerability.

The repair introduces an explicit assignment that copies the acl_file from the default listener into the specific listener configuration. By adding the line:
  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;
we ensure that any ACL rules defined in default_listener.acl_file are effectively applied to the listener in use. This action is vital for maintaining security because ACLs (Access Control Lists) serve as essential mechanisms to control who can publish or subscribe to topics on the MQTT broker. Not enforcing these restrictions could allow an unauthorized client to bypass authentication restrictions, thereby compromising the integrity and confidentiality of the system.

In this context, the acl_file assignment is done immediately after copying the rest of the security_options settings. This placement makes it clear that the ACL file should be treated as a fundamental part of the overall listener configuration, similar to other security parameters. Placing it after the existing security configurations emphasizes its importance and ensures that its value is not inadvertently overwritten by later code.

Furthermore, this repair is implemented in a way that is consistent with the overall approach of copying default values. It does not introduce any conditional logic or alter the flow of configuration initialization beyond the intended correction. This minimal change strategy reduces the likelihood of unintended side effects because the change is localized to the initialization logic where the default listener’s settings are applied.

By making sure that config->listeners[...].acl_file is set to config->default_listener.acl_file, the repair removes the possibility of an ACL bypass scenario. With this correction, if the default listener’s acl_file is specified and per_listener_settings is true, the intended restrictions defined within the acl_file will be active, thereby preventing unauthorized access. Overall, this change solidifies the security posture of Eclipse Mosquitto by ensuring that the configuration behavior adheres to the expected security design, avoiding any loopholes that would allow a malicious user to bypass access control restrictions.
