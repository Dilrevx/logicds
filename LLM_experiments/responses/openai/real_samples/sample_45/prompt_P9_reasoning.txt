The main change is the addition of this line:

  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;

Originally, when the default listener was used, any ACL settings defined in the default listener (specifically the ACL file) were not copied over to the new listener instance. This left a potential ACL bypass vulnerability when per_listener_settings was set to true. Attackers could exploit this situation by having the default listener configured with an acl_file (which would normally enforce access control), yet the actual listener in use didn't enforce these ACL settings because the acl_file value wasn’t applied.

By explicitly copying the acl_file from the default_listener to the new listener configuration, the repair ensures that the intended ACL rules and permissions are properly loaded and enforced. In other words, if the default listener is set to use an ACL file, the new listener instance also receives and uses that ACL file, thereby eliminating the ACL bypass path.

Additionally, the remainder of the code continues to copy over other vital connection and security settings like max_connections, protocol, TLS settings, and authentication options from the default_listener to the new listener. This consistency in applying configuration parameters is crucial not only for functionality but also for security. The repair now treats the acl_file configuration as essential as these other settings.

In summary, the repair:
1. Identifies and adds the missing step for copying over the ACL configuration (acl_file) from the default to the active listener.
2. Ensures that all necessary security settings, including ACLs, are consistently applied to every listener configuration.
3. Closes the security gap that originally allowed for ACL bypass when using the default listener with per_listener_settings enabled, thus mitigating the vulnerability described.

This change prevents a scenario where malicious clients might have been inadvertently granted unintended access because the ACL file that was supposed to restrict access was not applied, thereby enforcing stricter and intended access controls aligned with the configuration.
