The vulnerability occurred because when using per_listener_settings, the code did not apply the acl_file setting from the default listener to the new listener. This meant that if a user configured an acl_file on the default listener, it would be ignored when the default listener was in use, effectively bypassing the ACL restrictions.

To repair this, the changes made in the code ensure that the new listener explicitly receives the acl_file value from the default listener. Here’s how the repair works step-by-step:

1. The original code was copying various properties from the default listener to the new listener (such as max_connections, protocol, and TLS settings). However, it was missing the copy operation for acl_file. If the default listener was meant to enforce certain access control lists (ACLs) via an acl_file, the new listener wasn’t implementing those ACL restrictions since its acl_file field wasn’t being set.

2. The repair adds a new line:
  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;
This line explicitly copies the acl_file setting from the default listener over to the new listener. Thus, when per_listener_settings is true and the default listener is being used, the proper ACL file is assigned to the new listener.

3. By copying the acl_file, the repair ensures that any access control configurations specified in the acl_file are not bypassed but are properly applied to the listener, closing the gap that allowed an ACL bypass.

4. The rest of the code remains unchanged, ensuring that no other part of the system’s configuration is inadvertently affected by the repair. The overall structure still ensures that all settings—including TLS and security options—are copied from the default listener, maintaining the intended behavior.

In summary, the repair fixes the vulnerability by ensuring that the ACL file configured on the default listener is not ignored when per_listener_settings is enabled. The new listener now gets the same acl_file value as the default listener, ensuring that any intended ACL restrictions are enforced correctly.
