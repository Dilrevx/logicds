The repair involves adding a single assignment statement that copies the ACL file setting from the default listener to the newly created listener. Previously, when per‐listener configuration was enabled, the ACL file parameter from the default listener was never copied over. This oversight meant that even if an ACL file was specified for the default listener, it wouldn’t be applied to the listener object being created. As a result, if other parts of the system assumed that each listener would have proper ACL settings, a listener without an ACL file could treat access control as if it were not enabled, thereby exposing a potential security flaw.

In the corrected code, right after setting several parameters such as maximum connections, protocol, socket domain, and username configuration, the repair adds a step to explicitly set the ACL file. This added line explicitly assigns the value of the ACL file from the default listener structure to the corresponding field in the listener array for the new listener. This ensures that if an ACL file was configured for the default listener, it is properly propagated to the listener that is being created. By doing so, it guarantees that all the expected security configurations are in place for that listener prior to use.

This change fixes the vulnerability by ensuring that the ACL file – a critical parameter for controlling client access – is never unintentionally omitted. Without this, it was possible for the system to mistakenly bypass ACL enforcement if a per‐listener configuration was used, and the default ACL file configuration was inadvertently ignored. Ensuring that the ACL file is copied over eliminates any risk of an ACL bypass that arises from such a misconfiguration.

The rest of the existing configuration process remains untouched. Other fields like TLS settings and security options are set as before, and defaults are applied later in the function for the user and log type. Thus, the integrated change is both minimal and non-intrusive; it does not alter the overall behavior of the listener configurations, but rather ensures that the intended security measure is carried through properly.

In summary, the repair adds a specific assignment to set the ACL file field when creating a new listener configuration based on the default settings. This adjustment guarantees that the ACL file setting is not accidentally omitted, thereby maintaining the integrity of the access control mechanism and preventing potential unauthorized access that could arise from a missing ACL configuration.
