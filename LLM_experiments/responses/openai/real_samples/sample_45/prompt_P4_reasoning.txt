The original vulnerability arose because when using per_listener_settings with a default listener specifying an ACL file, the ACL file was not copied over to the new listener configuration. This omission leads to a situation where the ACL file defined by the default listener is effectively ignored. In turn, this permits an ACL bypass, as the security settings intended by the administrator do not get applied to new listeners properly.

To address this, the repair introduces an explicit copying of the ACL file from the default_listener to the most recently added listener (listeners[config->listener_count-1]). Specifically, we added the following line:

  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;

This line ensures that if the default listener has an ACL file configured, then this setting is carried over to the new listener configuration. By doing so, the security policy defined in the ACL file is enforced for the listener being initialized. Without this assignment, any new listener based on the default settings would lack the ACL restrictions, potentially granting unintended access privileges.

The repair is minimalistic and strategically placed to alter as little of the existing functionality as possible while securely propagating all relevant configuration settings. Notably, the code already sets up many of the appropriate connections – such as max_connections, protocol, and various TLS-related settings – from the default_listener. However, the oversight was the absence of the acl_file assignment. By mirroring the pattern observed with the other configuration fields, the repair reinforces consistency across the configuration assignment process.

This change is crucial because ACL files are used to define fine-grained access control policies, determining what topics clients can publish or subscribe to on the Mosquitto broker. Ignoring the ACL file on the listener means that even if the administrator intended to restrict access via that ACL file, the listeners would operate without these restrictions, thereby compromising the security posture of the application.

Additionally, this change caters specifically to environments where per_listener_settings is enabled and the default listener is actively used by ensuring that even defaults intended to enforce security come into effect. The correction demonstrates a typical security best practice: configuration values that contain security policies must always be propagated faithfully between related configuration entities. Any failure to do so might inadvertently weaken the security model, potentially leading to unauthorized access or data breaches.

Finally, the repair maintains backward compatibility and does not modify any other functionality of the configuration process. It solely fixes the ACL file handling issue, ensuring that the logic remains coherent and that every listener configuration has all the necessary security settings. This precise and minimalistic approach avoids introducing any new side effects while directly addressing the reported vulnerability, thus reinforcing the robustness of the MQTT broker against potential attacks involving ACL bypass.
