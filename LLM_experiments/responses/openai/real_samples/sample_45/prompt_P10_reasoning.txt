The repair adds a critical assignment that propagates the default listener’s ACL file setting to the actual listener structure that Mosquitto uses during runtime. In the original buggy code, if the default listener was being used (i.e. when per_listener_settings was true) and an ACL file was specified in the default listener configuration, that ACL file was never copied over to the listener instance. Consequently, ACL checks would bypass the intended restrictions because the ACL file was effectively ignored.

Specifically, the fix is implemented by adding this line:

  config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;

This statement is placed in the code block where a new listener is created from the default listener settings. Here’s how it helps:

1. Propagation of the ACL File:
  The default listener structure (config->default_listener) might have an ACL file set via an option in the configuration file. The original process did not assign this ACL file to the newly allocated listener, leading to the ACL bypass vulnerability. By explicitly copying the acl_file value from the default listener to the new listener (config->listeners[...]), the ACL settings are properly applied, ensuring that access control is enforced as expected.

2. Maintaining Consistency with Per-Listener Settings:
  The vulnerability arises when per_listener_settings is set to true. In such cases, each listener should respect its own individual settings (including ACLs). The fix ensures that the ACL configuration is not lost by associating the ACL file with the listener. This maintains consistency between the default and the per-listener configurations.

3. Integrity of Security Configurations:
  ACL files play a crucial role in determining which actions clients are permitted to perform on a topic basis. Without this fix, clients might experience unintended access authorization (or lack thereof), resulting in a security breach. By rectifying the oversight and ensuring the ACL file is attached to the listener, the repair guarantees that all per-listener security settings (including ACL files) are honored during connection authorization.

In summary, the repair directly addresses the ACL bypass by ensuring that the ACL file provided in the default listener configuration is no longer ignored. It does so by adding a straightforward assignment that copies the ACL file reference to the actual listener configuration used by Mosquitto. This fix maintains the integrity of access control measures, preventing unauthorized connections or actions that could arise from the previously ignored ACL file setting.
