The vulnerability arose because the original code compared the OCSP response serial with the certificate serial using the sizes from both fields (rserial.size and cserial.size), without verifying that the certificate’s true serial length (as returned in variable t) exactly matches the OCSP response serial length. This means that if the gnutls_malloc allocation leaves behind trailing bytes, the certificate’s serial might have extra data that isn’t validated against the OCSP serial. An attacker could exploit this discrepancy by using trailing bytes to bypass validation.

The repair addresses the issue in the following ways:

1. The function gnutls_x509_crt_get_serial returns the certificate's serial in buffer cserial.data and its length in the variable t. Instead of using cserial.size, the repaired code now uses t, which represents the exact length of the serial number as parsed from the certificate.

2. The conditional check has been updated so that the OCSP response’s serial (rserial.size) must match the true serial length t. This ensures that any extraneous trailing bytes in the certificate’s allocated buffer do not lead to an incorrect successful match.

3. In addition, the memcmp function is adjusted to compare exactly t bytes between cserial.data and rserial.data. This precise byte-level comparison prevents any mismatch caused by differences in buffer size or trailing garbage.

By enforcing that rserial.size equals t and that the memory comparison is performed using t bytes, the repair ensures that both serials are strictly validated against each other with exact lengths. This prevents an attacker from providing an OCSP response with a serial number that might otherwise match a part of a poorly terminated certificate serial number due to trailing bytes.

In summary, the change tightens the certificate serial validation by:
• Verifying that the OCSP response serial length exactly equals the actual certificate serial length.
• Adjusting the memory comparison to exactly the length provided by gnutls_x509_crt_get_serial (stored in t).

This repair eliminates any opportunity for a bypass caused by trailing bytes, ensuring that the certificate and OCSP response serials match exactly, both in content and in length.
