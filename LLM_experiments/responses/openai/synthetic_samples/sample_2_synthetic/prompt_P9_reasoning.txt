The original code started iterating from index 1 of the certificate chain, effectively ignoring the leaf certificate (index 0) when checking for invalid policies. This allowed a malicious Certificate Authority (CA) to embed invalid certificate policy extensions in the leaf certificate, bypassing checks that were supposed to validate policies on every certificate in the chain. If the leaf certificate contained an invalid policy, the vulnerability allowed it to be silently ignored, which could be exploited to circumvent certificate policy validation.

In the repaired code, the iteration has been modified to start at index 0 instead of index 1:

• Previously: The loop used "for (int i = 1; i < ctx.chain.size(); i++)", which skipped the leaf certificate.
• Now: The loop is changed to "for (int i = 0; i < ctx.chain.size(); i++)", ensuring all certificates in the chain, including the leaf certificate, are checked.

This alteration directly addresses the vulnerability by validating every certificate in the chain. The callback cbFailIf will now be applied to each certificate in the chain—ensuring that if any certificate (including the leaf) is found to be null or have an invalid policy (determined by a specific flag check on its hashCode()), the appropriate error handling is invoked.

Thus, this repair ensures that policies are enforced consistently across all certificates in the chain, preventing a situation where a malicious actor’s CA could deliberately embed invalid policies in the leaf certificate (or any certificate) to bypass critical validations.
