The original code loop started at index 1 of the certificate chain:

  for (int i = 1; i < ctx.chain.size(); i++)

This meant that the very first certificate (the leaf certificate) was excluded from the validation. The reasoning behind this approach was likely to intend to check only intermediate certificates for invalid policy extensions. However, per the vulnerability description, malicious CAs could deliberately include invalid policies in the leaf certificate to bypass policy checking. Since the leaf was not checked, this potentially allowed a malicious certificate to be accepted by exploiting the gap in validation.

In the repaired code, the loop now begins at index 0:

  for (int i = 0; i < ctx.chain.size(); i++)

By starting the loop at 0, the entire certificate chain is now validated, including the leaf certificate. This change ensures that any certificate in the chain — not just the intermediary certificates — is scrutinized for invalid policy extensions. The check involves verifying that the certificate is not null and that its hash code does not contain the flag EXFLAG_INVALID_POLICY, which might be used to represent an invalid certificate policy.

The corrected check:

  cbFailIf(x == null || (x.hashCode() & EXFLAG_INVALID_POLICY) != 0, ctx, x, i, X509Error.X509_V_ERR_INVALID_POLICY_EXTENSION);

ensures that even if a malicious CA attempts to disguise the leaf certificate with incorrect or malicious policies, these will not be silently ignored. Instead, the certificate is properly flagged during the validation process, and the corresponding error code is reported.

In summary, the primary fix is ensuring the iteration covers the complete certificate chain from the leaf to the root. This repair prevents an attacker from bypassing policy checks by including malicious invalid certificate policies in the leaf certificate. It closes the vulnerability by removing the loophole where the leaf certificate was never validated for those critical policy constraints.
