The repair changes the loop that checks for invalid certificate policies. In the original code, the for‐loop started at index 1 of the certificate chain:

  for (int i = 1; i < ctx.chain.size(); i++)

This means the leaf certificate (at index 0) was never checked for the invalid policy flag. Due to this oversight, a malicious Certificate Authority (CA) could craft a leaf certificate with deliberately invalid policies to bypass policy checking. Since certain policy checks were then skipped, the intended certificate validation would be weakened.

In the repaired code, the loop now starts at index 0:

  for (int i = 0; i < ctx.chain.size(); i++)

By iterating from 0, every certificate (including the leaf) is examined using the cbFailIf() function. This ensures that if any certificate in the chain contains the invalid policy marker (represented by the bit mask check using EXFLAG_INVALID_POLICY), an error is properly raised. As a result, if even the leaf certificate is compromised, the vulnerability is caught and reported.

In summary, the repair addresses the vulnerability by:
1. Including the leaf certificate in the policy validation process.
2. Preventing a potential attack where a CA could maliciously bypass policy checks using an invalid certificate policy on the leaf certificate.
3. Enhancing the overall robustness of certificate policy checking across the entire chain.

This subtle change ensures that the security assumptions in the certificate verification process are maintained, thereby mitigating the risk associated with an attacker using invalid policies to circumvent checks.
