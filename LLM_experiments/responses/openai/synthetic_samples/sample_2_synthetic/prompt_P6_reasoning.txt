The repair changes the certificate verification loop so that it starts at index 0 instead of index 1. In the original code, the loop began with i = 1, which meant that the leaf certificate (typically at index 0) was not being checked for the presence of an invalid certificate policy—an oversight that allowed a malicious CA to include an invalid policy in the leaf certificate to bypass policy checking. By modifying the loop to start at i = 0, the fix ensures that every certificate in the chain, including the leaf, is properly validated. This prevents an attacker from exploiting this gap by inserting invalid certificate policies into the leaf certificate, thereby addressing and mitigating the vulnerability.
