The repair adds an additional check to ensure that a ChangeCipherSpec (CCS) message isn’t processed more than once. Here’s a walkthrough of the changes:

1. Before processing the finished message, the code checks a flag (state.ccsReceived) to verify whether a CCS message has already been received. If the flag is true, it immediately logs an error message and aborts the handshake by returning an error code. This prevents attackers from injecting a duplicate CCS message that might otherwise alter the handshake state.

2. If no duplicate is detected, the code sets the flag (state.ccsReceived) to true. This marks that the valid CCS message has already been processed. By doing so, any later CCS messages that might be injected will trigger the check and cause an error, effectively blocking the vulnerability.

3. The code then continues with the normal handshake processing by calling ssl3_get_finished() to complete the handshake. This ensures that only a properly ordered handshake sequence is executed.

The core issue with the vulnerability (often referred to as the "CCS Injection" vulnerability) was that OpenSSL did not strictly restrict the processing of CCS messages. Without a mechanism to detect duplicate or injected CCS messages, an attacker could manipulate the handshake to force a zero-length master key, potentially compromising the security of the session. By adding the state.ccsReceived check, the repair prevents any re-processing of CCS messages once the first (legitimate) CCS has been handled.

In summary, the repair implements a simple but effective safeguard:
• It prevents duplicate CCS processing which is the key vector for CCS injection.
• The flag-based approach ensures that the original handshake logic is preserved while adding a guard condition.
• The handshake will be aborted if any attempt is made to inject an extra CCS message, thereby mitigating the vulnerability.

This approach safeguards the connection by ensuring that only a single, valid CCS is accepted, preventing man-in-the-middle attackers from exploiting the handshake process to manipulate the session keys.
