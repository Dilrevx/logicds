Explanation:
Previously the code skipped a byte‐for‐byte comparison when the parameters length was 0. This could allow a certificate that has a NULL algorithm parameters field (correctly encoded as “NULL”, typically non‐empty in DER) to be confused with an empty (or “REAL”) array. The repair removes the “sig_params1.len != 0” condition so that even if the length is 0 the code compares the bytes. In turn, if one side is encoded as a proper ASN.1 NULL (with its nonzero DER encoding) and the other as an absent/empty array, the length check (or the subsequent byte equality) will fail and the certificate is correctly rejected.
