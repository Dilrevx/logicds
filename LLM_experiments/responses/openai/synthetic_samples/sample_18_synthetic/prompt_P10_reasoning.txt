The repair addresses the vulnerability by ensuring that the length of the certificate’s serial number is determined directly from the certificate rather than assuming it matches the length provided by the OCSP response. Previously, the code simply used the length from the OCSP response to allocate a buffer for the certificate serial number. However, this could be exploited if the OCSP response contained extra trailing bytes (leftover from gnutls_malloc), allowing an attacker to bypass the serial check.

Here’s what the repair does step by step:

1. Before retrieving the certificate’s serial number, it performs an initial call to Helper.gnutls_x509_crt_get_serial with a null Datum. This call is used solely to acquire the actual serial length from the certificate. The length is stored in tHolder[0].

2. It then compares the serial length obtained from the certificate with the length provided in the OCSP response (rserial.size). If these lengths differ, the function returns an error. This equality check ensures that no extra trailing bytes in the OCSP response can cause the comparison to pass erroneously.

3. After verifying the serial lengths match exactly, the code allocates a buffer for the certificate’s serial number using the exact length determined in the previous step. Then it makes a second call to actually retrieve the serial number into the properly sized buffer.

4. Finally, the serial numbers from the OCSP response and the certificate are compared. Since the code ensured the serial lengths were exactly the same and correctly retrieved, the risk of trailing bytes causing a false positive in the memory comparison is mitigated.

In summary, by explicitly comparing the serial length obtained from the certificate with the OCSP response and then using that exact length for the serial comparison, the repair prevents an attacker from taking advantage of any additional trailing data. This careful length validation is critical in avoiding vulnerabilities that could otherwise lead to bypassing the intended certificate validation mechanism.
