The repair changes the way the key exchange algorithm list is handled. In the buggy code, if the SSH extension algorithm is found, the code truncates the entire list at that point. This means that if any algorithms follow the extension, they are lost. That behavior is problematic because if the extension isn't negotiated during the handshake (for example, if the other party’s guess was different), dropping the following algorithms forces the system into a degraded mode or even causes the security features to be bypassed—a situation exploited by the Terrapin attack.

The fixed code instead uses a helper function—safeRemoveAlgorithm—to remove just the extension algorithm from the comma-separated list while preserving all the other negotiated algorithms. Here’s how it works:

1. The helper function safeRemoveAlgorithm splits the algorithm list (a string of algorithm names separated by commas) into individual algorithm names.
2. It goes through each item in the list, trimming any extra whitespace (for robust comparison), and appends only those algorithms that do not match the extension algorithm.
3. Finally, it rejoins the filtered list into a comma-separated string.

By using this method, the repair ensures that if the extension algorithm is present, it gets removed from the list without affecting any other algorithms that might be required to negotiate a secure session. This fix effectively addresses the vulnerability by avoiding the premature truncation of the list that could disable or downgrade security features if additional algorithms are removed unintentionally.

Thus, if one side sends the extension optimistically but the other side does not agree, only the extension is discarded rather than abandoning the negotiation with all subsequent algorithms. This prevents an attacker from exploiting the handling flaws in the SSH Binary Packet Protocol (BPP) that could lead to insecure connections.
