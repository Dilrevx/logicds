</repair> 

Explanation:
The original code only triggered an error if the peer’s certificate had signing capabilities ((type & Constants.EVP_PKT_SIGN) != 0). This meant that a client using a Diffie-Hellman (DH) certificate—which does not have the signing bit set—could bypass the requirement for a CertificateVerify message. In the repair the condition is simplified so that if a peer (client) certificate is present, a missing CertificateVerify message is considered a fatal error regardless of the certificate type. This change ensures that even clients with DH certificates must provide a CertificateVerify message, thus fixing the vulnerability.
