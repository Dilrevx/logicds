The repair fixes the vulnerability by ensuring that if an ACL file is specified in the default listener, it is properly applied to the promoted listener. Here’s a walkthrough of the change and why it fixes the issue:

1. Identifying the Vulnerability:
 • The vulnerability occurs when the configuration uses per_listener_settings along with a default listener that has an acl_file defined. In the original code, when the default listener was “promoted” (i.e., its options copied to a separate listener instance), the acl_file was never copied over.
 • As a result, even if the administrator specified an ACL file in the default listener, that file was ignored, leading to an ACL bypass. Clients might then be allowed access without the correct access control in place.

2. The Repair Change:
 • In the fixed code, after setting up various listener parameters such as port, host, TLS settings, and security options, the repair adds one critical line:
  promoted.setAclFile(def.getAclFile());
 • This line takes the ACL file value from the default listener (referred to as def) and sets it on the newly promoted listener (referred to as promoted). This makes sure that any ACL rules intended for the default listener are not lost during the promotion process.

3. How It Fixes the Vulnerability:
 • By copying the acl_file from the default listener to the promoted listener, the patch guarantees that the ACL rules are enforced. This means that if the option per_listener_settings is set to true and the default listener was being used, the ACL file won’t be ignored.
 • This repair closes the ACL bypass vulnerability by ensuring that all listeners, including the promoted listener, use the correct ACL file settings. Consequently, unauthorized access through bypassing ACLs is prevented.

4. Overall Impact:
 • The rest of the code remains unchanged so that the behavior for other settings continues as expected. The repair focuses only on the ACL settings, which is the root cause of this particular access control vulnerability.
 • Administrators relying on ACLs to restrict access will now have their ACL file applied as intended, ensuring that the server properly enforces access control policies.

In summary, the repair simply adds a line to copy the acl_file from the default listener to the promoted listener, thereby preventing the mechanism that caused the ACL bypass vulnerability.
