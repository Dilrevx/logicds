The vulnerability was due to copying all of the default listener's security options (such as the psk file, auth plugin configs, and others) to the promoted listener. When the configuration is set to per_listener_settings, this behavior could allow an ACL bypass. In other words, although the default listener might have an ACL file defined, copying over extra—and potentially conflicting—security configurations into the promoted listener would result in the ACL file being ignored, thereby compromising access control.

Here's what was happening in the buggy code:
• The default listener had more security options (like pskFile, auth plugin configs, etc.) than just the ACL settings.
• If per_listener_settings was enabled and the default listener was used, the promoted listener would inherit these extra settings.
• This inheritance meant that if an ACL file was specified on the default listener, it might be overridden or ignored because of the other copied options, allowing unauthorized access.

What the repair does:
• The repair limits the inheritance from the default listener to only one security option: the password file.
• By calling promoted.getSecurityOptions().setPasswordFile(def.getSecurityOptions().getPasswordFile()) and omitting the other security options (e.g., psk file, auth plugin configs), the repaired code prevents the ACL bypass. This is because the promoted listener will not inadvertently activate or mix in configuration settings that could weaken security.

How the fix addresses the vulnerability:
1. Isolation of Security Parameters: By only setting the password file on the promoted listener, the fix avoids transferring extraneous security parameters from the default listener. This ensures that only intended security measures are enforced.
2. Protection of ACL Settings: Since the remaining security options, which may interfere with ACL processing, are not copied, the ACL file (and related rules) will be honored properly.
3. Minimization of Attack Surface: The reduced configuration brought into the promoted listener minimizes unexpected behaviors that could be exploited. This focused setting diminishes the risk of a configuration mismatch leading to unauthorized access.

In summary, the repair makes the code safer by not copying over all security options from the default listener to the promoted listener, thereby ensuring that ACL settings remain effective and the ACL bypass vulnerability is mitigated.
