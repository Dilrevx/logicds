The vulnerability arose from an incomplete transfer of security settings when applying configurations from the default listener object ("def") to the promoted listener object. In the original code, several parameters—such as password file, PSK file, authentication plugin configurations, and the setting for allowing anonymous access—were properly copied over. However, the ACL (Access Control List) file setting was omitted. This meant that if the default listener had a specific ACL file defined, that file was not passed along to the promoted listener when per-listener settings were enabled. As a result, the promoted listener would not enforce the intended ACL restrictions, potentially resulting in unauthorized access or other security risks.

The repair involves adding a single, straightforward step: copy the ACL file setting from the default security configuration into the promoted configuration. This change ensures that any ACL file specified in the default settings is also applied to the promoted instance, thereby maintaining consistency in security enforcement across configurations.

By including this additional step, the synchronized security settings now fully cover all critical parameters, including the ACL file. This comprehensive propagation of configurations ensures that if a default listener trusts an ACL file for access control, the promoted listener will adopt the same mechanism. The net effect is the mitigation of a bypass vulnerability where the ACL file—a critical element for controlling access—was previously ignored in the promotion process.

In summary, the repair does the following:
1. It first copies all the commonly transferred security configurations from the default listener to the promoted one.
2. Then, it explicitly adds a step to copy the ACL file setting, ensuring that no aspect of the security configuration is left unaddressed.
3. With this extra line, the security contract between default and promoted listeners is fully honored, removing the potential for security misconfigurations.

This change bolsters the application's overall integrity by ensuring that the promotion of a listener's security settings is comprehensive. Even if per_listener_settings is enabled, all necessary security measures—especially those critical for enforcing access control—are uniformly applied across instances, thereby minimizing the risk of vulnerabilities or lapses in security.
