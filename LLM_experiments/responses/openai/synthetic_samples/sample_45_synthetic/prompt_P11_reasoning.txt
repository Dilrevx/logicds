The repair adds a missing assignment that copies the ACL file setting from the default configuration ("def") into the promoted security options. In the original buggy code, several security configuration parameters (such as password file, PSK file, authentication plugin configuration, and whether anonymous access is allowed) are copied correctly. However, the ACL file—the file defining access control rules—was not copied. This omission caused Eclipse Mosquitto to ignore the ACL file when per_listener_settings was enabled and the default listener was used, thus allowing unauthorized access by bypassing the intended ACL restrictions.

By adding the following line:

  promoted.getSecurityOptions().setAclFile(def.getSecurityOptions().getAclFile());

the repair ensures that the ACL file specified for the default listener is properly applied to the promoted configuration. This preserves the intended access control rules, thereby fixing the vulnerability that would otherwise allow privileged or malicious users to bypass ACL checks.

In summary, the repair:
1. Copies the ACL file setting from the default configuration into the promoted configuration.
2. Ensures that all security-related settings are uniformly applied, eliminating any mismatch that could allow an ACL bypass.
3. Prevents the scenario where the default listener’s ACL file is ignored if per_listener_settings is true, thereby maintaining proper access control policies.

This change directly addresses the vulnerability by making sure that the ACL configuration is not inadvertently omitted during the configuration promotion process, thus reinforcing the system’s security posture.
