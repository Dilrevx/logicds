The repair adds an explicit assignment for the ACL file by copying it from the default configuration ("def") into the promoted configuration ("promoted"). Initially, the code only copied several security settings (password file, PSK file, authentication plugin configurations, and the anonymous flag), but it omitted the ACL file. This omission allowed an ACL bypass when the broker was configured with per_listener_settings enabled and a default listener using an ACL file—the ACL configuration was not applied in the promoted settings.

By adding this line:

  promoted.getSecurityOptions().setAclFile(def.getSecurityOptions().getAclFile());

the repair explicitly ensures that the ACL file defined in the source ("def") is propagated to the promoted configuration. This is critical because, with per_listener_settings set to true, inconsistent handling of security options could lead to a situation where the listener uses different ACL rules than intended. An attacker might exploit this misconfiguration to bypass access control checks if the ACL file was disregarded.

In summary, the fix addresses the vulnerability by ensuring that all security-related settings, including the ACL file, are consistently applied. This preserves the integrity of access control policies enforced by the ACL file, preventing unauthorized access.
