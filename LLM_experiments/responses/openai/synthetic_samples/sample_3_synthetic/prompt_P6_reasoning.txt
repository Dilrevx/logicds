The repair adds a check at the beginning that verifies the cipher’s NID is not NID_undef. Since using NID_undef may result in OpenSSL matching the NULL cipher – which would output the plaintext as the ciphertext – the new code immediately returns an error (0) if the cipher’s NID is undefined. This prevents the legacy custom cipher handling from proceeding when the cipher identifier is invalid. In doing so, it stops the fallback mechanism that could return the insecure NULL cipher from the provider. The rest of the code remains unchanged, so if a valid cipher is used, the usual cleanup (freeing the fetched cipher, resetting the context) and legacy handling continues. This modification directly addresses the vulnerability by ensuring an application cannot abuse the system by passing NID_undef to divert the encryption process to the insecure NULL cipher.
