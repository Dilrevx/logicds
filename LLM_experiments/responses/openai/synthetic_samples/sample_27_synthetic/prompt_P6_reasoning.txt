The repair removes the special-case branch that directly calls the detach callback when the socket’s thread ID matches the NodeManager’s thread. In the original code, if sock.tid equaled NodeManager.nmTid(), it would call NodeManager.nmhandle_detach_cb(handle) immediately. This bypasses the event-based cleanup that the remaining branch handles, meaning that sometimes the detachment process did not follow the prescribed sequence (including passing and enqueuing events), leading to improper cleanup of resources. Consequently, if a TCP stream was crafted to hit this branch, the resulting connection could linger in the CLOSE_WAIT state indefinitely since the necessary final cleanup was not triggered.

The repaired code now always creates a detach event via NodeManager.getNetiEventDetach(sock.mgr, sock) and sets the event’s handle to the given handle. The event is then passed to EventPasser.passEvent(event) before being enqueued on the appropriate worker thread with NodeManager.enqueueEvent(sock.mgr.workers[sock.tid], event). This event-driven approach ensures that all detachment actions are handled uniformly, regardless of which thread is processing the disconnect logic.

By using the same event-based mechanism for all cases, the repair prevents any potential divergence in cleanup logic that may otherwise leave socket resources in an undefined state. The event-driven detachment guarantees that all registrations, callbacks, and cleanup operations occur in the correct order and on the proper processing threads. This unified approach mitigates the risk that a specially crafted TCP stream might elicit a behavior (via the alternate direct callback) that does not fully terminate the connection, thus avoiding the indefinite CLOSE_WAIT state.

In summary, the repair ensures that every detach operation goes through the same event processing pipeline, allowing for complete and proper shutdown of the connection. This change removes the vulnerability by preventing any early return or bypass of essential cleanup operations, reducing the impact of malicious or malformed TCP streams that might otherwise leave connections hanging.
