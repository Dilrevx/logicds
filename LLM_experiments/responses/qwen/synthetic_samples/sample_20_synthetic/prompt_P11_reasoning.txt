### Vulnerability Explanation

When verifying the identity of a server using SSL/TLS, the client must ensure that the server's certificate is issued for the correct hostname. This is typically done by checking the Common Name (CN) field in the certificate's subject, or more securely, the DNS names listed in the SAN extension. However, the SAN extension can contain multiple types of names, including DNS names, IPv4 addresses, and IPv6 addresses.

The vulnerability arises because the original code does not check the type of each SAN entry before comparing it to the expected hostname. An attacker could obtain a certificate for an IP address they control and use it to impersonate a domain name, as long as the client does not properly verify the type of the SAN entry.
