This vulnerability arises from the incorrect handling of custom ciphers in OpenSSL versions 3.0.0 to 3.0.5, where the library fails to properly validate the NID (Numeric Identifier) passed to the `EVP_CIPHER_meth_new()` function. If `NID_undef` is mistakenly used, OpenSSL incorrectly matches this to the NULL cipher, which effectively bypasses encryption, leading to plaintext being output as ciphertext.

### Vulnerability Analysis

In the original buggy code snippet, there is no explicit check for the `NID_undef` value when initializing a custom cipher. This oversight allows an attacker to exploit the system by passing `NID_undef`, which results in OpenSSL selecting the NULL cipher instead of the intended custom cipher. The NULL cipher does not perform any encryption, thus rendering the security measures ineffective.
