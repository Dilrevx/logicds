### Vulnerability Analysis

The vulnerability arises from the fact that the client must receive either a `key_share` extension or a `pre_shared_key` extension from the server during the TLS 1.3 handshake. If neither is received, the client should not proceed with the handshake using a default, predictable IKM. Instead, the client should terminate the handshake by sending a `missing_extension` alert. This ensures that the session remains secure and prevents potential eavesdropping or tampering.

### Specification Compliance

According to the TLS 1.3 specification, a client attempting to negotiate using TLS 1.3 must receive specific extensions from the server based on the key exchange method being used:

- **For DHE or ECDHE key exchange**, the server must include a `key_share` extension in the `ServerHello` message. The absence of this extension indicates that the server does not support the agreed-upon key exchange method, and thus, the client should terminate the handshake.
- **For PSK key agreement**, the server must include a `pre_shared_key` extension. If the client initiated the handshake expecting a PSK-based key exchange but did not receive this extension, it should also terminate the handshake.
