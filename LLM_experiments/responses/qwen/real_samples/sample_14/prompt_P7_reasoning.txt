### Understanding the Vulnerability

In a typical TLS handshake, the CCS message is used to indicate that the sender is ready to start using the newly negotiated encryption keys. This message must be sent at specific points during the handshake process, depending on whether the client or the server is sending it. For instance, in the client-server handshake, the client sends a CCS message after sending the `Finished` message and before receiving the server's `Finished` message. Conversely, the server sends a CCS message after receiving the client's `Finished` message but before sending its own `Finished` message.

The vulnerability arises when the CCS message is processed prematurely, before the necessary cryptographic parameters (such as the encryption keys) have been fully established and verified. An attacker can exploit this by injecting a CCS message at an earlier stage, causing the recipient to switch to the new keys prematurely. This can lead to scenarios where the attacker can decrypt or tamper with the subsequent encrypted data, effectively breaking the security guarantees of the TLS protocol.
