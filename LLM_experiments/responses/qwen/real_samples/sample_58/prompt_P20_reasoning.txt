### Original Vulnerability

In the original code, if an error occurred while fetching the user information (`err != nil`), the middleware would respond with a `Forbidden` status instead of an `Unauthorized` status. This is misleading because a `Forbidden` status typically indicates that the server understood the request but refuses to authorize it due to some other reason (e.g., insufficient permissions), whereas an `Unauthorized` status indicates that the request has not been applied because it lacks valid authentication credentials for the target resource.

Additionally, if `userInfo` was `nil` (meaning no user information was found), the middleware did not handle this case explicitly. This could potentially allow requests to proceed without proper validation, leading to security vulnerabilities.
