### Understanding the Vulnerability

ChaCha20-Poly1305 is an authenticated encryption with associated data (AEAD) scheme that combines the ChaCha20 stream cipher with the Poly1305 message authentication code. A key requirement for the security of this scheme is that each encryption operation must use a unique nonce. According to the RFC 7539 specification, the nonce must be exactly 96 bits (12 bytes) long. However, the OpenSSL implementation allows nonces up to 16 bytes long, with only the last 12 bytes being significant. This flexibility can lead to errors where applications mistakenly believe they are using unique nonces when they are not.

The primary issue is that if an application sets a nonce longer than 12 bytes and modifies only the leading bytes while keeping the last 12 bytes constant, it risks reusing the same nonce for different messages. This reuse can compromise the security guarantees of the AEAD scheme, making it susceptible to attacks that can recover plaintexts and forge authentic messages.
