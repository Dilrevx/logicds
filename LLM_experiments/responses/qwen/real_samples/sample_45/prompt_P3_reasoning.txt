The provided repair addresses a specific security vulnerability in the Eclipse Mosquitto MQTT broker configuration handling logic. The vulnerability arises when the `per_listener_settings` option is set to `true`, and the default listener has an `acl_file` (Access Control List file) specified. In such cases, the `acl_file` from the default listener is not being applied to the new listener that is being configured, thus potentially allowing unauthorized access or bypassing intended access controls.

### Vulnerability Explanation

In the original code snippet, when a new listener is being configured based on the default listener settings, several properties from the default listener are copied over to the new listener. These include connection limits, protocol type, socket domain, security options like password and PSK files, and TLS-related configurations. However, the `acl_file` property is missing from this list, leading to the situation where the access control rules defined in the `acl_file` of the default listener do not get applied to the new listener. This can result in a security gap where clients may gain unauthorized access through the newly created listener.

### Repair Solution

The repair involves ensuring that the `acl_file` property is also copied from the default listener to the new listener. This is done by adding the following line to the code:

```c
config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;
```

This line should be inserted immediately after the other properties are copied over from the default listener to the new listener. By including the `acl_file` in the list of properties that are copied, the access control rules defined in the `acl_file` of the default listener will now be applied to the new listener as well. This ensures consistency in access control across all listeners that are configured using the default listener settings.

### Impact of the Fix

Implementing this fix resolves the ACL bypass vulnerability by ensuring that all necessary security settings, including the `acl_file`, are consistently applied to new listeners. This helps maintain the intended security posture of the MQTT broker, preventing unauthorized access and ensuring that only authorized clients can connect and perform actions according to the defined access controls.

### Additional Considerations

While the primary issue addressed here is the ACL bypass vulnerability, it's important to consider additional aspects of the configuration management process. For instance, ensuring that changes to the `acl_file` are properly reloaded without needing to restart the broker, and validating that the `acl_file` paths and permissions are correctly set to prevent tampering or unintended access, are crucial steps in maintaining overall security.

In summary, the repair ensures that the `acl_file` property is included when configuring new listeners based on the default listener settings, thereby addressing the ACL bypass vulnerability and maintaining the security integrity of the MQTT broker.
