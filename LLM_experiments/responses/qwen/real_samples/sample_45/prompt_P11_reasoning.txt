The vulnerability described pertains to the Eclipse Mosquitto MQTT broker, specifically regarding Access Control List (ACL) settings when using the `per_listener_settings` option. The issue arises when this option is enabled, and the default listener is configured with an ACL file. In such cases, the ACL file specified for the default listener is ignored, potentially leading to unauthorized access or other security issues.

To address this vulnerability, the repair involves ensuring that the ACL file specified in the default listener's configuration is correctly assigned to the listener structure. This is crucial because the ACL file defines the rules for client access control, including which clients can publish or subscribe to specific topics. Ignoring this file means that these access controls are not enforced, which can compromise the security of the MQTT broker.

In the provided buggy code snippet, the relevant section initializes various properties of a new listener based on the default listener's settings. However, it does not explicitly copy the `acl_file` property from the default listener to the new listener. This omission is what leads to the ACL bypass vulnerability.

The repair involves adding a line of code to ensure that the `acl_file` property is copied from the default listener to the new listener. Specifically, the line `config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;` is added right before the closing brace of the block where other listener properties are being copied. This ensures that whenever a new listener is created based on the default listener's settings, the ACL file specified in the default listener's configuration is also applied to the new listener.

By making this change, the broker will correctly enforce the access control rules defined in the ACL file for all listeners that inherit settings from the default listener.
