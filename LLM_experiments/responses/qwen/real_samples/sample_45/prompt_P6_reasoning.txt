The provided repair addresses a critical security vulnerability in the Eclipse Mosquitto MQTT broker configuration handling, specifically related to Access Control List (ACL) management when `per_listener_settings` is enabled. The vulnerability arises from the fact that the ACL file specified in the default listener settings is not being applied to the actual listener configuration, leading to potential ACL bypass issues.

### Vulnerability Analysis

In the original code snippet, several properties of the default listener are copied over to the newly added listener configuration, including `max_connections`, `protocol`, `socket_domain`, and various security-related options like TLS settings, password files, PSK files, and authentication plugin configurations. However, the `acl_file` property, which specifies the path to the Access Control List file, is not explicitly copied from the default listener to the new listener configuration. As a result, if `per_listener_settings` is set to true and the default listener has an `acl_file` specified, this ACL file is ignored for the new listener, potentially allowing unauthorized access to the broker.

### Repair Explanation

The repair involves adding a line of code to ensure that the `acl_file` property from the default listener is copied to the new listener configuration. This is done by appending the following line:

```c
config->listeners[config->listener_count-1].acl_file = config->default_listener.acl_file;
```

This line is inserted right after the other properties of the default listener are copied to the new listener configuration. By doing so, the ACL file specified in the default listener settings is correctly applied to the new listener, ensuring that access control rules defined in the ACL file are enforced as intended.
