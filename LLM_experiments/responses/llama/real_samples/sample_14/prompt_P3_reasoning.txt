The repair provided is aimed at addressing the "CCS Injection" vulnerability in OpenSSL, which allows man-in-the-middle attackers to trigger the use of a zero-length master key in certain OpenSSL-to-OpenSSL communications, potentially leading to session hijacking or sensitive information disclosure.

The vulnerability arises from the fact that OpenSSL does not properly restrict the processing of ChangeCipherSpec messages, allowing an attacker to inject a ChangeCipherSpec message with a zero-length master key. This can cause the server to use a zero-length master key, effectively breaking the encryption and allowing the attacker to intercept and manipulate the encrypted data.

The repair involves adding a simple check for a zero-length master key in the SSL3_ST_SW_CHANGE_A and SSL3_ST_SW_CHANGE_B states. Specifically, the line `if (s->session->master_key_length == 0)` checks whether the master key length is zero, and if so, sets the return value to -1 and jumps to the end of the function, effectively aborting the handshake.

This check is crucial in preventing the CCS Injection vulnerability, as it ensures that the server does not proceed with the handshake if a zero-length master key is detected. By aborting the handshake in such cases, the server prevents the attacker from exploiting the vulnerability and potentially compromising the security of the communication.

The location of the check is also important. It is placed after the `s->session->cipher=s->s3->tmp.new_cipher` line, which sets the cipher for the session, and before the `ssl3_send_change_cipher_spec` function call, which sends the ChangeCipherSpec message. This ensures that the check is performed after the cipher has been set but before the ChangeCipherSpec message is sent, allowing the server to detect and prevent the use of a zero-length master key.

The repair does not modify any other parts of the code, ensuring that the fix is minimal and does not introduce any unintended side effects. The check is also specific to the SSL3_ST_SW_CHANGE_A and SSL3_ST_SW_CHANGE_B states, which are the only states where the ChangeCipherSpec message is sent, further minimizing the impact of the fix.

In summary, the repair adds a simple yet effective check for a zero-length master key in the SSL3_ST_SW_CHANGE_A and SSL3_ST_SW_CHANGE_B states, preventing the CCS Injection vulnerability and ensuring the security of OpenSSL-to-OpenSSL communications. The check is carefully placed to detect and prevent the use of a zero-length master key, and the repair is designed to be minimal and non-intrusive, making it an effective solution to the vulnerability.
